# EPIC 102 — Provider transport on `pi-ai`

Status: **ready**.

## Goal

One model call reaches a real provider through a stored `kind = 'llm'` registration. A new capability, `src/services/model/`, declares the interface in `src/services/model/index.ts` and holds one implementation, `PiAi`, in `src/services/model/pi-ai.ts`. A call takes the sealed `ProviderRow` of `src/domain/provider.ts` and one model id, opens the payload through `services/crypto`, reads the provider variant, the credential and the base url from `src/domain/provider-payload.ts`, and streams one request through the `Models` collection of `@earendil-works/pi-ai`. A request that names no model takes the `defaultModel` of the payload. The call assembles the text, the tool calls, the stop reason and the reported token usage, and it owns its timeout and its cancellation. `src/services/model/pi-ai-models.ts` builds the collection and denies every ambient credential. The service persists nothing and opens no storage transaction. `src/main.ts` constructs `PiAi` and registers the capability as a health dependency, so `system.health` reports `model` as `ok` or `failed` on a running daemon. The health probe reads the built-in provider catalogue and calls no provider, so a real provider call still needs a registration, a credential and the caller of EPIC 106. Every test in this epic runs on a hand-written mock transport.

The capability name is `model`. Nothing under `src/services/` uses that name today, so no rename is needed.

## Non-goals

- No attempt-level pinning of the registration and `provider_model`. EPIC 110 owns the attempt lifecycle and the pin.
- No binding resolution. The caller passes the registration row, and the model id is the caller's or the payload default. EPIC 101 owns `set_default_at`, and EPIC 110 owns the attempt-time resolution and the binding override.
- No tool set and no agent session. EPIC 106 runs `general@1` and `re@1` on `pi-coding-agent` with its own allow list.
- No ordered chain and no failover across attempts. `docs/proposal/phase-2/providers-and-credentials.md` defers both.
- No token accounting. The result carries the provider-reported counts of one call, because EPIC 106 reports them in its evidence and `docs/proposal/database/agent_invocation.md` holds `usage_json` for them. No sum across calls, no cost and no persistence.
- No key rotation. `docs/proposal/phase-2/providers-and-credentials.md` defers it.
- No storage write, no transaction, no event. The service returns, and a later command persists.
- No model call from a route, and no sampling control. No phase-2 operation is a bare model call: `src/http/contract/credential.ts` declares `provider.register`, `provider.list`, `provider.show`, `provider.rename`, `provider.remove` and `provider.setDefault`, and none of them calls a model. EPIC 106 is the first caller of `complete`, and it consumes the interface only. No named source asks for a `temperature`, so the request carries none.
- No route moves to `routed`. Every operation keeps the lifecycle EPIC 101 and later epics give it. `system.health` is already `routed` in `src/http/contract/system.ts`, and this epic adds one dependency line to its answer.
- No reasoning replay. A `thinking_delta` event is not forwarded, and a `ThinkingContent` block never enters the assembled text.

## Stories

- **The `model` capability interface** — `src/services/model/index.ts` declares the types and one interface, and it names no vendor package. `ModelRequest` is `Readonly<{ registration: ProviderRow; model: string | null; systemPrompt: string | null; messages: readonly ModelMessage[]; tools: readonly ModelTool[]; maxOutputTokens: number | null; timeoutMs: number; signal: AbortSignal | null; onTextDelta: ((delta: string) => void) | null }>`. A null `model` takes the `defaultModel` of the opened payload, because `docs/proposal/phase-2/providers-and-credentials.md` applies the payload default until a binding override column exists. `ModelMessage` is a union over `role`: `{ role: "user"; text: string }`, `{ role: "assistant"; text: string }` and `{ role: "toolResult"; toolCallId: string; toolName: string; text: string; isError: boolean }`. `ModelTool` is `Readonly<{ name: string; description: string; parameters: Readonly<Record<string, unknown>> }>`, and `parameters` is a JSON Schema object. `ModelResult` is `Readonly<{ provider: string; model: string; stop: ModelStop; text: string; toolCalls: readonly ModelToolCall[]; usage: ModelUsage }>`, `ModelStop` is `"stop" | "length" | "toolUse"`, `ModelToolCall` is `Readonly<{ id: string; name: string; arguments: Readonly<Record<string, unknown>> }>`, and `ModelUsage` is `Readonly<{ inputTokens: number; outputTokens: number; cacheReadTokens: number; cacheWriteTokens: number; totalTokens: number }>`. `ModelErrorCode` is exactly `"request-invalid" | "registration-kind-invalid" | "credential-unreadable" | "provider-unknown" | "model-unknown" | "model-timeout" | "model-cancelled" | "model-failed" | "model-stream-incomplete" | "callback-failed"`. `ModelError` carries `code` and nothing else, and follows the shape of `AgentError` in `src/services/agent/index.ts`, which declares `code` and `message` only. The file also exports `modelErrorMessages`, a frozen `Record<ModelErrorCode, string>` of ten literal messages, and `ModelError` declares `constructor(code: ModelErrorCode)` and takes its message from that record. No upstream provider text passes into a refusal. The interface is `Model`, with two methods: `complete(request: ModelRequest): Promise<ModelResult>` and `probe(): DependencyStatus`, where `DependencyStatus` comes from `src/domain/health.ts`. `src/domain/provider.ts` supplies `ProviderRow`, and no field of the interface is optional, because a null states the absence.
- **The registration opens to a variant, a credential and a base url** — `src/services/model/pi-ai.ts` exports `class PiAi implements Model`. Its dependencies are `Readonly<{ crypto: Crypto; clock: Clock; deadline: Deadline; models: Models }>`, where `Crypto` comes from `src/services/crypto/index.ts`, `Clock` and `Deadline` from `src/services/clock/index.ts`, and `Models` from `@earendil-works/pi-ai`. A call refuses `registration.kind !== "llm"` with `registration-kind-invalid` before it opens anything. It then calls `crypto.open({ ciphertext: registration.payloadCiphertext, iv: registration.payloadIv, tag: registration.payloadTag, keyVersion: registration.keyVersion })` and `deserializePayload("llm", text)` from `src/domain/provider-payload.ts`. A thrown `CryptoError` or `PayloadError` becomes `credential-unreadable`, and the cause is not attached. `models.getProvider(payload.provider) === undefined` refuses `provider-unknown`. The effective model id is `request.model` when it is non-null, and `payload.defaultModel` otherwise. `models.getModel(payload.provider, <the effective model id>) === undefined` refuses `model-unknown`. `ModelResult.model` reports the effective model id. A non-null `payload.baseUrl` produces the request model `{ ...found, baseUrl: payload.baseUrl }`, and a null `payload.baseUrl` keeps the model unchanged. One private helper raises every refusal: it reads `modelErrorMessages` by code, and it takes no other argument. A `ModelError` therefore cannot carry `payload.apiKey`, by its shape.
- **The pi-ai models collection denies an ambient credential** — `src/services/model/pi-ai-models.ts` exports `createPiAiModels(): MutableModels`. It calls `builtinModels` of `@earendil-works/pi-ai/providers/all` with `credentials: new InMemoryCredentialStore()` and with `authContext: { env: async () => undefined, fileExists: async () => false }`. `resolveProviderAuth` in `node_modules/@earendil-works/pi-ai/dist/auth/resolve.js` consults ambient sources through that context only, so a built-in provider cannot spend an operator's environment key. The store starts empty, so every request auth comes from the `apiKey` override the call passes. This file is the only place in `src/` that names a built-in provider catalogue. The oracle is per provider, and this epic asserts `anthropic` and `openai` only. The claim covers no other provider by test, because one test per built-in provider is out of proportion, and because `authContext` is one object every provider shares.
- **The request shape** — `PiAi` builds one `Context` and one `StreamOptions`. `Context.systemPrompt` is `request.systemPrompt` when it is non-null, and the field is absent otherwise. `Context.messages` maps each `ModelMessage` in order, and each mapped message stamps `timestamp: clock.now()`, because `UserMessage`, `AssistantMessage` and `ToolResultMessage` of `@earendil-works/pi-ai` all require the field. A `user` and an `assistant` message map `content` to `[{ type: "text", text }]`. A `toolResult` message maps to `{ role: "toolResult", toolCallId, toolName, content: [{ type: "text", text }], isError, timestamp }`. `Context.tools` is absent when `request.tools` is empty. `StreamOptions` is exactly `{ apiKey: payload.apiKey, signal: <the call signal>, maxRetries: 0, maxTokens: request.maxOutputTokens ?? undefined }`. `StreamOptions.timeoutMs` is absent, because the deadline story gives the deadline one owner. `maxRetries: 0` makes one call reach the provider once, so retry policy stays with the caller. The call is `models.stream(requestModel, context, options)`, never `models.streamSimple`.
- **Streaming, and a stream that stops without a terminal event** — `PiAi` consumes the returned `AssistantMessageEventStream` with `for await`. Each `text_delta` event calls `request.onTextDelta` with `event.delta`, in arrival order, and a null callback skips the call. A callback that throws is the caller's defect: `PiAi` catches the throw, aborts the call signal, and refuses `callback-failed`. The thrown value is not attached, and no later delta reaches the callback. A `thinking_delta` event is ignored. The loop keeps the first `done` or `error` event and stops using later events. `result` text is the concatenation of every `TextContent` block of the terminal message, in content order, joined with the empty string. `result.usage` maps the `usage` of the terminal `AssistantMessage` field by field: `input` to `inputTokens`, `output` to `outputTokens`, `cacheRead` to `cacheReadTokens`, `cacheWrite` to `cacheWriteTokens`, and `totalTokens` to `totalTokens`. No other field of `Usage` reaches the result, so `cost`, `reasoning` and `cacheWrite1h` are dropped. A terminal message that reports no usage gives five zeros, because a provider that reports nothing is not a failure. `PiAi` never calls `models.complete`: `forwardStream` in `node_modules/@earendil-works/pi-ai/dist/api/lazy.js` calls `end()` with no result when the inner stream exhausts, and `EventStream.result()` in `node_modules/@earendil-works/pi-ai/dist/utils/event-stream.js` then never settles. A loop that ends with no terminal event therefore refuses `model-stream-incomplete`, and it is the reason this epic iterates rather than awaits.
- **Tool calls** — each `ModelTool` maps to `{ name, description, parameters: tool.parameters as unknown as Tool["parameters"] }`, where `Tool` is the exported type of `@earendil-works/pi-ai`. `pi-ai` types `Tool.parameters` as `TSchema` of `typebox`, and a `typebox` schema is a JSON Schema object at run time, so no conversion runs and kanthord imports no `typebox`. `result.toolCalls` maps every `ToolCall` block of the terminal message, in content order, to `{ id, name, arguments }`. A terminal `done` event whose `reason` is `toolUse` sets `stop: "toolUse"`.
- **The deadline has one owner** — `pi-ai` forwards `timeoutMs` to a provider SDK and enforces nothing itself. Two timers would make the reported code depend on which one fires first, so `PiAi` owns the deadline alone and the SDK gets no `timeoutMs`. The SDK keeps its own transport default, which is longer than any kanthord deadline, so it never decides the outcome. `src/services/clock/index.ts` gains one more interface: `Deadline`, with `arm(delayMs: number, onExpire: () => void): () => void`, where the returned function disarms. `src/services/clock/system-deadline.ts` exports `class SystemDeadline implements Deadline`, on `setTimeout` and `clearTimeout`, and it calls `unref()` so no handle keeps `node:test` alive. One `AbortController` per call supplies the signal in `StreamOptions`. `deadline.arm(request.timeoutMs, …)` aborts it and sets the timeout flag. An abort of `request.signal` aborts it and sets the cancel flag, through one listener added with `{ once: true }`. A `request.signal` that is already aborted refuses `model-cancelled` before any call. The implementation disarms the deadline and removes the listener in a `finally`. The first flag set wins, and a later flag never replaces it, so a deadline and a cancellation that both fire report the one that fired first. A terminal `error` event maps by flag: the timeout flag gives `model-timeout`, the cancel flag gives `model-cancelled`, and neither flag gives `model-failed`. A synchronous throw from `models.stream`, and a throw from the async iteration, map the same way: a set flag decides the code, and no flag gives `model-failed`. An abort that arrives after the terminal event changes no result.
- **A truncated response, and a provider failure** — a terminal `done` event with `reason: "length"` returns `stop: "length"` with the assembled text, and it throws nothing, because a truncated answer is the caller's decision. A terminal `error` event with no flag set refuses `model-failed`, and `event.error.errorMessage` reaches nothing. Request validation runs first and refuses `request-invalid`: `request.timeoutMs` must be a positive integer, a non-null `request.model` must be non-empty, `request.messages` must be non-empty, and a non-null `request.maxOutputTokens` must be a positive integer.
- **The hand-written mock transport, and the manual deadline** — `src/services/model/pi-ai.test.ts` declares `createMockTransport`, `createMockModels` and `createManualDeadline`, and no file under `test/helpers/` names `@earendil-works/pi-ai`. A shared helper coupled to a vendor type crosses the boundary the import matrix draws, and a scripted transport returns the deterministic value a story names, so it is a Mock rather than a Fake. `createMockTransport` returns an object implementing `ProviderStreams` of `@earendil-works/pi-ai` plus the captured `{ model, context, options }` of every call, and it scripts the event sequence a test names, including a sequence with no terminal event and a sequence that waits for an abort. `createManualDeadline` implements `Deadline` and holds the armed callbacks, so a test expires the deadline by one synchronous call and reads no wall clock. `createMockModels` calls `createProvider` with `id: "mock-provider"`, one model `{ id: "mock-model", api: "mock-api", provider: "mock-provider", baseUrl: "https://mock.invalid", … }`, and a hand-written `ApiKeyAuth` whose `resolve` returns `{ auth: { apiKey: credential?.key } }` and reads no environment. It registers the provider on `createModels({ authContext: { env: async () => undefined, fileExists: async () => false } })`. The mock does not use `fauxProvider` of `@earendil-works/pi-ai/providers/faux`, because a `FauxResponseStep` is an `AssistantMessage` and cannot script a stream that ends without a terminal event or one that blocks until an abort.
- **The daemon constructs the adapter and reports it** — `src/main.ts` is the only file that names `PiAi`, per `AGENTS.md`. The `serve` action constructs `new PiAi({ crypto, clock, deadline: new SystemDeadline(), models: createPiAiModels() })` after it constructs `crypto`, and it builds the `reporters` array after that construction, because `reporters` sits above `crypto` today. `reporters` gains `{ name: "model", probe: () => model.probe() }`. `PiAi.probe()` returns `"ok"` when `models.getProviders().length > 0`, and `"failed"` otherwise; `readHealth` in `src/queries/system/read-health.ts` turns a throwing probe into `"failed"` as well. `docs/proposal/api/new-decisions.md` and `docs/proposal/api/system.md` decide that `system.health` asks each dependency for `ok`, `failed` or `not-implemented`, and `src/domain/health.ts` holds the shape, so no contract file and no schema changes. `readHealth` orders the lines by name bytewise, so `model` precedes `storage`. The probe reads the catalogue in memory, and it calls no provider.
- **The layout and the vendor boundary** — `src/domain/layout.test.ts` lists the service directories, so its assertion gains `"model"` between `"lease"` and `"plan"`, and its name becomes `src/services/ holds exactly the fifteen capabilities plus home-lock`. `Deadline` and `SystemDeadline` sit in the existing `clock` capability, so the list gains one name only. `eslint.config.js` gains `"@earendil-works/*"` in `vendorPackages`, so `src/domain/`, `src/commands/` and `src/queries/` cannot name `pi-ai`. It also gains one block over `files: ["src/services/*/index.ts"]` with `ignores: ["src/**/*.test.ts"]` that bans `vendorPackages`, so a service interface stays vendor-free. Flat config resolves `no-restricted-imports` by last match and never by union, so the new block sits after the `src/**/*.ts` block and repeats its `gitLibraries` and `node:child_process` entries.
