# EPIC 004.5 — Contract schemas, ahead of the handlers

Status: **draft**.

## Goal

Every phase-1 read operation declares a zod request schema and a zod response schema, and the generated
`openapi.yaml` plus a published example set become a contract a second repository can build against. No
handler is written here.

## Why this epic exists

The Flutter client is blocked on shapes, not on behaviour. EPIC 004 gave every operation an identity —
`operationId`, method, path tuple, `introducedIn`, `status` — and two of fifty-three a schema. So the
generated document is a route directory, a client cannot generate a model from it, and the client's only
alternative is to reconstruct the wire contract from prose in its own repository. That is a second
authority for the same contract, and the two forks are discovered at integration.

**Schema authorship does not depend on handler implementation.** `src/http/contract/` is pure, it
imports no storage and no command, and `docs/proposal/` already fixes every field this epic writes down.
So this work runs in parallel with EPIC 006 and 007 rather than after 009, and it unblocks the client
weeks earlier than EPIC 010 would.

It needs EPIC 002 for the domain enums and EPIC 004 for the registry. It needs nothing else.

## Non-goals

- **No handler, no command, no query.** An operation covered here still answers `501` until its own
  epic implements it. The registry `status` does not change.
- **No schema for a later-phase route.** A `stubbed` operation reads no body, because dispatch answers
  `501` before the body parser runs. EPIC 010's rule stands: an operation with no schema is correct
  until the phase that implements it.
- **No change to the two operations that already have schemas.** `system.health` and `system.db` are
  done.
- **No proof that a handler emits what its schema declares.** This epic validates each example against
  its schema, which proves the examples and the schemas agree. It cannot prove a handler agrees, because
  no handler exists. **The epic that implements a handler asserts its response against the registered
  schema**, and that obligation is stated here so it is not lost: a schema authored ahead of its handler
  is a prediction until one test validates a real response against it. A consumer is building against
  these shapes, so the assertion is not optional.

## The slice

The read operations the client's first screens need, and `plan.import` because its request is the most
expensive shape to get wrong.

| operationId                          | Schemas                 | Source                            |
| ------------------------------------ | ----------------------- | --------------------------------- |
| `system.status`                      | response                | `docs/proposal/api/system.md`     |
| `project.list`, `project.show`       | request query, response | `docs/proposal/api/project.md`    |
| `node.list`, `node.show`             | request query, response | `docs/proposal/api/graph.md`      |
| `edge.list`                          | response                | `docs/proposal/api/graph.md`      |
| `event.list`                         | request query, response | `docs/proposal/api/event.md`      |
| `plan.export`, `plan.revisions`      | response                | `docs/proposal/api/graph.md`      |
| `plan.validate`, `plan.import`       | request, response       | `docs/proposal/api/graph.md`      |
| `repository.list`, `repository.show` | response                | `docs/proposal/api/repository.md` |
| `provider.list`, `provider.show`     | response                | `docs/proposal/api/credential.md` |

`blob.show` is excluded on purpose: it returns bytes, so it declares a media contract rather than a body
schema, and EPIC 010 owns that.

## Stories

- **The four decisions each field carries** — every field in this epic answers all four explicitly,
  because prose answers none of them and a consumer must not guess: required or optional; absent or
  explicitly `null`; a closed enum or an open string; and, for `details`, the shape per error code. A
  field whose answer is not in `docs/proposal/` is a proposal gap, and the story raises it rather than
  choosing.
- **The response schemas** — one `z.strictObject` per operation, composed from the domain enums of EPIC
  002 rather than from a restated string union. `nodeState`, `blockReason`, `nodeKind`, the attempt
  outcome and the check result each have exactly one definition in `domain/`, and a second copy here is
  a defect.
- **The request schemas** — a query filter set per list operation, and a body per command. The cursor is
  one shared shape: `after` as an optional prefixed id and `limit` as a bounded positive integer. Every
  list operation reuses it, so no route invents its own paging.
- **The error `details` shapes** — one schema per error code that carries `details`:
  `stale-revision`, `needs-reconcile`, `binding-in-use`, `plan-invalid`, `choices-invalid`,
  `choices-stale`, `choices-changed`, `identity-kind-mismatch`, `credential-rejected` and
  `host-key-mismatch`. A client branches on `code` and then reads `details`, so an undeclared `details`
  is an untypable branch. `docs/proposal/api/README.md` names each one's contents.
- **The example set** — one request example, one success example and one error example per operation,
  authored beside the schema and **validated against it in a test**. This is the artifact the client
  builds fixtures from, so an example that does not satisfy its own schema is a build failure rather
  than a review comment.
- **The published artifact** — `npm run verify` already generates, validates and deletes
  `openapi.yaml`. Add one script that writes the document and the example set to a named output
  directory for a consumer to pin, with the daemon version and the commit in it. The document stays
  uncommitted, per `docs/proposal/api/README.md`.
- **The parity assertion widens** — `npm run verify` asserts today that the registry's operation set
  equals `docs/proposal/api/`. It now also asserts that every operation named in the table above
  carries the schemas that table names. Adding a row to the table without a schema fails the build, so
  the slice cannot silently shrink.

## Verification gate

Gates: `npm run verify`

Proof:

```bash
node --test src/http/contract/**/*.test.ts && echo "PASS EPIC-004.5"
```

Hermetic coverage required beyond the Proof:

- Every operation in the slice table carries the schemas the table names, asserted by walking the table
  rather than by a hand-written list.
- Every authored example validates against its own schema. One deliberately broken example fails the
  suite.
- The generated `openapi.yaml` contains a `$ref` to a named component for each of those operations, and
  no operation in the slice resolves to an empty response body.
- The generated document validates against an independent OpenAPI validator, and every reference
  resolves. This is the EPIC 004 assertion, re-run over a document that now has real schemas.
- Generation is byte-identical across two runs, and the component order is canonical.
- A `stubbed` operation still carries no schema, and the suite asserts that adding one is a fault.
- Every enum in a response schema is the `domain/` definition. An assertion greps the contract modules
  for a restated state or kind literal and fails on one.
- The cursor shape is one definition, referenced by every list operation. A list operation with its own
  `after` or `limit` declaration is a fault.
- A `501` from a `stubbed` route is unchanged by this epic, asserted against the EPIC 004 sweep.
