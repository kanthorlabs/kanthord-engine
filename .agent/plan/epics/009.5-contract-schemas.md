# EPIC 009.5 — Contract schemas, ahead of the handlers

Status: **draft**.

## Goal

Every phase-1 `routed` operation declares the zod schemas its wire shape needs, the error `details` are
typed per code, and the generated `openapi.yaml` plus a published example set become a contract a second
repository can build against. No handler is written here.

## Why this epic exists

The Flutter client is blocked on shapes, not on behaviour. EPIC 004 gave every operation an identity —
`operationId`, method, path tuple, `introducedIn`, `status` — and 007, 008 and 009 authored a response
schema alongside each handler they built. So the shapes exist, but three things a consumer needs do not:
the one remaining unimplemented read, `event.list`; the `details` payload a client branches on, which is
`z.record(z.string(), z.unknown())` at `src/http/contract/errors.ts:39` and therefore untypable; and any
example set at all. A client that cannot type an error branch reconstructs it from prose in its own
repository, and that second authority forks at integration.

**Schema authorship does not depend on handler implementation.** `src/http/contract/` is pure, it
imports no storage and no command, and `docs/proposal/` already fixes every field this epic writes down.
So this epic completes and hardens the contract as one artifact rather than leaving each handler epic to
declare its own.

It needs EPIC 002 for the domain enums, EPIC 004 for the registry, and 007, 008 and 009 for the schemas
it audits. It runs immediately before EPIC 010, whose `event.list` story consumes two of these schemas.

## Non-goals

- **No handler, no command, no query.** `event.list` still answers through EPIC 010. The registry
  `status` does not change.
- **No schema for a later-phase route.** A `stubbed` operation reads no body, because dispatch answers
  `501` before the body parser runs. EPIC 010's rule stands: an operation with no schema is correct
  until the phase that implements it.
- **No new field on an operation that already answers.** The audit tightens what an authored schema
  accepts and rejects. It does not add a field, rename one, or change a value a handler already emits.
- **No proof that a handler emits what its schema declares.** This epic validates each example against
  its schema, which proves the examples and the schemas agree. For an operation with a handler, the
  handler epic already asserted its response against the registered schema. **EPIC 010 carries that
  obligation for `event.list`**, and it is stated here so it is not lost: a schema authored ahead of its
  handler is a prediction until one test validates a real response against it.

## The slice

Every phase-1 `routed` operation except `blob.show`. Two columns, because most of the set is authored
and this epic must not re-open it.

| operationId                            | State when this epic opens                                      |
| -------------------------------------- | --------------------------------------------------------------- |
| `event.list`                           | **no schema.** This epic authors request and response.          |
| every other phase-1 `routed` operation | response authored by 004, 007, 008 or 009. This epic audits it. |

`blob.show` is excluded on purpose: it returns bytes, so it declares a media contract rather than a body
schema, and EPIC 010 owns that.

The audited set is read from the registry, never from a list in this file. `docs/proposal/api/graph.md:102`
fixes phase 1 with no query-parameter mechanism, so no list operation but `event.list` carries a request
schema, and a filter added to one is a transport decision rather than a story here.

## Stories

- **`event.list`** — the one unauthored pair, and the blocker EPIC 010 Story 02 waits on. It needs
  `eventListRequest` and `eventListResponse` in `src/http/contract/event.ts`, which is twelve lines with
  no zod today.

  **The three values `docs/proposal/` does not fix are fixed here**, because EPIC 010 implements the
  handler against them and a handler cannot be written to an unbounded schema:

  - `limit` **defaults to 100**;
  - `limit` **caps at 500**, and a larger value is `400 invalid-request` rather than a silent clamp;
  - **no response carries a cursor field.** `docs/proposal/api/event.md` makes `after` the id of the
    last event read, so the client already holds the value and a `nextAfter` would be a second
    authority for it.

  `after` and `limit` are one exported cursor shape, so a later list operation reuses it rather than
  inventing its own paging. `event.list` declares **no `wait`**. `docs/proposal/api/event.md` defers the
  long poll to phase 2, and a schema that declared it would promise behaviour no phase-1 handler honours.

- **The four decisions each field carries** — an audit of every authored schema. Each field answers all
  four explicitly, because prose answers none of them and a consumer must not guess: required or
  optional; absent or explicitly `null`; a closed enum or an open string; and, for `details`, the shape
  per error code. A field whose answer is not in `docs/proposal/` is a proposal gap, and the story raises
  it rather than choosing.
- **`z.object` becomes `z.strictObject`** — 007 and 008 authored with `z.object`, and 009 authored
  `systemStatusResponse` with `z.strictObject`. An unknown key therefore passes on most of the contract
  and fails on one operation, and a consumer cannot tell which rule it is generating against. One rule:
  every request and response schema rejects an unknown key. Every enum stays the `domain/` definition of
  EPIC 002, and a restated string union found by the audit is a defect.
- **The error `details` shapes** — one schema per error code that carries `details`:
  `stale-revision`, `needs-reconcile`, `binding-in-use`, `plan-invalid`, `choices-invalid`,
  `choices-stale`, `choices-changed`, `identity-kind-mismatch`, `credential-rejected` and
  `host-key-mismatch`. A client branches on `code` and then reads `details`, so an undeclared `details`
  is an untypable branch. `docs/proposal/api/README.md` names each one's contents. `errorEnvelopeSchema`
  at `src/http/contract/errors.ts:35-41` carries one open record for every code, and it becomes a
  discriminated union on `code`. The `httpError` overloads at `src/http/contract/errors.ts:59-75` already
  make `details` mandatory for a `409`, so the union tightens a rule that exists rather than adding one.
- **The example set** — one request example, one success example and one error example per operation,
  authored beside the schema and **validated against it in a test**. This is the artifact the client
  builds fixtures from, so an example that does not satisfy its own schema is a build failure rather
  than a review comment.
- **The published artifact** — `npm run verify` already generates, validates and deletes
  `openapi.yaml`. Add one script that writes the document and the example set to a named output
  directory for a consumer to pin, with the daemon version and the commit in it. The document stays
  uncommitted, per `docs/proposal/api/README.md`.
- **The parity assertion widens** — `npm run verify` asserts today that the registry's operation set
  equals `docs/proposal/api/`. It now also asserts that every phase-1 `routed` operation except
  `blob.show` carries a response schema, and that each one carries an example set. The assertion walks
  the registry, so a `routed` operation added later without a schema fails the build.

## Verification gate

Gates: `npm run verify`

Proof:

```bash
node --test src/http/contract/**/*.test.ts && echo "PASS EPIC-009.5"
```

Hermetic coverage required beyond the Proof:

- Every phase-1 `routed` operation except `blob.show` carries a response schema, asserted by walking the
  registry rather than a hand-written list.
- Every request and response schema rejects an unknown key, asserted by walking the registry. One
  schema left as `z.object` fails the suite.
- `eventListRequest` rejects `limit: 501`, rejects `wait`, and defaults `limit` to 100 when absent.
- Every authored example validates against its own schema. One deliberately broken example fails the
  suite.
- Every error code that carries `details` has exactly one `details` schema, and an envelope whose
  `details` does not match its `code` fails to parse.
- The generated `openapi.yaml` contains a `$ref` to a named component for each of those operations, and
  no `routed` operation but `blob.show` resolves to an empty response body.
- The generated document validates against an independent OpenAPI validator, and every reference
  resolves. This is the EPIC 004 assertion, re-run over a document that now has real schemas.
- Generation is byte-identical across two runs, and the component order is canonical.
- A `stubbed` operation still carries no schema, and the suite asserts that adding one is a fault.
- Every enum in a response schema is the `domain/` definition. An assertion greps the contract modules
  for a restated state or kind literal and fails on one.
- The cursor shape is one exported definition. A second `after` or `limit` declaration anywhere in
  `src/http/contract/` is a fault.
- A `501` from a `stubbed` route is unchanged by this epic, asserted against the EPIC 004 sweep.
