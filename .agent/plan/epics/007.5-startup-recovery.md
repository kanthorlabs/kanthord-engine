# EPIC 007.5 — Startup recovery

Status: **draft**.

## Goal

The daemon establishes a clean, owned home before it reports ready. It probes its external tools, proves that no predecessor's `git` child survives, removes the remnants that only a dead predecessor leaves, reconciles the local journal, and recovers expired leases — in that order, every time. `docs/proposal/phase-3/recovery.md` holds the sequence.

## Why this epic exists

EPIC 001 shipped a startup sweep on the home lock alone. That was correct while git ran in process, because the daemon dying stopped git. It is not correct now: a `git` child is a separate process and outlives the daemon, the operating system releases the home lock the moment the daemon dies, and a replacement daemon would delete a lock a live `git` still owns. The sweep was removed rather than left unsafe, so nothing sweeps today. This epic restores the capability with the missing proof in front of it.

It sits after EPIC 007 because a reap needs a journal row that only a real git operation writes, and before EPIC 009 because the composition root wires this into startup.

## Non-goals

- No remote reconcile at startup. A `publish` row needs the network, and it is reconciled after readiness so a remote outage costs one repository rather than the daemon.
- No phase-2 recovery semantics. Lease expiry beyond the phase-1 rule, and divergence repair, stay where they are.

## Stories

- **Tool probe** — add the `tools.git`, `tools.ssh` and `tools.sshKeyscan` keys to the config service of EPIC 001, each with a documented default, and resolve them to absolute paths, read the version of `git` and `ssh`, and probe `ssh-keyscan` for presence only because it has no portable version output. A missing tool, or a `git` outside the supported range, refuses startup and names what it found and what it wanted. This runs after the home lock and before anything that invokes a tool.
- **Journalling a spawn** — the command layer commits the `git_operation` row carrying `child_token`, the pid-file path the launcher will write, before it asks the git service to spawn. Completing or discarding a row clears the token and removes the file. EPIC 006 owns the launcher that writes the file; this story owns the row that points at it.
- **The orphan reap** — for every in-flight row carrying a token, read the pid file and decide liveness. No pid file means `git` never started. A pid is this row's child when it is alive and its operating-system start time precedes the pid file's creation time; a process that reused the number started after that file existed and is left alone. A live child is an orphan: signal its process group, wait for it to exit, then continue. An orphan that will not exit refuses startup and names the process and the repository. Reading a process start time is platform work, and the story names the supported platforms and the source on each.
- **The startup sweep** — remove the three classes of remnant `docs/proposal/phase-3/recovery.md` lists: git lock files, staging directories from an unfinished seed or clone, and decrypted ssh key material. Every removal asserts a daemon-owned boundary, a regular file or a staging directory, and no symbolic link on the path. A remnant failing any check is left alone and reported. Removal happens only after the reap.
- **Local journal reconcile** — resolve every incomplete `merge`, `sync` and `revert` row against one reading of the real ref, by the matrix in `docs/proposal/phase-3/recovery.md`. A `publish` row is left open and marked for reconcile, and the repository owning it refuses new work until that succeeds. An unreadable ref refuses startup.
- **Expired lease recovery** — a `running` node whose lease has expired at startup returns to `ready` when its workspace is clean and its head equals the recorded base, and otherwise moves to `blocked` with reason `dirty-recovery`. Expiry is read from the injected clock, never from the wall clock. Each transition writes an event. `docs/proposal/phase-3/recovery.md` fixes the rule and `docs/proposal/phase-1/state-machine.md` fixes the states.
- **The recovery component and its ordering** — one unit takes the storage and git interfaces and the held home, and runs probe, reap, sweep, reconcile, leases in order. It is wired into `src/main.ts` before readiness is announced, and the order is asserted rather than assumed.

## Verification gate

Gates: `npm run verify`

Proof:

```bash
node --test src/commands/startup/**/*.test.ts && echo "PASS EPIC-007.5"
```

Hermetic coverage required beyond the Proof:

- **The ordering proof.** A daemon started against a home holding a stale ref lock reports ready only after that lock is gone, and a second daemon against the same home exits non-zero naming `home-locked`. This restores the assertion EPIC 001 carried and the library migration removed.
- A live process recorded as an in-flight child is signalled and waited for before any removal happens, asserted by observing that the lock still exists while the child lives.
- A recorded pid that has been reused by an unrelated process is not signalled, proved by recording a pid with a start time that does not match.
- An orphan that ignores the signal refuses startup, and the message names the process and the repository.
- A lock file reached through a symbolic link pointing outside the home is not removed, and it is reported.
- A staging directory from an interrupted seed is removed, and a finished home beside it is untouched.
- An ssh key file left by a killed daemon is removed before anything touches the network.
- A `publish` row is still open after startup, the daemon is ready, and the repository owning it refuses new work.
- A ref that matches neither the base nor the proposed head leaves the row open, reports, and does not retry.
- An expired lease on a clean workspace at the recorded base returns the node to `ready`, and an expired lease on a dirty workspace moves it to `blocked` with reason `dirty-recovery`. Both write an event, and both read expiry from a mock clock.
- An in-flight row whose pid file was never written is treated as "git never started", and its remnants are removed.
