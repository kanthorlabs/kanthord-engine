# EPIC 105 — Ambient context channel

Status: **blocked**. The external-drive block takes migrations `0005` (EPIC 015), `0006` (EPIC 017) and `0007` (EPIC 018). This epic renumbers its migration to `0008` below, and it becomes ready when EPIC 018 closes.

## Goal

Ambient text becomes one untrusted channel, and it carries text only. `src/domain/ambient.ts` holds the pure rule: the four discovered names, the name that wins, and the closed refusal-reason list. `src/domain/ambient-compose.ts` composes the channel contribution from up to three sources, and it stays pure, so `src/commands/` and `src/queries/` both reach it. `src/services/config/convict.ts` gains the `ambient.hostFiles` switch, default `false`, so `~/.claude/CLAUDE.md` and `~/.agent/AGENTS.md` load only when the human switches them on. `src/services/git/run.ts` returns the raw stdout bytes, and `src/services/git/ambient.ts` reads the root tree of the objective's pinned commit out of the git object store, so no ancestor directory and no checked-out tree can reach the channel. `src/services/workspace/sqlite.ts` and `src/services/storage/migration-0008-workspace-ambient-frozen.ts` make the freeze durable, and `src/commands/workspace/freeze-ambient-file.ts` persists the evidence inside the caller's transaction. `src/queries/instruction/resolve-instruction.ts` of EPIC 104 stops supplying an empty ambient contribution, so `instructions.resolve` returns a prompt holding the frozen ambient block, with one provenance entry per source blob.

## Non-goals

- No channel type, no precedence arithmetic, no budget refusal and no render. EPIC 104 owns the compiler, the per-channel budget, the budget drop of the ambient channel, and the declaration of `instructions.resolve`. This epic supplies the content of one channel and declares no channel.
- No route lifecycle change. EPIC 104 already declares `instructions.resolve` as `routed` in `src/http/contract/instruction.ts`, and this epic changes no registry row. `agent.list`, `template.list`, `template.show` and `profile.verify` keep `status: "stubbed"`.
- No budget-drop event. EPIC 104 reports the ambient budget drop in a read path, and EPIC 110 records it inside a real attempt. This epic appends an event for a repository refusal only.
- No `noContextFiles: true` construction and no fail-closed adapter assertion. EPIC 106 owns both, because both live in the `pi-coding-agent` adapter. This epic proves only that its own read reaches the pinned commit's root tree.
- No repeated-attempt proof. EPIC 110 owns the attempt loop, so "a later attempt in the same objective sees no edit" is asserted there. This epic proves the single read by construction: the resolve path holds no git dependency.
- No workspace creation and no clone. EPIC 110 inserts the `workspace` row, opens the transaction, and passes it to the freeze command. `WorkspaceStore` gains the clone lifecycle it needs there, and this epic adds no further method.
- No profile field, no `checks` entry and no structured value of any kind from ambient text. EPIC 103 owns every structured field, and the ambient contribution type of EPIC 104 carries `prose` and `sources` only.

## Stories

- **The ambient rule** — `src/domain/ambient.ts` holds the whole decision, and it imports `zod` only. `ambientFileNames` is the ordered tuple `["AGENTS.md", "AGENTS.MD", "CLAUDE.md", "CLAUDE.MD"]`, the discovery list of `docs/proposal/phase-2/instructions-and-profiles.md`. `chooseAmbientName(names)` returns the first name of that tuple which the supplied set holds, or `null`. **This epic decides that the tuple order is also the precedence order**, because a root tree can hold two candidates and the chosen file must be the same on every read. The proposal states no precedence, so the reason is determinism, and the discovery order is taken unchanged. `ambientHostLabels` is the tuple `["ambient:host:claude", "ambient:host:agents"]`, one label per host path, in the host path order of story three. `ambientSourceKind(mode)` maps a git mode to `AmbientSourceKind`: `100644` and `100755` are `regular-file`, `120000` is `symlink`, and every other mode is `other`. `ambientRefusalReasons` is the closed sorted list `["not-a-regular-file", "not-utf8", "symlink"]`. `AmbientSourceMetadata` is `Readonly<{ kind: AmbientSourceKind; decodable: boolean | null }>`, and it is **the one metadata shape**: the git service and the host reader both produce it, and `decodable` is `null` when no read happened. `classifyAmbientSource(metadata)` is **the one verdict function**: `symlink` returns `symlink`, `other` returns `not-a-regular-file`, `decodable` of `false` returns `not-utf8`, and anything else returns `null`. It reads no bytes and calls no `Buffer` method, because `domain/` may depend on `zod` only. **There is no size rule here.** The proposal names no ambient size limit, and the `ambient-context` cap of `channelBudgets` of EPIC 104 already decides a drop, so the channel budget is the one limit. The module parses nothing else: it never reads frontmatter, never splits on a heading, and exports no field name.
- **The channel contribution, composed in `domain/`** — `src/domain/ambient-compose.ts` exports `composeAmbientChannel(sources)`, and it is pure, so `src/queries/instruction/resolve-instruction.ts` of story eight and the workspace command of EPIC 110 both call it. A command cannot import a query, so the composition sits behind this pure function and behind the service interfaces of stories four and five, and no query holds it. One source is `Readonly<{ from: string; bytes: Uint8Array; text: string }>`. The function returns `Readonly<{ prose: readonly string[]; sources: readonly Readonly<{ from: string; bytes: Uint8Array }>[] }>`, and the two lists carry the same length and the same order. **The order is fixed**: the frozen repository file first, then each switched-on host file in the `ambientHostLabels` order. One prose fragment is one source text with every trailing LF removed, because `renderPrompt` of EPIC 104 already joins the fragments of one channel with one blank line, so this epic adds no heading, no marker and no second delimiter. The provenance bytes are the original source bytes, never the trimmed fragment, because EPIC 104 addresses the source and not the rendered block. **The contract EPIC 104 must accept, in one sentence:** the `ambient-context` channel contributes one prose fragment and one provenance entry per source blob, in source order — the frozen repository file first, then each switched-on host file in `settings.ambient.hostPaths` order — so `renderPrompt` accepts up to three `ambient-context` source byte sequences and `sources_json` holds one entry per source blob rather than one per rendered block. The `from` label of the repository source is `ambient:<ambientBlob>`, which is the label EPIC 104 already fixes, and the host labels are `ambientHostLabels`. **No host path reaches provenance**, because a home path is machine specific and a golden fixture must hold no machine path. The function returns the keys `prose` and `sources` only, so ambient content can never set a structured field.
- **The `ambient.hostFiles` switch** — `src/services/config/convict.ts` gains `ambient.hostFiles`, format `Boolean`, default `false`, env `KANTHORD_AMBIENT_HOST_FILES`. The env pass beside `parseEnvInteger` gains `parseEnvBoolean`, which accepts exactly `true` and `false` and raises `ConfigError("config-invalid")` for anything else, so `KANTHORD_AMBIENT_HOST_FILES=1` is refused rather than guessed. `src/services/config/index.ts` gains `AmbientSettings` as `Readonly<{ hostFiles: boolean; hostPaths: readonly [string, string] }>` and adds `ambient: AmbientSettings` to `Settings`. `hostPaths` resolves once at load from `LoadInput.homeDir`, in the fixed order `join(homeDir, ".claude", "CLAUDE.md")` then `join(homeDir, ".agent", "AGENTS.md")`, so a daemon home that is not the human's home is decided at load and a test injects `homeDir`. `test/helpers/home.ts` keeps its current base configuration, because the default is `false` and no test needs the key to start a daemon.
- **The raw bytes of the root tree at the pinned commit** — `GitRunResult` of `src/services/git/run.ts` gains `stdoutBytes: Uint8Array`, the concatenated stdout buffer that `stdout` decodes, so one runner serves a text read and a byte read and no caller re-encodes. Every existing caller keeps `stdout` unchanged. `src/services/git/ambient.ts` adds one method to `Git` in `src/services/git/index.ts`: `readAmbientSource({ gitDir, commitOid })`, returning `AmbientRepositorySource` or `null`, where `AmbientRepositorySource` is `Readonly<{ name: string; commitOid: string; metadata: AmbientSourceMetadata; bytes: Uint8Array | null; text: string | null }>`. It goes through the `GitRunner`, so it carries the pinned invocation, the timeout, the output cap and the supervised spawn of EPIC 006. It runs `git --git-dir=<gitDir> ls-tree -z <commitOid> --`, parses each NUL-terminated record into `{ mode, oid, name }`, keeps the records whose name is in `ambientFileNames`, and calls `chooseAmbientName`. No candidate returns `null`. **The read is the git object store, never the checked-out tree**, because the working tree is writable by the agent and the pinned commit is the contract. `ls-tree` without `-r` lists the root tree only, so an ancestor directory and a subdirectory file are both unreachable, which is what the ancestor walk of `pi-coding-agent` makes necessary. It maps the mode through `ambientSourceKind`. A kind other than `regular-file` reads no blob and returns `bytes` of `null`, `text` of `null` and `decodable` of `null`, because a symlink at the root must never be resolved. A `regular-file` runs `git --git-dir=<gitDir> cat-file blob <oid>` and decodes `stdoutBytes` with `new TextDecoder("utf-8", { fatal: true })`. **The decode is fatal, and it runs on the object bytes**, because `stdout` of `GitRunner` decodes with replacement, so a malformed sequence cannot be classified after decoding. A `TypeError` from the decode sets `decodable` to `false` and `text` to `null`, and it keeps the bytes. A successful decode sets `decodable` to `true`. It names no `outputLimitBytes`, so `DEFAULT_OUTPUT_LIMIT_BYTES` of `src/services/git/run.ts` applies; that is the runner's existing output cap and not an ambient rule. A non-zero exit raises `GitError("unknown", ...)`, like `resolveRef` of `src/services/git/ref-read.ts`.
- **The host file reader** — `src/services/ambient/index.ts` declares `HostAmbientReader` with one method, `readHostSources(settings: AmbientSettings): readonly HostAmbientSource[]`, where `HostAmbientSource` is `Readonly<{ from: string; metadata: AmbientSourceMetadata; bytes: Uint8Array | null; text: string | null }>`. The switch lives in the service, so no caller can forget it: `hostFiles` of `false` returns `[]`. Otherwise it returns one entry per **present** path, in the `settings.hostPaths` order, and `from` is the matching entry of `ambientHostLabels`. `src/services/ambient/host.ts` implements it with `node:fs`. `lstatSync` decides the kind, and it is never `statSync`, so a symlink is refused instead of followed: a symbolic link is `symlink` and reads nothing, an entry that is neither a symbolic link nor a regular file is `other`, and `ENOENT` yields no entry. A regular file is read with `readFileSync` and decoded with the same fatal `TextDecoder`, so the host source and the repository source produce the identical metadata shape. **The reader decides nothing.** Every verdict comes from `classifyAmbientSource` of `src/domain/ambient.ts`, and the service holds no second classifier. `src/domain/layout.test.ts` gains `ambient` at the head of the pinned service list and `workspace` at its tail, both sorted, and the count in that test's title grows by two.
- **The workspace store and the durable freeze stamp** — `src/services/storage/migration-0008-workspace-ambient-frozen.ts` exports `migration0008WorkspaceAmbientFrozen`, version `8`, name `0008-workspace-ambient-frozen`, one statement `ALTER TABLE workspace ADD COLUMN ambient_frozen_at INTEGER`, and `src/services/storage/migrations.ts:7-12` appends it after `migration0007ExternalExecution` of EPIC 018, so `migrations` holds eight entries. Migrations `0005`, `0006` and `0007` belong to EPICs 015, 017 and 018, so `0008` is the first free number. **EPIC 110 owns the next phase-2 migration, and its number must follow this one.** A later reader therefore renumbers 110 upward and never renumbers 105 down into a collision. **The stamp exists because `ambient_blob` alone cannot say "frozen, and the repository holds none"**: a null value means both "not read yet" and "no file", so a repeated call would re-read git and append a second event. `workspaceRow` of `src/domain/workspace.ts` gains `ambientFrozenAt: epochMillis.nullable()`. `docs/proposal/database/workspace.md` needs one amendment, which Aelita applies and this epic does not edit: add the column `ambient_frozen_at INTEGER` with the comment `time the ambient read happened; null means the objective was never read`, and extend the `ambient_blob` sentence to read that a null value means the repository holds none **once `ambient_frozen_at` is set**. **This epic owns the `services/workspace` capability**, and the capability holds the SQLite `workspace` row store only, so no other epic puts a second service at that path. `src/services/workspace/index.ts` declares `WorkspaceStore` with exactly three methods: `insert(transaction, row: WorkspaceRow)`, `readByNode(nodeId, transaction?)` returning `WorkspaceRow` or `null`, and `freezeAmbient(transaction, { id, ambientBlob, frozenAt })` returning the number of rows changed, where `ambientBlob` is `string | null`. `src/services/workspace/sqlite.ts` implements it against the `workspace` table, and `freezeAmbient` runs `UPDATE workspace SET ambient_blob = ?, ambient_frozen_at = ?, updated_at = ? WHERE id = ? AND ambient_frozen_at IS NULL`, so a second freeze changes zero rows on every branch. The interface names `Transaction` of `src/services/storage/index.ts`, and it copies the shape of `src/services/plan/index.ts`.
- **The freeze, inside the caller's transaction** — `src/commands/workspace/freeze-ambient-file.ts` takes `workspaces`, `blobs`, `events` and `clock`, and it takes `{ transaction, workspaceId, source, actor }`, where `source` is `AmbientRepositorySource` or `null`. **The transaction belongs to the caller.** `src/services/storage/sqlite.ts` raises `storage-transaction-failed` on a nested transaction, so this command opens none: EPIC 110 opens one transaction for workspace creation and passes that `Transaction` through the interface, which `AGENTS.md` allows. The command runs no git call and no host read, so a service returns the evidence and the command persists it, and every step inside the transaction is synchronous. It calls `classifyAmbientSource` once and takes exactly one of three paths. No candidate, when `source` is `null`: it calls `freezeAmbient` with `ambientBlob` of `null`, appends no event, and returns `{ ambientBlob: null, refusal: null }`, because a repository that holds no ambient file refused nothing. Accepted, when the verdict is `null`: it writes `source.bytes` through `blobs.put`, calls `freezeAmbient` with that hash, appends no event, and returns the hash; acceptance writes no event, because `ambient_blob` is already the record. Refused: it calls `freezeAmbient` with `ambientBlob` of `null` and appends exactly one event, type `workspace.ambient-refused`, subject kind `workspace`, subject id the workspace id, actor kind `daemon`, actor id `input.actor`, payload `{ source: "repository", name: source.name, reason, commitOid: source.commitOid }`. The event names a refusal and never a budget drop, because EPIC 104 owns the drop. Every branch stamps `ambient_frozen_at` with `clock.now()`, so a changed-row count other than one raises `FreezeAmbientFileError("already-frozen")`, in the style of `CreateProjectError` of `src/commands/project/create-project.ts`. Every write of one branch commits or rolls back with the caller's transaction.
- **The ambient block reaches `instructions.resolve`** — `src/queries/instruction/resolve-instruction.ts` of EPIC 104 gains the dependencies `workspaces`, `hostAmbient` and `settings`, and its `ambient-context` contribution stops being empty, so this epic closes on a route. Inside the same `storage.transact` it reads the `workspace` row of the owning objective through `WorkspaceStore.readByNode`, decodes `ambient_blob` through `BlobStore.get` when it is not `null`, calls `hostAmbient.readHostSources(settings.ambient)`, and calls `composeAmbientChannel`. **`ResolveInstructionDependencies` still names no `Git`**, so the resolve path cannot re-read the repository file and the freeze holds for the whole objective by construction. A node whose objective holds no `workspace` row contributes no ambient prose and no ambient provenance entry, because a prospective resolve before the clone has nothing frozen, and EPIC 110 creates the row. The repository source reuses the stored `ambient_blob` for its provenance entry, so no hash is recomputed, and a host source is addressed through `blobs.hash` over its bytes and is never inserted. `src/main.ts` constructs `SqliteWorkspaceStore` and `NodeHostAmbientReader` and passes them plus `settings` into the bound query. The registry, the error table and the CLI grammar of EPIC 104 stay unchanged.
