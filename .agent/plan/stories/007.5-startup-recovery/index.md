# EPIC 007.5 — Startup recovery — stories

Epic: `.agent/plan/epics/007.5-startup-recovery.md`
Prereq: EPIC 007 (sequence order), expanded at `.agent/plan/stories/007-repository-registration/` and **built** — `src/services/git/` holds nineteen production files, `src/commands/` and `src/queries/` exist, and `src/main.ts` is 373 lines with eight bound handlers.

The daemon establishes a clean, owned home before it reports ready: it proves no predecessor's `git` child survives, removes the remnants only a dead predecessor leaves, reconciles the local journal, and recovers expired leases, in that order, every time.

## Decisions this expansion settled

Nineteen choices the EPIC and the proposal leave open. Each is pinned in a story, so none reaches build time.

- **Every filesystem read and every signal goes through the `Git` interface, and the four steps are commands.** `eslint.config.js:233-234` bans `node:fs` in `src/commands/**`, so the decision matrices live in commands and the syscalls live in `src/services/git/`. The EPIC's own wording forces the same split: the recovery unit "takes the storage and git interfaces and the held home". `Git` therefore grows from twelve members to eighteen, and no fourteenth service directory is created.
- **The journal helpers are a second interface in `src/services/git/index.ts`, not a new service and not free functions.** A command may import only `domain/` and a service `index.ts`, so a helper taking a `Transaction` must be declared on an interface. `src/services/home-lock/index.ts` already declares three interfaces in one file, and `EventLog.append(transaction, input)` is the precedent for a synchronous service method enlisting in the caller's transaction.
- **The ordering unit takes the four steps as injected functions, and `main.ts` binds them.** `src/domain/layout.test.ts:175-189` forbids a command importing another command, and `main.ts` is the only file that may import all four. Injection is what lets the order be **asserted in a unit test** rather than only observed through a daemon child process. The sweep additionally takes the reap's report as its argument, so it is unreachable before the reap resolves — a type-level ordering constraint on top of the asserted one.
- **The reap has two sources: journal rows with a token, and pid files in the run directory that match a closed grammar.** `git_operation.repository_id` is `NOT NULL REFERENCES repository(id)` and `register-repository.ts:279` inserts the repository row after `seedHome` returns, so registration — the only phase-1 command that spawns git — cannot pre-commit a journal row. A row-only reap would find nothing in phase 1 and the EPIC's goal would not hold. Both sources feed one list: rows by `id`, then remaining files in bytewise path order. See B1.
- **Source 2 is every regular `*.pid` file in the run directory; the two name forms add attribution and never filter.** Ownership comes from the directory, not the filename: `<home>/git/run` is created by the daemon at mode `0700` (`src/services/git/probe.ts:219-223`) inside a home it holds an exclusive lock on, so the daemon's own launcher is the only writer. A filter on `seed-<repositoryId>.pid` and `gitop-<gitOperationId>.pid` was drafted and rejected: `seedHome` passes the caller's pid file to only two of its six spawns — `fetchTracking` at `src/services/git/seed.ts:131` and `refUpdate` at `:165` — while `init` (`:99`), `remote add` (`:111`), the refspec `config` (`:122`), `resolveRef` (`:138`) and `canPush` (`:150`) each take a runner-minted `git-<uuid>.pid` (`run.ts:37-39`). `canPush` is a `git push --dry-run` that reaches the network and is the longest-lived of them. `run.ts:163-164` removes a minted file in a `finally` that a `SIGKILL` never runs, so a surviving `canPush` child leaves one `git-<uuid>.pid` behind while it holds the staging directory the sweep removes. The sweep's premise is that no process still **uses** a path, not that none still writes a ref, so a name filter would have defeated the epic. `SEED_PID_PATTERN` and `GITOP_PID_PATTERN` remain in `src/domain/recovery.ts` to attribute a candidate to a repository or a row for the event and the report.
- **The launcher waits for one byte between writing its pid file and `exec`.** Write, then wait, then exec. `printf`-before-`exec` already makes "a running `git` has a pid file" true; it does not make a startup observation **final**, because a shell spawned a moment before the crash has not written yet, and it would write and `exec` after a replacement daemon had already reaped and begun sweeping. The pipe's lifetime closes that: a dead daemon closes the write end, the shell reads end-of-file and exits `112` without touching the target. A pre-committed journal row does not close it — the row's token would name a file that does not exist, which `recovery.md` resolves to "stale". This is the one change in the epic that edits EPIC 006 code, and it is what makes `recovery.md`'s own table sound rather than requiring the table to be weakened.
- **A liveness that cannot be established refuses startup.** `docs/proposal/phase-3/recovery.md:49` requires it. A live process whose start time cannot be read, and `EPERM` from `process.kill(pid, 0)`, are both `liveness-unknown` and both throw `RecoveryError("liveness-unknown", …)` leaving the token and the pid file intact. Mapping either to "absent" would let the sweep run over a repository a live `git` may still hold, which is the one failure this epic exists to prevent.
- **No journal method touches the filesystem; the caller removes the pid file after the commit.** The four methods that clear `child_token` return the path they cleared. A removal inside the `transact` callback is not atomic with the commit: a removal followed by a failed commit would leave an open row whose token names a file that is gone, and the next startup would read that as "git never started". Removing after the commit inverts the residue into the safe direction.
- **`stopChild` polls the process group, not the leader.** `process.kill(-pid, 0)` answers `ESRCH` only when the group is empty, so a leader that exits while an `ssh` descendant survives keeps the answer negative. Its poll timer is not `unref`'d, because recovery runs before `listen` and an `unref`'d timer may be the only referenced handle.
- **The sweep collects candidates by name and refuses by type.** A `.staging-` entry that is a regular file and a `.lock` entry that is a symbolic link must both enter the candidate list to be refused and reported; a collector that filtered by type would make every refusal unobservable. The walk emits every symbolic link it meets and descends into none. The check order is symlink, then boundary, then kind — symlink first so the reason names the link and no `realpathSync` runs over a path a link controls.
- **Every command test builds its fixture in `test/helpers/recovery.ts`.** AGENTS.md lets a test reach an implementation only in the capability it covers, so a test under `src/commands/` may not import `src/services/git/journal.ts` or `src/services/event/sqlite.ts`. `test/helpers/database.ts` already imports `SqliteStorage`, so the helper layer may. The helper also owns the exact `repository` fixture row, so no test invents one.
- **The process start time is read with `ps -o lstart=` on both supported platforms, through `spawnSupervised`.** One code path, one parse, one refusal. `/proc/<pid>/stat` was rejected because it needs the kernel tick rate, which Node does not expose, and it does not exist on darwin. `resolvePs` refuses any platform but `darwin` and `linux`, and refuses when neither `/bin/ps` nor `/usr/bin/ps` is executable. The environment is pinned to `PATH: ""`, `LC_ALL: "C"`, `TZ: "UTC"`, and `parseLstart` uses an exact regex plus a month table and `Date.UTC` — never `new Date(string)`.
- **The pid file's `mtimeMs` is its creation time, and `birthtimeMs` is not used.** The launcher creates the file with `set -C` and writes it once with one `printf` (`launcher.ts:6-7`) and never touches it again, so modification time equals creation time; `birthtimeMs` is unavailable or zero on filesystems without `statx`.
- **The liveness comparison is `startSeconds <= floor(mtimeMs / 1000)`, at whole-second granularity.** `ps -o lstart=` prints seconds, so both sides are floored to one unit. `EPERM` from `process.kill(pid, 0)` is treated as `started-later`, not as absence: a process this daemon cannot signal is not a process it should signal. See S1 for the residual window.
- **A remnant is a candidate only inside a boundary the database names.** The sweep enumerates `repository.home_path` and `workspace.path`, never a walk of the daemon home for `*.git`. That is what keeps `src/services/home-lock/startup.test.ts:145-176` green untouched: its planted `<home>/repos/a.git/refs/heads/main.lock` has no `repository` row.
- **The symbolic-link check runs before the boundary check.** A lock reached through a link is reported as `"symlink-on-path"` rather than as `"outside-boundary"`, which is the diagnosis an operator can act on, and the walk never descends into a link so a link to a directory outside the home is never read.
- **The key sweep removes `key-*` and `helper-*.log`, and never `credential-helper.sh` or `ssh-wrapper.sh`.** `docs/proposal/phase-1/git-foundation.md:92` says "every key file in that directory", and the directory also holds two persistent `0700` scripts the next operation needs. `helper-<uuid>.log` is included because `credential.ts:84-86` writes it into the same `0700` directory in the same operation and it is a remnant of the same class; leaving it would keep credential-helper traffic on disk after a `SIGKILL`. See S2.
- **A finding reaches the operator two ways, and neither is stdout.** Every finding is in the returned `RecoveryReport`; a finding that names a repository also gets an `event` row, which is durable; `main.ts` writes one stderr line per finding through the single `renderFinding` renderer. A clean recovery produces no finding and therefore no line, which is what `startup.test.ts:247-248` requires.
- **The refusals are a new `RecoveryError` in `src/domain/recovery.ts`, not three more `StartupErrorCode` members.** `.agent/plan/stories/004-transport-skeleton/02-migration-gate-at-startup.md:37` declares that union a closed startup-refusal set that never reaches `src/http/contract/errors.ts`; `RegisterRepositoryError` is the precedent for a per-concern error class. `main.ts:217-229` gains one line.
- **A `publish` row is marked with `outcome = 'awaiting-remote-reconcile'` and keeps `state = 'open'` and `completed_at = NULL`.** `outcome` is unconstrained `TEXT` with no `CHECK` (`migration-0003:141`), so the mark needs no column and no migration. The repository refusal is **not** `needs-reconcile`: `src/domain/repository.ts:23-31` ties that state to two non-null diverged oids, and an open publish row sets neither.
- **Expired-lease recovery reads the `lease` table with its own statement, and increments `fence`.** `Lease.expired` throws (`src/services/lease/not-implemented.ts:22-27`), and `assert-no-outside-writer.ts:25-29` is the precedent. The fence increment is what fences a worker that returns after the recovery.
- **`graceMs` is the literal `5000` in `main.ts`, not a configuration key.** `src/services/config/convict.ts:160` validates with `allowed: "strict"`, and an operator lowering this value would turn a corrupt-repository refusal into a silent sweep.

## Open items

Five blockers and five suggestions. **All five blockers are done** — applied to the EPIC, to `docs/proposal/phase-3/recovery.md`, to `docs/proposal/database/git_operation.md` and to `docs/proposal/phase-1/git-foundation.md`. The five suggestions are recorded residuals, none blocking. This expansion is ready for `/work`.

- B1 - **done** - registration-cannot-pre-commit-a-journal-row - the EPIC's first bullet required the `git_operation` row carrying `child_token` to be committed **before** the spawn, and `docs/proposal/phase-3/recovery.md` claimed the guarantee "There is no window in which a git process exists unrecorded". No phase-1 command can deliver it: `git_operation.repository_id` is `NOT NULL REFERENCES repository(id)` (`migration-0003-execution-and-journal.ts:129`), `register-repository.ts:225` awaits `seedHome` and `:279` inserts the repository row afterwards, and `git-foundation.md:42-46` requires the row naming the home to commit after the directory is durable. Registration is the only phase-1 command that spawns a `git` that writes refs.

  Two options were rejected on cost after the debate priced them properly.
  - **Making `repository_id` nullable is not one nullable column.** `ref`, `base_oid` and `proposed_head_oid` are all `NOT NULL` (`migration-0003:135-137`) and none is knowable before the fetch. - S1 - action:NO - the-liveness-window-is-one-second-wide - `ps -o lstart=` prints whole seconds, so a pid reused by a process that started in the same second as the pid file's creation is indistinguishable from the real child, and the reap treats it as alive and signals its process group.
