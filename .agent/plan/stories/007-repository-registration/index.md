# EPIC 007 — Repository registration — stories

Epic: `.agent/plan/epics/007-repository-registration.md`
Prereq: EPIC 006 (sequence order), expanded at `.agent/plan/stories/006-git-primitives/`. Twelve files under `src/services/git/` run the `git` binary under a pinned environment, and `test/helpers/remote/` serves two fixture remotes on loopback ports.

A human stores a git credential, inspects a remote, confirms the detected default branch and the host key, registers the repository, and reads the ref layout back through the public surface. This epic delivers the first HTTP-speaking CLI path, the first `src/commands/` and `src/queries/` files, and the first assembly of `Git` over EPIC 006's primitives.

Every story also carries an **end-to-end verification against the real GitHub repository named in `.env.e2e`**, run by `npm run e2e:007` and outside `npm run verify`.

### Measured behaviour — each of these changes an assertion

Observed on `git version 2.50.1 (Apple Git-155)`, `OpenSSH_10.2p1`, `node v24.17.0`, `LC_ALL=C`, against `github.com/kanthorlabs/kanthord-verify`.

- **`git push --dry-run` writes nothing, and it answers.** With a valid token and a refspec naming a new branch: exit `0`, stdout `* [new branch] <oid> -> <branch>`, and a following `ls-remote` reported no such ref. Against the base branch: exit `0`, `Everything up-to-date`. This is what makes the preflight safe.
- **A wrong token is exit `128` with `remote: Invalid username or token. Password authentication is not supported for Git operations.` and `fatal: Authentication failed for '<url>'`.** `classifyFailure` rule 3 matches `Authentication failed`, and the helper's `erase` reaches the same verdict first. An **empty** token produces the identical two lines, so the epic's "missing token" case is reachable and is `auth-failed`.
- **No credential at all is exit `128` with `fatal: could not read Username for 'https://github.com': terminal prompts disabled`, which `classifyFailure` maps to `unknown`.** The daemon cannot reach that state — `credentialId` is mandatory and Story 03 requires a non-empty token — so no sixth `classifyFailure` pattern is added. Recorded because it is the one measured message the five rules miss.
- **The ambient credential chain answers if it is not reset.** While measuring, a `push --dry-run` with no explicit credential and no `-c credential.helper=` used the operator's macOS keychain and **created a real branch on the remote**. The empty helper entry of EPIC 006 Story 03 is what prevents it, and Story 07's E2E asserts the wrong-token refusal with the operator's real `HOME` in place for exactly that reason.
- **`ls-remote --symref <url> HEAD` reports `ref: refs/heads/main\tHEAD`** against the E2E repository, and the repository holds sixteen branches. A real fetch therefore fills the tracking namespace and writes one head, which the one-branch fixture cannot show.
- **`--no-tags` leaves `refs/tags` empty** against the E2E repository as well as against the tagged fixture.
- **`ssh-keyscan github.com` offers three algorithms** — `ssh-rsa`, `ecdsa-sha2-nistp256`, `ssh-ed25519` — in that raw order on three consecutive runs. The raw order is never asserted; the accepted set is those three, bytewise sorted.
- **`node:crypto` reproduces `ssh-keygen -l -f` exactly.** `"SHA256:" + sha256(base64-decoded blob) in base64 with padding removed` matched all three `github.com` host keys and the generated ed25519, RSA and ecdsa keys. The daemon therefore needs no `ssh-keygen`, and `tools.*` stays three keys.
- **`ssh-keyscan -T 3 -p 1 127.0.0.1` exits `1` and writes `write (127.0.0.1): Broken pipe` to stderr with nothing on stdout.** The scan classification therefore reads the parsed output, not the exit code, and a closed loopback port is the scan-failure seam EPIC 005 provides none for.
- **`ssh -V` writes to stderr**, `OpenSSH_10.2p1, LibreSSL 3.3.6`. A probe reading stdout classifies every present `ssh` as unreadable.
- **`zsh` expands `"$U:refs/heads/x"` as `${U:r}` followed by `efs/heads/x`.** `:r` is a parameter modifier. No refspec in this product is built in a shell, and the E2E harness builds every one in TypeScript.

## Decisions this expansion settled

Sixteen choices the EPIC and the proposal leave open. Each is pinned in a story, so none reaches build time.

- **The tool probe lives at `src/services/git/probe.ts`, not in the config service.** The probe must run three binaries, and EPIC 006 Story 01's lint rule permits `node:child_process` in `src/services/git/launcher.ts` alone. `probe.ts` reaches a process through `spawnSupervised`, so the rule holds unchanged and `src/services/config/**` stays free of a process.
- **`GitPaths`'s four directories are derived from `settings.home`, never configured.** `<home>/git/home`, `<home>/git/keys`, `<home>/git/known_hosts`, `<home>/git/run`. `git-foundation.md:62` requires a daemon-owned `HOME`, and one operator setting must not be able to split the daemon's tree. `buildGitPaths` creates the three directories at mode `0700` and never truncates `known_hosts`, because Story 08 appends pinned keys to it.
- **The end-to-end harness lives at `scripts/e2e/`, and `npm test` never collects it.** Measured: bare `node --test` collects every file under a `test` directory, so a scenario there would break the hermetic rule. The fence has two halves, because placement is not hermeticity: a `src/domain/layout.test.ts` assertion against Node's five default patterns plus a `test` path segment, and a second assertion that no file under `src/` or `test/` mentions `scripts/e2e` or `.env.e2e`. A hermetic test that imported a harness module would pass the first and make a network call anyway.
- **The gate is a parent driver, not a `node --test` glob.** `node --test` runs each file in its own process and may run several at once, so a glob gives no ordering, no shared run id, no single before-and-after measurement of the base branch, and no unconditional cleanup. `scripts/e2e/007/run.ts` mints one ULID run id, exports `E2E_RUN_ID`, spawns each scenario sequentially, cleans in a `finally`, and re-reads the base branch object id. A scenario run without `E2E_RUN_ID` refuses rather than inventing a suffix — otherwise each of thirteen processes would mint its own and one scenario's cleanup would miss another's refs.
- **A missing `.env.e2e` key refuses; it never skips.** `t.skip` on a missing credential turns a gate that proved nothing into a passing run. This is the rule EPIC 005 Story 01 applies to a missing tool.
- **Exactly one function pushes without `--dry-run`, and one scenario calls it.** `pushScratchRef` calls `assertScratchRef` before it spawns anything, and `assertScratchRef` refuses any ref outside `refs/heads/kanthord-e2e/007/` and refuses the base branch unconditionally. Story 13's gate greps every file under `scripts/e2e/` and fails on a second writer, because `writesRemoteRef` in the scenario table is hand-maintained declaration data and proves nothing about code. Story 13's driver also re-reads the base branch object id after the whole suite and exits non-zero on a difference. Together those make the read-only promise on `E2E_GH_BASE_BRANCH` structural rather than declared — the residual risk is stated in S6.
- **The provider payload gets its own domain file, and the row gets no column.** `src/domain/provider-payload.ts` holds two schemas, one closed forge set, one canonical serializer per shape and one projection per kind. `docs/proposal/database/provider.md:25` requires the table to carry no per-kind column, and this epic adds none.
- **The encrypted-key refusal reads the OpenSSH cipher name, not a PEM header.** Decode the base64 body, assert the `openssh-key-v1\0` magic, read the length-prefixed cipher name at offset 15, and refuse anything but `none`. A classic PEM is refused as `private-key-malformed`, because the daemon reads one key format and a message naming the format is more useful than one naming a cipher it will not read either way.
- **Canonical serialization builds a fresh literal in the schema's declared key order.** Never `JSON.stringify(parsed)`: a parsed object carries the request body's insertion order. The three orders are pinned per shape and asserted byte for byte, including a case whose input keys are reversed.
- **The public projection is built as a fresh literal, never by deleting a key.** A projection that starts from the secret and removes fields leaks whatever a later schema adds.
- **`repository.inspect` is a query, and its credential verdict is a read verdict.** It writes nothing, so `AGENTS.md`'s write/read split puts it under `src/queries/`. Its verdict member is named `reachable`, not `allowed`, because a write advertisement needs a local object and at inspect time there is none. See B2.
- **The preflight runs between the upstream read and the landing write.** `seedHome`'s order is `host-key`, `init`, `remote-add`, `refspec`, `fetch`, `read-upstream`, `preflight`, `landing`, `rename`, and `SeedStep` is declared in that order. The host key is written first so both the fetch and the preflight run under `StrictHostKeyChecking=yes`.
- **`failAfter` is a declared member of `SeedHomeExtended`, not a hidden hook.** The epic requires an assertion that a failure injected after the fetch leaves no visible home, and there is no other deterministic way to reach that state. A test walks `src/commands/`, `src/queries/`, `src/http/` and `src/cli/` and asserts no file names it.
- **`trustHostKey` appends and is idempotent.** One daemon serves repositories on several hosts, so a replace would unpin every other host. The `[host]:port` spelling is used always, including at port 22, so Story 08 never chooses between two spellings and the written line is byte-equal to the fixture's own.
- **`confirmHostKey` never reads `known_hosts`.** A stored key is not evidence about the host's current key. The test proves it by overwriting the file with a wrong key and asserting the verdict is unchanged, which a call-count assertion cannot show.
- **`createBinaryGit` is a function returning an object literal of twelve delegations, and it lands in Story 09.** Five interface members were EPIC 007's, so the assembly could not exist until the last one did — `.agent/plan/stories/006-git-primitives/index.md:127`. A record is chosen over a class because twelve one-line delegations in a literal cannot accumulate state.
- **`assertNoOutsideWriter` returns a verdict and the caller refuses.** A throw from inside the `transact` callback would roll back and discard the event the refusal is meant to record. The transaction commits the event and returns the verdict; the caller throws after `transact` returns. That keeps the read and the write in one transaction, which `docs/proposal/phase-1/domain.md` requires.
- **One `repositoryView` shape serves `register`, `list` and `show`.** The register command calls `showRepository` after its transaction commits rather than assembling a second literal, so a client parses one type and the three routes cannot drift. `home_path` is read and never returned, per `docs/proposal/api/README.md:188`.
- **The CLI's confirmation rule is one function.** `confirmValue` serves `--upstream` and `--host-fingerprint`, so the two cannot diverge. A flag always beats a prompt, and no terminal with no flag throws `ConfirmationRequiredError` naming the flag.
- **A secret reaches the CLI by file path only.** `--token-file`, `--private-key-file`, `--api-key-file`. There is no `--token`, `--private-key` or `--api-key` option, and their absence is asserted by reading the module source, because `argv` is readable by any process of the same user.

## Open items

Five blockers and seven suggestions. None blocks dispatching a story except where stated. B1, B2, B4 and B5 each need a human decision on a contract, and all four were confirmed by an adversarial review of this expansion.

- B1 - action:YES - journal-cannot-record-a-pre-registration-failure - the EPIC at `:20` and `:52` says a rejected credential "writes `auth-failed` to the journal" and "creates no `repository` row". Those two cannot both hold: `git_operation.repository_id` is `NOT NULL REFERENCES repository(id)`, `src/services/storage/migration-0003-execution-and-journal.ts:129`, so a journal row needs a repository row that the same sentence forbids. Story 10 therefore records the refusal as an `event` on the credential provider and writes no `git_operation` row, and its E2E asserts no journal row carries `outcome = 'auth-failed'`. Amend the EPIC's two bullets and `docs/proposal/database/repository.md:64` to say the refusal is an event, or add a nullable `repository_id` and a migration this epic does not own. My recommendation is the event: a failed registration has no repository to journal against, and `git_operation` is a per-repository journal by construction.
- B2 - action:YES - preflight-placed-on-the-wrong-route-in-the-proposal - `docs/proposal/api/repository.md:50` puts `git push --dry-run` on `repository.inspect`. A push needs a local repository and a local object, and at inspect time there is neither; the EPIC itself says so at `:20` and places the preflight in the seeding sequence. Amend `:50` to move the write advertisement to `repository.register`, and amend `:32` so the `credential` member of the inspect response is a **read** verdict.
