## 2026-08-04 (later) — EPIC 005 review repair round 7 (V1–V7)

- SIGKILL death of a real POSIX child process is empirically ~0ms on macOS even against a `trap '' TERM` script (spiked and confirmed) — you cannot force `waitForExit` to return `false` by racing real signal timing against a hardcoded multi-second wait. To regression-test a "registry cleared even though disposal never confirmed exit" defect (V1), monkeypatch `ChildProcess.prototype.kill` to a no-op for the duration of the target dispose() call, inside an isolated harness subprocess — this makes "cannot confirm exit" a deterministic, non-racy outcome instead of a real-timing gamble, then restore the real `kill` before the harness's real `process.exit()` so the emergency-exit handler's own kill call (if the registry still has the entry) is real and observable from outside.
- `dispose()` in `ssh.ts` removes the whole server directory (config, pid file, log) unconditionally, even when it throws because it couldn't confirm the exit — a regression test that wants to inspect the pid/config _after_ calling dispose() must capture that data _before_ calling dispose(), not rely on `findSshdDirectory` working post-dispose.
- A stub daemon script written for a test can avoid depending on any unresolved sixth binary (e.g. `/usr/bin/nc`) by giving the file a shebang line pointing directly at `process.execPath` and writing a small CommonJS body (no extension, no ancestor package.json — Node's module-type auto-detection defaults to CommonJS when no import/export syntax is present) — `net.createServer().listen(port)` replaces `nc -lk` with zero new external dependencies.
- When a spawn-guard test needs to "walk every module in a directory" rather than name two hardcoded paths, factor the per-call check into a small pure function (`checkModuleSpawns(moduleName, source)`) so a "fails closed on an unlisted module" case is testable against a literal string, without writing scratch files into the very directory being scanned.
