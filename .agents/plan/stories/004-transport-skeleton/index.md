# EPIC 004 — Transport skeleton — stories

Epic: `.agents/plan/epics/004-transport-skeleton.md`
Prereq: EPIC 003 (sequence order). Every phase-1 table exists on `node:sqlite`, `src/services/storage/index.ts` fixes `Storage` — including `ping()` — and `Transaction`, and `src/cli/base-url.ts` and `src/cli/db/migrate.ts` are the two files already under `src/cli/`.

A request reaches a handler only after the `Origin` rejection, the `Host` allow list and the constant-time bearer compare. The route registry is typed on zod, it generates `openapi.yaml` into a temporary directory, and `npm run verify` refuses a registry that disagrees with `docs/proposal/api/`. The CLI carries a base URL and a token, so it runs on a second machine.

## Dispatch order

```
05 → 06a → 06b → 06c → 04 → 03 → 01 → 02 → 07 → 08
```

- `05` and `06a` are the contract, and nothing compiles without them. `05` is first because `06c` references the error envelope from the generated document.
- The EPIC's registry bullet is three stories. `06a` authors the registry, `06b` proves it against `docs/proposal/api/`, `06c` generates and validates `openapi.yaml`. Only `06a` blocks the rest of the epic; `06b` and `06c` read the registry and are dispatchable any time after it, in parallel with `04` and `03` if you want.
- `04` and `03` deliver three middleware that each refuse on their own input and call `next()` otherwise. None knows its position, so each is tested against a bare `new Koa()` in the shape `05` established, and neither needs the app.
- `01` assembles the chain and fixes the order. It therefore owns every assertion that depends on the order — the browser defences over `system.health`, `origin-forbidden` over `host-forbidden`, a browser code over `401`, and `401` over `404`. Those assertions live in `src/http/server/app.test.ts` and nowhere else.
- `01` also creates `test/helpers/app.ts`, so no story before it uses `createTestApp`.
- `02` needs only `01`'s `serve` sequence. Dispatch it any time after `01`; it is placed here so the child-process cases of `src/services/home-lock/startup.test.ts` are edited once.
- `07` precedes `08`, because `kanthord db status` is a client of `src/cli/client.ts`.
- `08` is last. It is the only story where the registry, the renderer, the four middleware, a query, a handler and the CLI client all run together against one socket.

Measured behaviour — each of these changes an assertion:

- `supertest` honours `.set("Host", ...)`. With no override it sends `127.0.0.1:<ephemeral port>`, so a test app whose allow list is a fixed name refuses every un-overridden request. `test/helpers/app.ts` presets the header for that reason.
- `zod@4.4.3` supports `z.toJSONSchema(schema, { target: "openapi-3.0" })` and emits `enum` for a literal rather than `const`, which is what OpenAPI 3.0 accepts. No generation dependency is needed.
- `YAML.stringify(document, { lineWidth: 0 })` from `yaml@2.9.0` emits LF only and exactly one trailing newline — the canonical form of `docs/proposal/api/README.md:19`.
- `@apidevtools/swagger-parser@12.1.0` exposes only a default export, with `validate` and `dereference` as static members. `validate` rejects a dangling internal `$ref` with a `MissingPointerError` whose message contains `"Missing $ref pointer"`, and rejects a schema violation with a `SyntaxError` whose message contains `"Swagger schema validation failed"`. One call therefore covers both assertions the epic needs.
- `new URL` rejects `http://127.999.0.1` with `ERR_INVALID_URL`, and canonicalises `http://127.1` and `http://127.0.0.01` to hostname `127.0.0.1`. Unifying `isLoopbackUrl` onto the strict octet predicate is therefore behaviour-preserving, and no EPIC 003 expected value changes.
- `new URL("http://[::1]:7421").hostname` is `"[::1]"`, with the brackets.
- `timingSafeEqual` throws when its two buffers differ in length. The token compare hashes both sides to a 32-byte SHA-256 digest first, so the compare always runs and a wrong-length token does not throw.
- `koa@3` reads `X-Forwarded-Host` through `context.request.host` when `app.proxy` is true. Every check in this epic reads `context.request.headers.host`.

## Decisions this epic settled

Fourteen choices the EPIC and the proposal leave open. Each is pinned in a story so none reaches build time. An adversarial review of this story set produced three of them, and Ulrich decided four — the exit-code scheme, the `system.db` shape, `system.health` reporting dependencies behind a token, and the uniqueness reading of the schema rule. Every item in the list below is now settled; none awaits a decision.

- **The registry declares identity for all fifty-three rows, and a schema pair arrives with its use case.** Ratified by Ulrich as the reading of "one zod schema pair per `operationId`" — see B1. `docs/proposal/api/README.md:11` scopes parity to "the set of `operationId`, method and path", and the epic's coverage list requires parity to fail "when a route is declared and not registered", so the full set is registered here. The epic's non-goal, "No domain routes beyond the two that prove the skeleton. Each use case brings its own", scopes the **schemas**. Story 06a writes fifty-three identity rows and zero schemas; Story 08 attaches the first two. `.agents/plan/epics/010-contract-completion.md:18` then enumerates a registry that is already complete, which is what its `501` sweep needs.
- **Uniqueness is enforced, not assumed.** A schema is authored only in `src/http/contract/`. Story 06a asserts that no file under `src/http/server/` or `src/cli/` calls a zod schema constructor, so a handler or a CLI command cannot declare a second shape for an operation that already has one. Story 08 binds each schema to its entry with `assert.strictEqual` — the same object, never an equal copy. Together those are what let `cli/` be a typed client of the same contract the daemon serves, which `AGENTS.md` names as the reason `http/contract/` exists.
- **An unbound `routed` operation fails `createApp`, and a declared-unimplemented one answers `501`.** Twenty-one `routed` operations have no command until EPIC 007 or later, so `createApp` takes an explicit `unimplemented` list and throws `BindingError` when a `routed` operation is in neither that list nor `handlers`, when an id is in both, when an id is absent from the registry, or when a `stubbed` id appears in either. `src/main.ts` derives the list by filtering the registry, so it shrinks without an edit as commands land. The two `501` messages differ — `"<id> ships in <phase>"` for a stub, `"<id> is not implemented yet"` for a declared gap. An earlier draft let an unbound `routed` operation answer `501` silently; that made a wiring defect indistinguishable from a lifecycle state for five epics, and it read against `AGENTS.md` — "A `routed` entry binds to exactly one command or query." The debt is now a reviewable list in the composition root, and forgetting to bind a new command fails at construction instead of answering a plausible `501`. `.agents/plan/epics/009-cli-and-composition-root.md:23` asserts the list is empty.
- **The registry enforces a grammar, not only a vocabulary.** `registryFaults` walks the segment kinds through a state machine: a system path is one leaf or a namespace then a leaf; a resource path is `resource`, then optionally `parameter`, then `subresource`*, then optionally one terminal `action`. `docs/proposal/api/README.md:78` requires exactly this — "A closed vocabulary alone would prove spelling and nothing else — it would accept `/v1/project/:id/project` and `/v1/status/status`." Both counterexamples are asserted rejected, which is why `systemSegments` splits into a namespace set (`db`) and a leaf set (`health`, `status`).
- **A path parameter is never percent-encoded, on either side.** `matchRoute` binds the raw segment and calls no `decodeURIComponent`; the CLI client substitutes the value verbatim and refuses one that would need encoding. `docs/proposal/api/system.md:65` fixes it — "A colon is legal in a path segment, so nothing is percent-encoded" — and `decodeURIComponent` throws a `URIError` on a malformed escape, which inside a middleware would report a client fault as `500 internal-error`.
- **`internal-error` is the twentieth code, and it is the only one this repository adds.** `docs/proposal/api/README.md:147-165` declares no `5xx` besides `501`, and an unexpected throw must still answer one shape. The response body carries the literal message `"internal error"` and never the caught message.
- **A `409` code will not compile without `details`.** `httpError` is one implementation behind two overload signatures, and the `409` overload makes `details` required. `new-decisions.md:13` — "each returns the current value" — becomes a type error rather than a review note.
- **The middleware order is envelope, origin, host, resolve, auth, not-found, body, dispatch.** The proposal fixes the codes and not their precedence, so the precedence is **new security policy decided here** rather than a reading of the error table — a table's row order does not define fault order. Two consequences are asserted. A request with an `Origin` header and a bad `Host` reports `origin-forbidden`: the tie breaks toward the check that needs no configuration to evaluate, and the row order at `README.md:149-150` agrees, which is corroboration and not the reason. An unauthenticated request to an unknown path reports `401` and not `404`, because `resolve` records the match and `not-found` answers only after the token check. The guarantee is stated as an equality and tested as one — without a token, a registered protected path and an unregistered path return the identical status and a deep-equal body. It is **not** "the caller learns nothing": `system.health` is deliberately distinguishable, and a linear matcher has path-dependent timing this epic does not defend against.
- **The registry is the router.** `matchRoute` walks the segment tuples, and `@koa/router` is not added. A path-matching dependency would be a second place a path is spelled, and `blob.show` carries a colon inside its parameter value.
- **The loopback policy moves to `src/domain/loopback.ts`.** The epic asks for no second classifier, and the import matrix forbids one home in either `services/` or `cli/` — `domain/` is the only directory both may import. `src/services/config/refusals.ts` and `src/cli/base-url.ts` become re-export sites, so `src/services/config/refusals.test.ts` and `src/cli/base-url.test.ts` are the regression suite for the move. The grep assertion allows two files: `src/domain/loopback.ts`, and the `default: "127.0.0.1"` line at `src/services/config/convict.ts:47`, which is a configuration default fixed by `phase-1/transport.md:13` and not a classification.
- **A CLI exit code carries its category in the leading digit, in three hundred-blocks.** Ulrich's scheme. `1`–`99` local, meaning the request never reached the daemon; `100`–`199` the daemon refused it; `200`–`255` the daemon failed or has not implemented the route. `0` is success only. Within a block the tens step once per HTTP status and the units separate codes sharing one, so the number is derivable from the error table: `110` `400`; `120` `401`; `130`/`131` the two `403`; `140` `404`; `150`–`158` the nine `409` in table order; `160`–`163` the four `422`; `210` `500`; `220` `501`. `exitCodes` is typed `Readonly<Record<ErrorCode, number>>`, so a code added to `errorStatuses` without an exit code fails `tsc`.
- **The third block ends at 255, and there is no fourth.** A POSIX exit status is masked to `& 0xFF`, so `256` becomes `0` and would report success on a failure. Story 07 asserts every value is at most `255`. That ceiling is why three categories fit and eight would not.
- **An unknown code falls to its category floor.** `exitCodeForError(code, status)` routes on `code` for every code the CLI knows, and consults `status` only when the code is unrecognised — `4xx` gives `100`, `5xx` gives `200`, anything else gives `1`. A daemon newer than the CLI therefore still tells a script which side is at fault. `LOCAL_REFUSAL` stays `1` because `.agents/plan/epics/001-runtime-foundation.md:67` fixes every startup refusal there and EPIC 003 fixes `db-remote-base-url` there; `TRANSPORT_FAILURE` is `2`, a new distinction that separates an unreachable daemon from a bad local configuration.
- **`system.health` reports per-dependency status, and it carries the bearer token.** Ulrich's decision, against `docs/proposal/api/system.md:22-26` (the body is a constant), `README.md:177` and `phase-1/transport.md:21` (the route is token-exempt). `src/queries/system/read-health.ts` takes a list of named reporters, records a throwing probe as `"failed"`, orders lines bytewise by name, and rolls up to `"ok"` or `"degraded"`; a `"not-implemented"` dependency never degrades the daemon. The route answers `200` even when degraded, because a truthful report is not an HTTP error and `503` has no code in the table. `storage` is the only live reporter in this epic. This also closes the `AGENTS.md` half of S4 — the route now binds to exactly one query.
- **No route is exempt from the token, so the chain is six middleware rather than eight.** With no exemption, `authMiddleware` needs no route match, so it runs before resolution and `resolveMiddleware` plus `notFoundMiddleware` collapse into one `routeMiddleware`. `401` before `404` becomes structural instead of a split-resolution trick, and every path — registered or not — returns the identical status and body without a token. Story 03 asserts the absence of the exemption by construction: `src/http/server/auth.ts` contains no `context.state`, no `registry` and no `operationId`, so reintroducing an exemption forces the chain reorder to be visible in the same edit.
- **`Storage` gains `ping()`.** A health probe must neither write nor lock, and no existing method qualifies: `status()` bootstraps the `migration` table, and `transact()` opens `BEGIN IMMEDIATE`. `ping()` is `SELECT 1` outside a transaction.
- **`systemDbResponse` is one ordered list.** `system.md:34` specifies "Returns every migration and whether it is applied" and names no field. `applied` and `pending` flatten into one array sorted ascending by `version`, with `appliedAt` null on a pending row, so a client reads one table instead of joining two. The version is the `migration` primary key, so the sort is total and needs no tie-break.
