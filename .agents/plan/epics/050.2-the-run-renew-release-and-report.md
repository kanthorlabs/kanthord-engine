# EPIC 050.2 — The run renew, release and report

Status: **draft**. It follows EPIC 050.1 by sequence order, and it runs before EPIC 050.3. It consumes EPIC 050's run row and exclusion rules, and EPIC 050.1's migration `12`, its opened run and its expiry pass.

It carries a decimal number because EPIC 051 through EPIC 057 are authored and numbered, and renumbering them to insert a whole-number epic would break every cross-reference between them.

## Goal

A fence guards every write after the claim:

- every write asserts the run is active, unexpired, held by the caller, bound to the target, and carrying the current fence;
- a renew is one operation, and it never touches the fence;
- a release ends the run, returns the node and cancels the open attempt;
- the report prelude proves authority by the run, where it proved it by the lease.

This epic also carries the wire announcement of the whole worker protocol: `node.heartbeat` becomes `node.renew`, `external-drive` retires, `worker-model` is declared, and the major version moves.

## Non-goals

- **No claim.** EPIC 050 owns the run row and the exclusion rules, and EPIC 050.1 owns `node.claim`, the claim seams and the expiry pass. This epic changes no claim path and adds no claim refusal.
- **No checkpoint.** `node.report` gains its authority prelude here, and EPIC 051, 052 and 053 own its body, one per checkpoint type. This epic pins the prelude and nothing after it.
- **No attempt classification.** `termination` lands in EPIC 054. An ended run here records `outcome` only.
- **No node-lease removal.** EPIC 050.4 removes the node rows of the `lease` table. This epic keeps the lease **mechanism**, including the objective lease renewal and the lease release, and it moves the observable surface onto the run so EPIC 050.4 is wire-invisible.
- **No worker switch.** EPIC 056 owns the only writer that changes an assignment.

## Decisions

- **Run authority is five conditions, not one.** `worker.md` section 11 lists an active run and a matching fence as separate guarantees. `assertRunAuthority({ run, runId, fence, targetNodeId, subtreeIds, caller, now })` in `src/domain/run-authority.ts` refuses in this fixed order: `run-not-found`, `run-ended`, `run-expired`, `run-caller-mismatch`, `target-outside-run`, `fence-stale`. An ended run presented with its own last fence must fail, and a fence comparison alone admits it.

- **A refusal never returns the current fence.** EPIC 050.1 states the rule for the claim, and it holds identically here. Handing the replacement value to a writer that just proved it holds a stale one gives that writer the authority the raise was meant to remove. The refusal names the run id and the reason only.

- **`assertRunAuthority` is pure, so the run row is read at the seam.** `execution.runById(transaction, runId)` returns an ended run rather than null, because the authority function refuses it by code and a null would collapse `run-ended` into `run-not-found`. `activeRunOfNode` answers a different question and cannot answer this one.

- **Every run operation evaluates expiry first, inside its own single transaction.** `renew`, `release` and `report` each call `expiry.expireRuns` before anything else, on the `expiry` capability key EPIC 050.1 introduced. Sweeping only at the next claim would leave an expired run able to renew itself back to life. A command that expires a run and then refuses rolls the expiry back with everything else, which EPIC 050.1 states and this epic inherits unchanged.

- **A renew never touches the fence.** The fence rises when a run ends, and nowhere else. A renew that rotated the fence would invalidate the run id and fence pair the worker already holds, which is the authority of that run.

- **A renew sets `expires_at = min(now + runTtlMs, max_lifetime_at)` and refuses `lifetime-exceeded` when `now >= max_lifetime_at`.** The comparison is `>=`, so the boundary instant is expired. EPIC 050 declares both budgets and validates them at startup; this epic is their only consumer beyond the claim.

- **A renew renews the run and every lease that run holds.** `src/commands/node/heartbeat-node.ts:82` renews the objective lease beside the node lease, and the lease mechanism lives until EPIC 050.4. A run on `runTtlMs` that outlived an objective lease on `leaseTtlMs` would free a node that another claim then takes, under a run that still holds authority. The renew therefore keeps `lease.renew` on the target, the objective lease read and the objective `lease.renew`, beside `execution.renewRun`. EPIC 050.4 removes the three lease steps and changes no wire shape when it does.

- **A release returns the node to `ready` and cancels the open attempt.** `src/commands/node/release-node.ts:166-179` closes the open attempt and moves the node from `running` to `ready`. Ending the run alone would leave the node `running` under no run, which no claim can take and no report can close. The release therefore keeps the attempt close and the state write, and adds `execution.endRun` on the branch where the shipped code ended no run.

- **The release reads the attempts once.** `src/commands/node/release-node.ts:101` and `:114` call `attemptsOfRun` twice with one argument, which is two steps of one token and one wasted read. This epic collapses them into one read, and `accountAttempts` receives that list.

- **`release` survives, and it has one stated meaning.** `worker.md` names four verbs: claim, report, close and renew. `release` has no verb in the document, and it is retained: a worker voluntarily ends its run with no checkpoint. Removing it would make an abandoned claim block a node for a full run lifetime.

- **An ordinary failure never changes the assignment.** Ending a run writes `run.state = 'ended'` and raises the fence. It does not clear `node.assignment`. A test asserts the assignment is unchanged after a release and after a rejection, completing the pair EPIC 050.1 began with the expiry case.

- **Exactly one terminal event per run.** `release` and `report` both append `run.ended` with different `outcome` values, in the same transaction as the transition and the fence raise. With EPIC 050.1's expiry appending `run.expired`, a run that moves from `active` to `ended` appends exactly one terminal event across all three paths, never both and never neither.

- **The three `lease.*` event types are gone once this epic lands.** An event is an observability contract, not a mechanism contract, and a reader of `event.list` should never learn that the daemon changed its internal exclusion mechanism. EPIC 050.1 removed `lease.claimed` and added `run.opened` and `run.expired`. This epic removes `lease.renewed` and `lease.released` and adds `run.renewed` and `run.ended`. There are no deployments, so `retiredEventTypes` stays empty. `run.renewed` carries `runId`, `nodeId`, `fence` and `expiresAt`. `run.ended` carries `runId`, `nodeId`, `fence`, `outcome` and `reason`.

- **`node.heartbeat` becomes `node.renew`, and the old operation id is removed.** One vocabulary survives. `node.renew` returns `expiresAt` and `renewAfterMs`, the same two fields EPIC 050.1 put on the claim response, and `heartbeatIntervalMs` leaves the codebase with its last producer.

- **`runId` and `runFence` are required request fields on `node.renew`, `node.release` and `node.report`.** A worker that cannot name its run has no authority to write, so the schema says so rather than a refusal code. `node.claim` returns the run id and the fence, and receives neither.

- **This epic amends the `/v1` policy, because a human ruled there is no `/v2`.** `docs/proposal/api/README.md:100` forbids adding a required request field and closes its list. EPIC 046 records the ruling. This epic writes the amendment into the proposal: a change outside the list is legal when a human records the ruling in the epic that makes it, and the capability name covering the affected operations is retired and replaced. `023-version-compatibility-policy.md` D1 is superseded by that sentence and by nothing else.

- **The capability swap is the announcement, and it is exact.** `capabilityOperations` at `src/http/contract/capability.ts:5` binds `external-drive` to `node.claim`, `node.heartbeat`, `node.release` and `node.report` — precisely the operations EPIC 050.1 and this epic change. `external-drive` is retired, and `worker-model` is declared in its place, naming `node.claim`, `node.renew`, `node.release` and `node.report`. A client reading `system.health.capabilities` sees `external-drive` gone and cannot call the old shape unknowingly, which is the handshake EPIC 023 built.

- **EPIC 050.1 and this epic are one wire generation, delivered in two commits.** EPIC 050.1 changed the claim shape while still declaring `external-drive`, because a capability name announces a finished shape and the claim is half of one. No build is published between the two epics, so no client ever observes a half-changed protocol. The announcement lands once, here. `worker-model` is the last capability name this block declares; EPIC 050.4 changes no wire shape.

- **`KANTHORD_VERSION` moves to `28.0.0`.** `src/domain/version.ts:1` reads `27.8.1`. The policy states the package version describes a build, so the bump records the whole block. The capability list is what describes the wire.

## Stories

Each entry is a name and the output it contributes. The story file holds the change, the tasks and
the diagrams, and it declares its kind. A `story-foundation` draws nothing; a `story-implement` draws
one baseline and one ship diagram. `.agents/plan/authoring.md` is the standard.

1. **Run authority** — `src/domain/run-authority.ts` exports `assertRunAuthority`, returning `null` or one of the six refusals in the fixed order. `story-foundation`.

2. **The authority seams** — `execution.runById` and `execution.renewRun` on `src/services/execution/index.ts`, and one implementation each. `story-foundation`.

3. **The renew** — `src/commands/run/renew-run.ts`, renamed from `heartbeat-node.ts`, moves the run's `expires_at` forward under the authority check, renews both leases, and leaves the fence unchanged.

4. **The lifetime refusal** — a renew at or past `max_lifetime_at` refuses `lifetime-exceeded` and writes nothing.

   Diagrams: renew-refusal-lifetime-exceeded

5. **The release** — `src/commands/node/release-node.ts` ends the run under the authority check, closes the open attempt in one read, returns the node to `ready` and releases the lease.

   Diagrams: release-success

6. **The report prelude** — `src/commands/outcome/report-outcome.ts` proves authority by the run id and the fence the caller presents, where it proved it by the lease. EPIC 051 owns everything after the prelude.

   Diagrams: report-authority-prelude

9. **The proposal records the authority model** — `docs/proposal/phase-2/runs-and-exclusion.md` gains the five authority conditions, the renew formula and its maximum lifetime, the release contract and the one-terminal-event rule. `story-foundation`.

- `assertRunAuthority` refuses each of the six conditions in isolation, and an input failing two reports the earlier one. Story 1.
- `assertRunAuthority` refuses an ended run presented with that run's own last fence, with code `run-ended`. A fence comparison alone would admit it. Story 1.
- No refusal object holds a fence value. The assertion scans the refusal details key set of all six. Story 1.
- `renew`, `release` and `report` each refuse a stale fence, an ended run and an expired run. Nine cases, one per pair. The expired-run case reports `run-ended`, because the expiry pass ends the row before the authority check reads it; `run-expired` is reachable at the pure function alone, and Story 1 covers it. Stories 3, 5 and 6.
- A renew at exactly `max_lifetime_at` refuses `lifetime-exceeded`, and `expires_at` is asserted unchanged. Story 4.
- A successful renew leaves the fence unchanged and moves `expires_at` forward. Both are asserted in one case, so the code cannot drift toward rotating the fence on a renew. Story 3.
- A renew renews the objective lease with the node lease, asserted by reading both `expires_at` values after the call. A run that outlived its objective lease would free a node under a live run. Story 3.
- A release returns the node to `ready` and closes the open attempt, asserted on the node row and the attempt row, beside the ended run. Ending the run alone would leave the node `running` under no run. Story 5.
