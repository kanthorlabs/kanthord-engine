# EPIC 050.2 — The run renew, release and report

Status: **draft**. It follows EPIC 050.1 by sequence order, and it runs before EPIC 050.3. It consumes EPIC 050's run row and exclusion rules, and EPIC 050.1's migration `12`, its opened run and its expiry pass.

It carries a decimal number because EPIC 051 through EPIC 057 are authored and numbered, and renumbering them to insert a whole-number epic would break every cross-reference between them.

## Goal

A fence guards every write after the claim:

- every write asserts the run is active, unexpired, held by the caller, bound to the target, and carrying the current fence;
- a renew is one operation, and it never touches the fence;
- a release ends the run, returns the node and cancels the open attempt;
- the report prelude proves authority by the run, where it proved it by the lease.

This epic also carries the wire announcement of the whole worker protocol: `node.heartbeat` becomes `node.renew`, `external-drive` retires, and `worker-model` is declared. The version does not move; EPIC 050.4 bumps it for the whole block.

## Non-goals

- **No claim.** EPIC 050 owns the run row and the exclusion rules, and EPIC 050.1 owns `node.claim`, the claim seams and the expiry pass. This epic changes no claim path and adds no claim refusal.
- **No checkpoint.** `node.report` gains its authority prelude here, and EPIC 051, 052 and 053 own its body, one per checkpoint type. This epic pins the prelude and nothing after it.
- **No attempt classification.** `termination` lands in EPIC 054. An ended run here records `outcome` only.
- **No node-lease removal.** EPIC 050.4 removes the node rows of the `lease` table. This epic keeps the lease **mechanism**, including the objective lease renewal and the lease release, and it moves the observable surface onto the run so EPIC 050.4 is wire-invisible.
- **No worker switch.** EPIC 056 owns the only writer that changes an assignment.

## Decisions

- **Run authority is five conditions, not one.** `worker.md` section 11 lists an active run and a matching fence as separate guarantees. `assertRunAuthority({ run, runId, fence, targetNodeId, caller, now })` in `src/domain/run-authority.ts` refuses in this fixed order: `run-not-found`, `run-ended`, `run-expired`, `run-caller-mismatch`, `target-outside-run`, `fence-stale`. An ended run presented with its own last fence must fail, and a fence comparison alone admits it.

- **The node read precedes the authority check on all three operations.** `assertRunAuthority` condition 5 refuses `target-outside-run` for a target that is not the run's node, and an absent node and an initiative both satisfy it. Reading the node after the authority check therefore makes `src/commands/node/release-node.ts:68` `node-not-found`, `src/commands/node/release-node.ts:72` `initiative-not-claimable`, `src/commands/node/heartbeat-node.ts:70` `node-not-found`, `src/commands/node/heartbeat-node.ts:74` `initiative-not-claimable` and `src/commands/outcome/report-outcome.ts:116` `initiative-not-reportable` unreachable, and two wire-visible codes change meaning. The four ship diagrams read the node first, and each of Stories 3, 5 and 6 carries a refusal pair plus a `target-outside-run` control that proves the precedence.

- **Condition 5 binds a write to the run of that node, and to no wider set.** An earlier draft admitted any target inside `plan.readSubtree(run.nodeId)`. A structural objective run holds no attempt, so that admission let a task `release` present the objective run id and refuse `no-open-attempt`, and let a task `report` present it and reach `src/commands/outcome/report-outcome.ts:209` — a bare `Error` and a 500. The binding is therefore `targetNodeId === run.nodeId`. The subtree rule of EPIC 050 governs claim-time exclusion, not authority. The subtree-bound structural mutation of `worker.md:412` belongs to EPIC 052, which declares its own admission and its own control case; it never widens condition 5 in place. `plan.readSubtree` leaves the prelude of all three operations, and Stories 3, 4, 5 and 6 drop the token from their Seams and their diagrams.

- **A refusal never returns the current fence.** EPIC 050.1 states the rule for the claim, and it holds identically here. Handing the replacement value to a writer that just proved it holds a stale one gives that writer the authority the raise was meant to remove. The refusal names the run id and the reason only.

- **`assertRunAuthority` is pure, so the run row is read at the seam.** `execution.runById(transaction, runId)` returns an ended run rather than null, because the authority function refuses it by code and a null would collapse `run-ended` into `run-not-found`. `activeRunOfNode` answers a different question and cannot answer this one.

- **Every run operation evaluates expiry first, inside its own single transaction.** `renew`, `release` and `report` each call `expiry.expireRuns` before anything else, on the `expiry` capability key EPIC 050.1 introduced. Sweeping only at the next claim would leave an expired run able to renew itself back to life. A command that expires a run and then refuses rolls the expiry back with everything else, which EPIC 050.1 states and this epic inherits unchanged.

- **A renew never touches the fence.** The fence rises when a run ends, and nowhere else. A renew that rotated the fence would invalidate the run id and fence pair the worker already holds, which is the authority of that run.

- **A renew sets `expires_at = min(now + runTtlMs, max_lifetime_at)` and refuses `lifetime-exceeded` when `now >= max_lifetime_at`.** The comparison is `>=`, so the boundary instant is expired. EPIC 050 declares both budgets and validates them at startup; this epic is their only consumer beyond the claim.

- **A renew renews the run and every lease that run holds.** `src/commands/node/heartbeat-node.ts:84` renews the objective lease beside the node lease, and the lease mechanism lives until EPIC 050.4. A run on `runTtlMs` that outlived an objective lease on `leaseTtlMs` would free a node that another claim then takes, under a run that still holds authority. The renew therefore keeps `lease.renew` on the target, the objective lease read and the objective `lease.renew`, beside `execution.renewRun`. EPIC 050.4 removes the three lease steps and changes no wire shape when it does.

- **A release returns the node to `ready` and cancels the open attempt.** `src/commands/node/release-node.ts:166-179` closes the open attempt and moves the node from `running` to `ready`. Ending the run alone would leave the node `running` under no run, which no claim can take and no report can close. The release therefore keeps the attempt close and the state write, and adds `execution.endRun` on the branch where the shipped code ended no run.

- **The release reads the attempts once.** `src/commands/node/release-node.ts:101` and `:115` call `attemptsOfRun` twice with one argument, which is two steps of one token and one wasted read. This epic collapses them into one read, and `accountAttempts` receives that list.

- **`release` survives, and it has one stated meaning.** `worker.md` names four verbs: claim, report, close and renew. `release` has no verb in the document, and it is retained: a worker voluntarily ends its run with no checkpoint. Removing it would make an abandoned claim block a node for a full run lifetime.

- **An ordinary failure never changes the assignment.** Ending a run writes `run.state = 'ended'` and raises the fence. It does not clear `node.assignment`. A test asserts the assignment is unchanged after a release and after a rejection, completing the pair EPIC 050.1 began with the expiry case.

- **Exactly one terminal event per run on the release and expiry paths this epic owns.** `release` appends `run.ended`, and EPIC 050.1's expiry pass appends `run.expired`, in the same transaction as the transition and the fence raise. When one of these owned paths moves a run from `active` to `ended`, it appends exactly one terminal event, never both and never neither. The `node.report` terminal event is assigned to EPIC 050.4 Story 6; this epic's report prelude changes no seam call after the authority check. Its retained lease release maps a stale body fence to `lease-held` until EPIC 050.4 removes that release.

- **The three `lease.*` event types are gone once this epic lands.** An event is an observability contract, not a mechanism contract, and a reader of `event.list` should never learn that the daemon changed its internal exclusion mechanism. EPIC 050.1 removed `lease.claimed` and added `run.opened` and `run.expired`. This epic removes `lease.renewed` and `lease.released` and adds `run.renewed` and `run.ended`, each in the story that writes its producer: Story 3 owns `run.renewed`, and Story 5 owns `run.ended`. `src/http/contract/event-payload.test.ts:344` asserts every produced type is declared and `:365` asserts every declared non-retired type has a producer, both by literal string scan over `src/commands`, so a contract-only story would fail one scan in each direction. `lease.released` has three producers — `src/commands/node/release-node.ts:154`, `:191` and `:290` — and Story 5 converts all three, the objective one included, because leaving it would keep the type produced. There are no deployments, so `retiredEventTypes` stays empty. `run.renewed` carries `runId`, `nodeId`, `fence` and `expiresAt`. `run.ended` carries `runId`, `nodeId`, `fence`, `outcome` and `reason`.

- **`node.heartbeat` becomes `node.renew`, and the old operation id is removed.** One vocabulary survives. `node.renew` returns `expiresAt` and `renewAfterMs`, the same two fields EPIC 050.1 put on the claim response, and `heartbeatIntervalMs` leaves the codebase with its last producer.

- **A lease fence and a run fence are two counters, and the claim response names both of each.** A lease fence rises when a lease is taken again after it expires; a run fence rises only when a run ends. The shipped `nodeClaimResponse` returned `objectiveRunId` with no fence of that run, so every caller presented `objectiveLease.fence` as the objective run fence. A claim reuses an active structural objective run, so that lease fence reaches 2 while the reused run's fence stays 1, and the presented value is refused `fence-stale`. The response therefore carries `lease.fence`, `runFence`, `objectiveLease.fence` and `objectiveRunFence`, and the top-level `fence` is renamed `runFence` because on the renew and release requests `fence` means the lease fence. The CLI prints the four under four names and the e2e harness parses all four. This changes `node.claim`, which EPIC 050.1 settled: the two epics are one wire generation delivered in two commits, no build is published between them, and the claim is the only place a worker can learn a run fence it must later present. Story 7 carries it and Story 8's compatibility record lists it.

- **A task renew moves the objective run with the task run, and a claim refreshes the objective run it reuses.** A task claim opens or reuses one structural run over the objective, and the shipped renew moved the task run alone. The objective run then expires under a live task run: the expiry pass ends it, raises its fence, and the later attest or close refuses `run-ended`. The reuse path has the same hole at the claim, because a reused run keeps the expiry its last writer left and a worker told to renew after `runTtlMs / 3` can reach that deadline first. The renew therefore renews the structural run of the target's objective scope, derived from the node exactly as the objective lease is derived, and the claim renews the run it reuses. Each appends one `run.renewed` per run whose `expires_at` moved, so a task renew appends two. No request field is added: the task run's own authority already proves the caller holds a claim under that objective. Each run clamps to its **own** `max_lifetime_at`, and no path renews past it. EPIC 050.2.1 refuses `objective-run-lost` on the read this decision adds, so that read precedes every write of the renew.

- **`runId` and `runFence` are required request fields on `node.renew`, `node.release` and `node.report`.** A worker that cannot name its run has no authority to write, so the schema says so rather than a refusal code. `node.claim` returns the run id and the fence, and receives neither.

- **This epic amends the `/v1` policy, because a human ruled there is no `/v2`.** `docs/proposal/api/README.md:100` forbids adding a required request field and closes its list. EPIC 046 records the ruling. This epic writes the amendment into the proposal: a change outside the list is legal when a human records the ruling in the epic that makes it, and the capability name covering the affected operations is retired and replaced. `023-version-compatibility-policy.md` D1 is superseded by that sentence and by nothing else.

- **The capability swap is the announcement, and it is exact.** `capabilityOperations` at `src/http/contract/capability.ts:5` binds `external-drive` to `node.claim`, `node.heartbeat`, `node.release` and `node.report` — precisely the operations EPIC 050.1 and this epic change. `external-drive` is retired, and `worker-model` is declared in its place, naming `node.claim`, `node.renew`, `node.release` and `node.report`. A client reading `system.health.capabilities` sees `external-drive` gone and cannot call the old shape unknowingly, which is the handshake EPIC 023 built.

- **EPIC 050.1 and this epic are one wire generation, delivered in two commits.** EPIC 050.1 changed the claim shape while still declaring `external-drive`, because a capability name announces a finished shape and the claim is half of one. No build is published between the two epics, so no client ever observes a half-changed protocol. The announcement lands once, here. `worker-model` is the last capability name this block declares; EPIC 050.4 changes no wire shape.

- **This epic bumps no version.** `src/domain/version.ts:1` reads `27.8.1` and stays there, and `package.json` stays with it. `src/domain/version.test.ts:13` binds the two, and they sit in different lane ceilings, so moving them costs a story slot for no wire signal. The capability list is what describes the wire, and EPIC 050.4 moves the pair to `29.0.0` for the whole block.
