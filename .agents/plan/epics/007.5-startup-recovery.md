# EPIC 007.5 — Startup recovery

Status: **ready**.

## Goal

The daemon establishes a clean, owned home before it reports ready. It proves that no predecessor's `git` child survives, removes the remnants that only a dead predecessor leaves, reconciles the local journal, and recovers expired leases — in that order, every time. `docs/proposal/phase-3/recovery.md` holds the sequence.

## Why this epic exists

EPIC 001 shipped a startup sweep on the home lock alone. That was correct while git ran in process, because the daemon dying stopped git. It is not correct now: a `git` child is a separate process and outlives the daemon, the operating system releases the home lock the moment the daemon dies, and a replacement daemon would delete a lock a live `git` still owns. The sweep was removed rather than left unsafe, so nothing sweeps today. This epic restores the capability with the missing proof in front of it.

It sits after EPIC 007 because a reap needs a journal row that only a real git operation writes, and before EPIC 009 because the composition root wires this into startup.

## Non-goals

- No remote reconcile at startup. A `publish` row needs the network, and it is reconciled after readiness so a remote outage costs one repository rather than the daemon.
- No phase-2 recovery semantics. Lease expiry beyond the phase-1 rule, and divergence repair, stay where they are.

## Stories

- **The launcher handshake and the injected scheduler** — the launcher writes its pid file, reports on descriptor 3, then waits for one byte from the daemon, then `exec`s. The daemon holds that byte until the report arrives, so the release always follows the pid write; a byte sent at spawn time outlives the daemon in the pipe and releases a launcher whose daemon is already gone. A launcher whose daemon died before the release sees end-of-file and exits without touching the target. Without it, "no pid file" is not a final observation: a shell spawned a moment before the crash can write its pid file and start `git` after a replacement daemon has already reaped and begun sweeping. The same story injects the timeout scheduler into `createGitRunner`, because four of its tests prove a timeout by waiting for real milliseconds and one of them raced its own descendant — the hermetic suite must carry no wall clock, and it does only because the seam is missing. This is the one story in this epic that changes EPIC 006 behaviour; the later stories add members to `src/services/git/index.ts` and `binary.ts` without altering what is there.

- **Journalling a spawn** — the command layer commits the `git_operation` row carrying `child_token`, the pid-file path the launcher will write, before it asks the git service to spawn. Completing or discarding a row clears the token and removes the file. EPIC 006 owns the launcher that writes the file; this story owns the row that points at it.

  **The seed exception.** `repository.register` spawns `git` before its `repository` row exists, and `git_operation.repository_id` is `NOT NULL REFERENCES repository(id)` while `ref`, `base_oid` and `proposed_head_oid` are `NOT NULL` and unknown until after the fetch. A seed spawn therefore carries no journal row, and its record is the pid file itself, in the daemon-owned run directory. `docs/proposal/phase-3/recovery.md` states the rule and its limit. This story delivers the interface and its tests; the first production caller is the first journaled write on an already registered repository, which a later epic binds to a route.

- **The orphan reap** — for every in-flight row carrying a token, **and for every pid file in the run directory**, read the pid file and decide liveness. Both sources are needed: a seed spawn carries no row, and `seedHome` passes the caller's pid file to only two of its six spawns while the other four take a runner-minted name. The run directory is daemon-created at mode `0700` inside a locked home, so every name in it is the daemon's own; a name grammar adds attribution and never filters a candidate. No pid file means `git` never started. A pid is this row's child when it is alive and its operating-system start time precedes the pid file's creation time; a process that reused the number started after that file existed and is left alone. A live child is an orphan: signal its process group, wait for it to exit, then continue. An orphan that will not exit refuses startup and names the process and the repository. Reading a process start time is platform work, and the story names the supported platforms and the source on each.
- **The startup sweep** — remove the three classes of remnant `docs/proposal/phase-3/recovery.md` lists: git lock files, staging directories from an unfinished seed or clone, and decrypted ssh key material. Every removal asserts a daemon-owned boundary, a regular file or a staging directory, and no symbolic link on the path. A remnant failing any check is left alone and reported. Removal happens only after the reap.
- **Local journal reconcile** — resolve every incomplete `merge`, `sync` and `revert` row against one reading of the real ref, by the matrix in `docs/proposal/phase-3/recovery.md`. A `publish` row is left open and marked for reconcile, and the repository owning it refuses new work until that succeeds. That refusal is a verdict function with its own tests and **no call site in this phase**, because no phase-1 command writes to an already registered repository; the first caller arrives with the first repeat write path. An unreadable ref refuses startup.
- **Expired lease recovery** — a `running` node whose lease has expired at startup returns to `ready` when its workspace is clean and its head equals the recorded base, and otherwise moves to `blocked` with reason `dirty-recovery`. Expiry is read from the injected clock, never from the wall clock. Each transition writes an event. `docs/proposal/phase-3/recovery.md` fixes the rule and `docs/proposal/phase-1/state-machine.md` fixes the states.
- **The recovery component and its ordering** — one unit runs reap, sweep, reconcile, leases in order, after the tool probe that EPIC 007 owns. It takes the four steps as injected functions and names no implementation, because a file under `src/commands/` may not import another one and the four steps are commands; `src/main.ts` binds them over the storage and git interfaces and the held home. The sweep takes the reap's report as its argument, so it is unreachable before the reap resolves. The unit is wired into `src/main.ts` before readiness is announced, and the order is asserted in a unit test rather than assumed.

Every path is named. A `**` glob is not used: `**` is not recursive in a default `bash` or `zsh` without `globstar` or `extendedglob`, so a glob makes the match set depend on the operator's shell, and a Proof that matches nothing still prints `PASS`.

Hermetic coverage required beyond the Proof:

- **The ordering proof.** A daemon started against a home holding a stale ref lock reports ready only after that lock is gone, and a second daemon against the same home exits non-zero naming `home-locked`. This restores the assertion EPIC 001 carried and the library migration removed.
- A live process recorded as an in-flight child is signalled and waited for before any removal happens, asserted by observing that the lock still exists while the child lives.
- A recorded pid that has been reused by an unrelated process is not signalled, proved by recording a pid with a start time that does not match.
- An orphan that ignores the signal refuses startup, and the message names the process and the repository.
- A lock file reached through a symbolic link pointing outside the home is not removed, and it is reported.
- A staging directory from an interrupted seed is removed, and a finished home beside it is untouched.
- An ssh key file left by a killed daemon is removed before anything touches the network.
- A `publish` row is still open after startup, the daemon is ready, and the verdict function reports that the repository owning it refuses new work. The verdict is asserted at unit level, because this phase has no route that would consume it.
- A ref that matches neither the base nor the proposed head leaves the row open, reports, and does not retry.
- An expired lease on a clean workspace at the recorded base returns the node to `ready`, and an expired lease on a dirty workspace moves it to `blocked` with reason `dirty-recovery`. Both write an event, and both read expiry from a mock clock.
- An in-flight row whose pid file was never written is treated as "git never started", and its remnants are removed. That reading is only sound because of the launcher handshake: an orphaned launcher exits without `exec`, so an absent pid file cannot become a running `git` after the reap has passed.
- A launcher held before its pid write runs no command once its daemon dies. The pid-file path is a FIFO, so the launcher blocks in `open`; the daemon that spawned it through the real `spawnSupervised` exits; releasing the FIFO afterwards leaves the target unrun. This is the one case that fails against a daemon which sends its release byte at spawn time.
- A surviving `git push --dry-run` child of an interrupted seed, recorded only by a runner-minted pid file with no journal row, is reaped before its staging directory is removed.
