# EPIC 106 — Agents on `pi-coding-agent`

Status: **ready**. It consumes the process capability of EPIC 050.6, which holds the launcher, the one
spawned-child supervision machine and the TERM-then-KILL cancel path, and it re-specifies none of it.
**This epic holds fifteen stories against a cap of ten and must be split before dispatch**;
`.agents/plan/authoring.md` calls eleven a split and not a judgement call. EPIC 050.6 removed two
stories and does not fix that.

## Goal

`general@1` and `re@1` run on the installed `@earendil-works/pi-coding-agent` version `0.80.6`, each under the tool allow list of `docs/proposal/phase-2/agents-and-workers.md`. `src/services/agent/index.ts` is rewritten into the evidence contract, and `src/services/agent/pi-coding-agent.ts` holds the one implementation, `PiCodingAgent`. It builds each built-in tool from the root exports `createReadTool`, `createLsTool`, `createFindTool`, `createGrepTool`, `createEditTool`, `createWriteTool` and `createBashTool`, computes the exclusion from the allow list, and asserts the constructed tool set is exactly the allow list. It builds `DefaultResourceLoader` with `noContextFiles: true` and asserts the loader reported zero context files. It runs one `Agent` of `@earendil-works/pi-agent-core` with `toolExecution: "sequential"`, and its `streamFn` reaches the provider only through the `Model` interface of `src/services/model/index.ts`, so this epic names no provider API and constructs no `PiAi`. The agent shell runs on the `SupervisedRunner` of `src/services/process/`, which EPIC 050.6 extracts together with every git repair the move forces; this epic builds no supervision machinery and takes that runner as a dependency. A run carries a timeout from `agent.timeoutMs`, and a timeout or a cancellation signals the process group of every shell child. A run **returns** the rendered messages as canonical bytes, every source byte sequence, the provider usage, the tool trace, the diff, the `re@1` verdict per criterion, the adapter version and the tool definitions, and it writes no row. `agent.list` moves from `stubbed` to `routed` in `src/http/contract/instruction.ts`, so `GET /v1/agent` answers every role with its role contract identity and its tool set, and the capability this epic ships is reachable through a route.

## Non-goals

- No worker loop, no attempt row, no persistence. EPIC 110 owns the attempt lifecycle: it pins the registration and the `provider_model`, writes the `agent_invocation` row of `src/domain/agent-invocation.ts`, stores every blob, writes `usage_json`, and writes each transition with its event in one storage transaction. This epic opens no storage transaction and takes no `Storage` dependency.
- No reject-and-retry route and no task gate semantics. EPIC 110 owns the attempt counter, the `attempt-limit` block and the acceptance path. This epic returns a verdict and decides no state.
- No route other than `agent.list` moves to `routed`. `template.list`, `template.show`, `profile.verify` and every other phase-2 operation keep the lifecycle EPIC 104 and later epics give them.
- No inspection read of a recorded attempt. EPIC 111 owns `node.attempts`, `attempt.show`, `node.checks` and `worker.list`, and each reads a row this epic never writes.
- No check execution. EPIC 107 owns the verify service, its limits and its result record. A `bash` tool call is not a declared check.
- No prompt composition. EPIC 104 owns the channels, the render and the budget. This epic sends the composed bytes and adds no text of its own.
- No ambient loading. EPIC 105 owns the freeze and the host switch, and EPIC 110 owns the drop event. This epic owns the `noContextFiles: true` construction and the fail-closed assertion only.
- No `te@1`, no `swe@1`, no `git@1` run. `docs/proposal/phase-2/agents-and-workers.md` defers all three, and their tool sets are decided when they ship. `agent.list` reports each as deferred.
- No journal row. The diff runs on a temporary index and writes no ref and no working tree file, so no git write of this epic changes state. EPIC 108, EPIC 112 and EPIC 113 own the journal rows of the phase.
- No filesystem confinement claim. The capability control is the tool set, per `docs/proposal/phase-2/agents-and-workers.md`. The tools receive the workspace path as their working directory, and EPIC 110 owns the workspace.
