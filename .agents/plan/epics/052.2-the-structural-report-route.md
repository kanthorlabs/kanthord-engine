# EPIC 052.2 — The structural report route

Status: **draft**. It follows EPIC 052.1 by sequence order, and it runs before EPIC 053. It consumes EPIC 052.1's `acceptStructural` and every refusal that command decides, EPIC 051.4's `report-checkpoint-gate` diagram, and EPIC 050.2's authority prelude.

It carries a decimal number for the reason EPIC 052 states.

**This epic is the consumer half of the EPIC 052.1 split.** The honest seam trace of `acceptStructural` draws eight diagrams, and with the lowering and the proposal amendment EPIC 052.1 is already ten stories. The seventh `node.report` member, the wire error declarations, the refusal mapping and `report-structural-gate` are the eleventh and twelfth, so they land here. The wire contract and the route that honours it are one epic on purpose: a contract that advertises a request member the daemon cannot serve is a defect no gate catches.

## Goal

A structural run reports its patch over the wire:

- `nodeReportRequest` carries a seventh member, `{ report: "structural", fence, patch: unknown }`;
- `reportOutcome` injects `accept.structural` as a nested callable that takes the caller's transaction, after the authority prelude;
- `initiative-not-reportable` is lifted for the structural member alone, and the other six members keep it;
- each of the ten refusal groups maps to its own contract error, and every mapping is parsed against the operation's own envelope.

## Non-goals

- **No refusal semantics and no new command.** Every verdict is EPIC 052's and every ordering is EPIC 052.1's. This epic maps the refusals that command already raises to their contract errors, and it adds no predicate. `src/commands/checkpoint/accept-structural.ts` is not edited here.
- **No proposal amendment.** `docs/proposal/phase-2/checkpoints.md` records the behaviour, and EPIC 052.1 Story 10 (`10-the-proposal-records-the-structural-acceptance`) amends it, because `AGENTS.md` makes `docs/proposal/` the source of truth for behaviour and the behaviour is decided there. This epic amends `docs/proposal/api/README.md` alone, and only its error-code matrix.
- **No supersession of `report-checkpoint-gate`.** `.agents/plan/stories/051.4-the-acceptance-gate-and-the-report-route/08-the-report-route-enforces-the-gate.md` states that only the `accepted` member on an execution node reaches its `accept.execution` step, and that the other five members keep the tail `report-lease-free` drew. The structural member is a seventh member and a wholly new path, so its prior set is empty and every token of `report-structural-gate` is `+`.
- **No migration, no worker and no claim change.** Each is EPIC 052.1's non-goal for the reason that epic states, and none moves here.

## Decisions

- **The wire contract and the route are one epic, and the contract never ships ahead of its handler.** `src/http/contract/` is registry data that builds the published OpenAPI document, so a `nodeReportRequest` member declared without the handler that serves it puts a request shape in `pnpm run contract:publish` that the daemon answers with an undeclared substitute. `AGENTS.md` states a `routed` entry binds to exactly one command; a member of a routed operation is bound the same way. The split that produced this epic therefore cut between the command and its consumer, never between the contract and its route.

- **The seventh member carries the patch as an opaque value.** `nodeReportRequest` at `src/http/contract/outcome.ts:23-53` gains `{ report: "structural", fence, patch: unknown }`, and `graphPatch.safeParse` runs inside `reportOutcome` after the authority prelude. **Embedding `graphPatch` in the contract would break the proof of the fixed order**: HTTP validation would reject a malformed patch with `invalid-request` before `assertRunAuthority` ran, and the order requires a stale fence to refuse before the patch is read. Gate row 28 is what pins it. The discriminator is `"structural"`, matching the run kind and the checkpoint kind.

- **`initiative-not-reportable` is lifted for one member, and the lift is narrowed by a paired case.** `src/commands/outcome/report-outcome.ts:116` refuses every report on an initiative today, and an initiative's run is `structural`, so the structural member cannot reach `accept.structural` while the guard stands. `worker.md:365` states a run never sets an initiative terminal state, which is why lifting the guard moves no node state. The other six members keep it, and gate row 35 asserts both directions in one case.

- **`stale-revision` and `plan-invalid` are declared on the operation and added to neither code registry.** Both already exist, at `src/http/contract/errors.ts:14` and `:30` and at `src/cli/exit-code.ts:20` and `:30`, and the handler now raises both. The operation's `errors` record is what builds its envelope, and `src/http/contract/coverage.test.ts:536` — `errorStatuses` checks only the reverse direction, that a declared code is a key of `errorStatuses`, so it catches nothing here. An undeclared code leaves `pnpm run contract:publish` describing no envelope for a response the daemon returns.

### Seam keys this epic introduces

- `accept.structural` — the nested callable injected into `ReportOutcomeDependencies`, taking the caller's transaction. It is one step of `report-structural-gate`, and EPIC 052.1 carries its eight diagrams.
- `storage.transact`, `clock.now`, `expiry.expireRuns`, `plan.readNode`, `execution.runById`, `plan.readSubtree`, `execution.attemptsOfRun` — all present since EPIC 050.2; this epic labels them and adds no method.
