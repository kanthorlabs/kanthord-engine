# EPIC 054.1 — The end-attempt command

Status: **draft**. It follows EPIC 054 by sequence order, and it runs before EPIC 054.2. It consumes EPIC 054's classifier, conversion, close statement, node counter and `attempt.ended` event type.

It carries a decimal number because EPIC 055, EPIC 056 and EPIC 057 are already numbered, and renumbering them would move every cross-reference.

**Dispatch prerequisite.** EPIC 054 ships before this one. Story 1 inserts `"054.1"` into `scripts/epic-sequence-range.ts:1` — `authoredEpics` after `"054"`, and Story 4 appends it to `shippedEpics`, which `test/sequence/conformance.test.ts:254` — `shippedEpics` requires to stay a prefix of `authoredEpics`. Story 4 is therefore last in dispatch order.

**It holds four stories.** One command, three drawn paths. No story of this epic calls the command from a product path: the nine paths that must call it are EPIC 054.2, EPIC 054.3 and EPIC 054.4, and each of those epics draws the path it changes.

## Goal

One command ends an attempt, and it is the only closer of one:

- `endAttempt(dependencies, transaction, input)` reads the accounting, classifies, converts, closes and appends, in the transaction it receives;
- it takes an accepted ending and a non-accepted ending, so `execution.closeAttempt` ends with one caller;
- it opens no transaction of its own, so a caller inside one can call it;
- an ambiguous termination increments the node counter, and a semantic or an accepted ending does not;
- a settlement over an attempt another operation already closed writes nothing and appends nothing;
- it deletes no git ref, and the caller discards the candidate after the transaction commits.

## Non-goals

- **No caller.** Every product path that must call this command is EPIC 054.2, EPIC 054.3 or EPIC 054.4, the accepted arms included. This epic's scenarios drive the command directly, as `.agents/plan/stories/051.4-the-acceptance-gate-and-the-report-route/07-the-gate-accepts-and-writes-the-checkpoint.md:14` — `drives the command directly` does for `acceptExecution`.
- **No transaction of its own.** The command takes the caller's transaction and opens none. Its diagrams therefore hold no `storage.transact` step.
- **No candidate discard.** A git write cannot join a SQLite transaction, so the discard belongs to the caller, after the transaction commits. EPIC 054.2, EPIC 054.3 and EPIC 054.4 each own the discards of their own paths.
- **No schema change, and no new seam.** EPIC 054 landed the close statement, the counter statement, the classifier and the event type.
- **No worker switch.** `.agents/plan/epics/056-the-worker-switch.md:45` — `end-attempt` calls this command from the switch and clears the counter. That epic owns the call and the arm distinction.

## Decisions

- **One command ends an attempt, it takes the caller's transaction, and it opens none.** `src/commands/attempt/end-attempt.ts` exports `endAttempt(dependencies, transaction, input)`. Every caller is already inside a transaction, and `src/commands/outcome/aggregate-initiative.ts:20` — `aggregateInitiative` is the shipped idiom for a nested write. A second `storage.transact` inside a caller's transaction is not a transaction, and a command of its own would give the expiry path — which runs inside `claimNode`'s transaction — no legal caller at all.

- **The close is the settlement guard, and no re-read stands in for it.** `src/services/execution/sqlite.ts:294` — `UPDATE attempt SET outcome` carries `WHERE id = ? AND outcome IS NULL` and `RETURNING`, so a close over an already-closed attempt returns zero rows inside the same statement that would have written. A separate "is it still open" read would decide on a value read before the write, which is the shape the guard exists to remove. **The zero-row result therefore decides the no-op**, and the command appends no event on that path.

- **A no-op settlement is not a refusal.** The earlier termination stands, no second `attempt.ended` is appended, and the command reports the settlement as already settled. The caller's own refusal is unchanged, because the client's request is refused either way. A late write would otherwise replace an `infrastructure` or `ambiguous` termination with a `semantic` one and move the attempt limit for an ending it did not cause.

- **Three paths are drawn, and neither the conversion nor the acceptance is one of them.** The seam set of a semantic ending and the seam set of an ambiguous ending differ by the counter increment, so each is a diagram. A **converted** ambiguous ending has the seam set of the ambiguous ending and stores a different value, and `.agents/plan/stories/050.2-the-run-renew-release-and-report/05-the-release.md:16` — `projected.exhausted` already rules that a branch which changes a value and not the call set is not a diagram. **An accepted ending has the seam set of a semantic ending** — the two reads, the close, the append — and differs only in what it stores and what the payload holds, so it is a case of Story 1 and not a fourth diagram. The conversion is a case of Story 2.

- **The counter is read on every path, because the payload carries it.** `ambiguousUsedAfter` and `semanticCountAfter` are members of the `attempt.ended` payload EPIC 054 settled, so the read of the counter and the read of the run's attempts precede the close on all three paths. The order is: read the attempts, read the counter, close, increment where the class is ambiguous, append.

- **The input is a two-member union, and neither member carries a class.** The **non-accepted** member is `{ attemptId, runId, nodeId, attemptNo, outcome, evidence }`, and the command selects `classifyInternal` or `classifyExternal` from the run driver it reads. The **accepted** member is `{ attemptId, runId, nodeId, attemptNo, outcome: "accepted", headOid }`, and it reaches no classifier, because `../docs/workflow/worker.md:467` — `A daemon rejection` classifies a failure and an acceptance is none. A caller that could pass a class would make the classifier optional.

- **The command closes every attempt, so `execution.closeAttempt` ends this family with one caller.** An accepted arm that kept its own close would compute the same snapshot at three more sites, and the closure of EPIC 054.4 would stay a list of callers rather than a count of one. EPIC 054.2 and EPIC 054.3 route their accepted arms here, and each supersedes the diagram of the arm it changes.

- **`end-attempt` writes and does not discard.** The candidate ref is attempt-scoped — `refs/kanthord/candidate/<runId>/<attemptNo>`, per `../docs/workflow/worker.md:423` — `refs/kanthord/candidate/` — and every discard calls `candidate.discard` of EPIC 051.1 Story 4 (`04-the-candidate-ref-is-deleted`) and never `git.deleteRef` directly. This command holds no `Git` and no `Candidate` dependency at all, which is what makes the absence provable rather than asserted.

- **A worker switch deletes the candidate ref it orphans, and only on the arm that ended an attempt.** EPIC 056 asked this family to rule the owner, and the ruling is the switch itself, after its transaction commits. It has such a point where the expiry path has none: `../docs/workflow/worker.md:292` — `after that transaction commits` already places the attempt-workspace discard there. The call is unconditional over the ref, because `candidate.discard` on an absent ref exits `0` — `.agents/plan/stories/051.1-the-candidate-and-the-git-primitives/04-the-candidate-ref-is-deleted.md:196` — `discarding an absent ref resolves` — so a switch before any candidate push and one after it reach the same single step. **The no-run arm calls it zero times**, because it ends no attempt and therefore orphans no attempt-scoped ref. All six conditions of `AGENTS.md` hold: no database mutation and no event ride with the deletion; correctness does not need it immediate; eligibility is the committed run end and the closed attempt the switch transaction wrote, over an attempt-scoped ref; a failure leaves an inert ref; `candidate.sweep` discards every ref whose run is not `active` at startup — `.agents/plan/epics/051.1-the-candidate-and-the-git-primitives.md:97` — `candidate.sweep`; and the switch settles its whole outcome in the committed transaction first.

- **A failed cleanup never changes a switch's result.** The assignment, the fence and the run end are committed before the deletion runs, so a deletion that throws still answers success and leaves the ref to `candidate.sweep`. Reporting failure would tell a human the switch did not happen, and their retry would answer `switch-unchanged` over an assignment that had already moved.

## Sequence

Three diagrams, one per drawn path, each with an empty prior set: `end-attempt-semantic`,
`end-attempt-ambiguous` and `end-attempt-settled`. Each is owned by exactly one story, and each story
adds its scenario at `test/sequence/scenarios/<id>.ts`. No diagram holds a `storage.transact` step,
per the Decisions.

## Stories

Each entry is a name and the output it contributes. The story file holds the change, the tasks and the diagrams, and it declares its kind. `.agents/plan/authoring.md` is the standard.

1. **A semantic ending, and an accepted one.** Add `src/commands/attempt/end-attempt.ts` with `EndAttemptDependencies`, the two-member `EndAttemptInput` and `endAttempt`, performing the two reads, the classification of a non-accepted ending, the close and the append. Draw `end-attempt-semantic`: four steps, no increment. Its prior set is empty, so every token is `+`. The accepted ending is a case of this story, because its seam set is the drawn one. Insert `"054.1"` into `authoredEpics`. `story-implement`.

2. **An ambiguous ending increments the counter.** Draw `end-attempt-ambiguous`, which adds the counter increment between the close and the append. Its prior set is empty. Its cases carry the conversion: the stored value at `ambiguous_used >= budget` is `semantic`, and the increment still runs, because the charge is what the counter counts. `story-implement`.

3. **A settlement over a closed attempt writes nothing.** Draw `end-attempt-settled`: the two reads and the close, which returns zero rows, and no append. Its prior set is empty, and the missing `events.append` token is what proves the no-op at the seam. `story-implement`.

4. **The proposal records the command.** Amend `docs/proposal/phase-2/attempts-and-classification.md` with the command contract, the transaction rule, the settlement guard, the read order and the payload snapshot, and state that no product path calls it until EPIC 054.2. Append `"054.1"` to `shippedEpics`. It is last in dispatch order. `story-foundation`.
