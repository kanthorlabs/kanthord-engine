# EPIC 101 — Credential registry completion

Status: **blocked**. EPIC 015 of the external-drive block removes the configured `actor` binding from every handler. This epic becomes ready when EPIC 015 closes.

## Goal

The credential registry of `docs/proposal/phase-2/providers-and-credentials.md` is complete. `provider.register` stamps `set_default_at` on the first `llm` registration, inside the storage transaction that appends its event. `provider.rename`, `provider.setDefault` and `provider.remove` move from `stubbed` to `routed` in `src/http/contract/credential.ts`, with one command each under `src/commands/provider/` and one handler each under `src/http/server/credential/`. A removal is refused while a non-null `set_default_at`, a `project_binding` row of `kind = 'provider'`, a `repository.credential_id`, or an `attempt.provider_id` names the registration, and the `409 binding-in-use` details list every blocker. A register, a rename and a `setDefault` answer the public provider view of `src/domain/provider-view.ts`, a removal answers `{ id }`, a refusal answers the error envelope, and no response carries a credential field. The daemon refuses to start with no master key, with a `masterKeyFile` whose mode is not `0600`, and with a `masterKeyFile` it cannot read.

## Non-goals

- No ordered chain, no chain advance across attempts, no key rotation. The proposal defers all three past the MVP.
- No attempt-time resolution of a registration or a `provider_model`. EPIC 110 owns the attempt lifecycle and the pin. This epic reads existing `attempt.provider_id` rows only as removal blockers.
- No provider transport, and no model call. EPIC 102 owns that.
- No agent-level binding, and no `binding.provider.agents` or `binding.provider.project` route. Those rows stay `deferred` and `post-mvp` in `docs/proposal/api/`.
- No new CLI command. `src/cli/credential/register.ts` is the only credential command in phase 2, and EPIC 114 owns the onboarding sequence that calls `provider.setDefault`.
- No project-scope provider binding write path. `src/commands/project/replace-project-repositories.ts` writes `kind = 'git'` rows only, and this epic reads `kind = 'provider'` rows as a blocker.

## Stories

- **The id generator becomes monotonic** — `src/services/ids/ulid.ts` calls `ulid()`, which repeats no value but does not sort in mint order inside one millisecond. `SqliteEventLog.list` of `src/services/event/sqlite.ts` orders by `id`, and this epic is the first to append two events in one operation, so mint order must equal sort order. Build the factory once at module scope with `monotonicFactory()` of the installed `ulid` package, version `3.0.2`, and call that factory in `mint`. One factory per process serves every `IdentityKind`, because the monotonic guarantee is per factory. Change no prefix and no id format.
- **The provider view moves to `domain/`** — `ProviderView` lives in `src/commands/provider/register-provider.ts` at line 29, and a command may not import another command. Move the type to `src/domain/provider-view.ts`, which holds the `ProviderView` type and nothing else, and which imports `ProviderKind` and `ProviderProjection` from `src/domain/provider-payload.ts`. Set `projection` to `ProviderProjection | null`, because stored ciphertext can be unreadable and the strict `providerView` contract already admits `null`. `src/commands/provider/register-provider.ts` then imports `ProviderView` from there, and so do the rename and setDefault commands and handlers. The type is a type, so `domain/` stays pure. Update the imports of `src/http/server/credential/register-provider.ts` at line 5, `src/http/server/credential/register-provider.test.ts` at line 8 and `src/commands/provider/register-provider.test.ts` at line 25.
- **The first registration stamps the chain** — `src/commands/provider/register-provider.ts` currently inserts a literal `null` into `set_default_at` at line 76. For `kind = 'llm'`, read `SELECT id FROM provider WHERE kind = 'llm' LIMIT 1` inside the same transaction. When that read returns no row, insert `set_default_at` equal to the `updated_at` of the row, which is the single `clock.now()` value the command already takes. The predicate is "no `llm` registration exists", not "no stamped `llm` registration exists", because `docs/proposal/database/provider.md` stamps the **first** `llm` registration. A database that already holds unstamped `llm` rows therefore gets no stamp from any later registration, and a human stamps one row with `provider.setDefault`. Append `provider.defaultSet` after `provider.registered` in that one transaction, with `subjectKind` `provider`, `actorKind` `human` and payload `{ name, kind, setDefaultAt }`. For `kind = 'git'`, insert `null` and append `provider.registered` only, because `docs/proposal/database/provider.md` keeps the `git` chain empty. The returned `ProviderView.setDefaultAt` reports the stamped value. `docs/proposal/phase-1/domain.md` requires an event for every transition and names none of them, so this epic decides every event name and every event payload field it introduces.
- **`provider.setDefault`** — `src/commands/provider/set-default-provider.ts` exports `setDefaultProvider({ storage, crypto, clock, events }, { id, actor })`. It selects the named row with `kind`, `set_default_at`, all four encrypted payload columns and `updated_at`. It refuses an unknown id with refusal `not-found`. It refuses `kind = 'git'` with refusal `kind-not-chainable`, because `docs/proposal/api/credential.md` returns `400` for that kind. When the named row already holds a non-null `set_default_at`, it writes nothing, appends no event, and returns the unchanged view. When another `llm` row holds a non-null `set_default_at`, it refuses with refusal `default-already-set`, and names that row through `ids` only, because the MVP admits one entry until the ordered chain ships. `ids` is the machine-readable channel of `invalidRequestDetails` in `src/http/contract/error-details.ts`, and this refusal sets no `detail`. Otherwise it stamps `set_default_at` and `updated_at` with one `clock.now()` value and appends `provider.defaultSet` in the same transaction. For every success path, it opens, deserializes and projects the selected payload through `crypto.open`, `deserializePayload` and `projectPayload`; if any of those three calls throws, it returns `projection: null` without changing the state or event result. The handler is `src/http/server/credential/set-default-provider.ts`, and it parses the path parameter, calls the one command, and formats `providerView`.
- **`provider.rename`** — `src/commands/provider/rename-provider.ts` exports `renameProvider({ storage, crypto, clock, events }, { id, name, actor })`. It selects the named row with `kind`, `set_default_at`, all four encrypted payload columns and `updated_at`. It refuses an unknown id with refusal `not-found`, and a name another row holds with refusal `name-taken`, which is the refusal `RegisterProviderError` already uses. A rename to the current name writes nothing and appends no event. Otherwise it updates `name` and `updated_at` and appends `provider.renamed` with payload `{ from, to }` in the same transaction. A rename never touches `payload_ciphertext`, `payload_iv`, `payload_tag` or `key_version`. For every success path, it opens, deserializes and projects the selected payload through `crypto.open`, `deserializePayload` and `projectPayload`; if any of those three calls throws, it returns `projection: null` without changing the state or event result. The handler is `src/http/server/credential/rename-provider.ts`, and the request body is `{ name }`.
- **`provider.remove` and its blocker list** — `src/commands/provider/remove-provider.ts` exports `removeProvider({ storage, events }, { id, actor })`. It refuses an unknown id with refusal `not-found`. It collects blockers in one fixed order: `{ kind: "default-chain" }` when `set_default_at` is non-null; then one `{ kind: "project-binding", projectId }` per `project_binding` row of `kind = 'provider'` and `target_id = <id>`, ordered by `project_id` through `Buffer.compare`; then one `{ kind: "repository", repositoryId }` per `repository` row whose `credential_id` is the id, ordered by `id` through `Buffer.compare`; then one `{ kind: "attempt", attemptId }` per `attempt` row whose `provider_id` is the id, ordered by `id` through `Buffer.compare`. A non-empty list refuses the removal and reports every blocker, never the first one only. Add the attempt member to `bindingInUseDetails` in `src/http/contract/error-details.ts`; the repository and attempt blockers are mandatory because both columns are non-null foreign keys to `provider(id)`. Add the attempt blocker to the removal lists in `docs/proposal/api/credential.md`, `docs/proposal/database/provider.md` and `docs/proposal/phase-2/providers-and-credentials.md`. An empty list deletes the row and appends `provider.removed` with payload `{ name, kind }` in the same transaction.
- **The three routes become `routed`** — in `src/http/contract/credential.ts`, set `status: "routed"` on `provider.rename`, `provider.remove` and `provider.setDefault`, and give each a `request` where it takes a body, a `response` of `providerView` for rename and setDefault, a `providerRemoveResponse` of `z.strictObject({ id: z.string() })` for remove, which this epic decides because `docs/proposal/api/credential.md` declares the removal refusal only and no success body, `errors` of `baselineErrors`, and `examples` built from `EXAMPLE_ULID` and `EXAMPLE_AT`. Add `"binding-in-use": bindingInUseDetails` to the `errors` of `provider.remove` only. Set the status cell of those three rows to `routed` in the table of `docs/proposal/api/credential.md`, because `src/http/contract/parity.test.ts` compares the registry against that table. Change no path, no method and no `introducedIn`. Every other phase-2 operation stays `stubbed`.
- **Composition** — `src/main.ts` imports the three commands and the three handlers and binds them in the `handlers` map beside `provider.register`. **The actor is not a configured dependency.** `015-actor-identity.md:70` drops every `actor: settings.actor` binding, and `015-actor-identity.md:58` puts the resolved actor on `HandlerContext` of `src/http/server/app.ts`. Each handler therefore reads the authenticated actor from its handler context and passes its id as the `actor` input of the command it calls. It passes `{ storage, crypto, clock, events }` to rename and setDefault and `{ storage, events }` to remove. `unimplementedFor` in `src/http/server/app.ts` returns no provider operation afterwards, so `bindingOffenders` stays empty and the three routes no longer reach the `501` branch of `src/http/server/dispatch.ts`. `src/http/server/credential/refusals.ts` maps the new refusals: `not-found` to the `not-found` code, `binding-in-use` to `binding-in-use` with the blocker list, and every other refusal to `invalid-request` with `refusal`, `detail` and `ids`.
- **The master key startup refusal** — `src/services/config/refusals.ts` already refuses an absent key at line 21, both sources set at line 30, and a `masterKeyFile` whose mode is not `0600` at line 40. `src/services/config/convict.test.ts` at line 839 already writes a real `0644` key file, expects `config-refused`, then loads the same file at `0600`, so the mode refusal is already proven against a real file, and only `src/services/config/refusals.test.ts` asserts `assertStartable` with a mode literal. The remaining gap is the read path of `src/services/config/convict.ts`. It stats `masterKeyFile` at line 331 and reads it at line 380 in two separate calls, converts only `ENOENT` into a `ConfigError`, and rethrows every other stat failure and every read failure raw. `readTokenFile` at line 63 already stats, reads and converts `ENOENT` for the other secret file, so this epic writes one shared `openRestrictedSecretFile` descriptor helper in the same file, and both call sites use it. The helper opens the path once with `fs.openSync`, calls `fs.fstatSync` on that descriptor and returns a handle with `mode`, `read()` and `close()`. `read()` reads from that same descriptor. `ConvictConfig.load` opens every configured restricted file inside one outer `try`, passes the handle modes to `assertStartable`, calls no handle `read()` before `assertStartable` returns, and closes every opened handle in the outer `finally`. A non-`0600` mode therefore refuses before content is read, and no path is resolved again between the mode check and the read. The helper converts `ENOENT` from open, fstat or read to `ConfigError("config-invalid", ...)`, which is the current code of both call sites, and converts every other open, fstat or read failure to `ConfigError("config-refused", ...)` naming the configured path and the OS error code, for example `EISDIR` or `ELOOP`. When `fs.openSync` succeeds and `fs.fstatSync` throws, the helper closes that descriptor before it converts and rethrows the error. `close()` calls `fs.closeSync` once and is idempotent, so every successfully opened descriptor closes exactly once. No refusal message and no refusal `details` ever carries the file content or a key byte. The load-boundary assertions extend `src/services/config/convict.test.ts`, and the daemon-boundary assertion is a new `src/services/config/startup.test.ts`, which follows the pattern of `src/services/home-lock/startup.test.ts`.
- **Inherited crypto and projection regressions** — re-run the phase-1 proofs this epic depends on, and label them regressions. The tampered-ciphertext round trip is `src/services/crypto/aes-gcm.test.ts`, which already covers a flipped ciphertext byte, a flipped tag byte, a flipped iv byte, a wrong key and a foreign key version. The public projection is `src/queries/provider/list-provider.ts` and `src/queries/provider/show-provider.ts`, which name their columns and return `projection: null` for a row they cannot decrypt. This epic adds no crypto code and no query.

Hermetic coverage required beyond the Proof:

- Two ids that `UlidIdGenerator.mint` returns for the same `kind` in one fixed millisecond sort in mint order, asserted with `Buffer.compare(Buffer.from(first), Buffer.from(second))` returning `-1`. The millisecond is fixed by mocking `Date.now` to `1700000000000`.
- A first `llm` registration stores `set_default_at` equal to its own `updated_at`, and the two event rows of that provider read `["provider.registered", "provider.defaultSet"]` ordered by `id`.
- A second `llm` registration stores `set_default_at IS NULL` and appends `provider.registered` only, and so does a registration made while one unstamped `llm` row already exists.
- A `git` registration stores `set_default_at IS NULL`, whether or not any `git` row exists already.
- The stamp is atomic: an event append that throws inside the register transaction leaves a `provider` row count of `0` and an `event` row count of `0`.
- `provider.setDefault` on a `git` registration answers `400` with refusal `kind-not-chainable`, and `set_default_at` of that row is still `NULL` after the call.
- `provider.setDefault` on a second `llm` registration while another holds the stamp answers `400` with refusal `default-already-set`, `ids` equal to `[<the holder id>]`, and both `set_default_at` values unchanged.
- `provider.setDefault` on the row that already holds the stamp answers `200`, and `set_default_at`, `updated_at` and the event row count are all unchanged.
- `provider.rename` to a name another row holds answers `400` with refusal `name-taken`, and both `name` values are unchanged.
- `provider.rename` leaves `payload_ciphertext`, `payload_iv`, `payload_tag` and `key_version` byte-identical, asserted with `Buffer.compare` returning `0`, and the decrypted payload still parses to the same projection.
- `provider.rename` and `provider.setDefault` return the exact stored public projection for a readable payload. For the broken rename case, replace `payload_tag` with sixteen zero bytes before renaming. For the broken setDefault case, also set `set_default_at = NULL` before the call. Each command performs its named state and event transition and returns `projection: null`.
- `provider.remove` on a registration blocked by all four causes answers `409 binding-in-use` with `details.blockers` deep-equal to the `default-chain` entry, then the `project-binding` entries by `projectId`, then the `repository` entries by `repositoryId`, then the `attempt` entries by `attemptId`, and the `provider` row still exists.
- `provider.remove` with two `project_binding` rows of `kind = 'provider'` lists both, in `Buffer.compare` order of `project_id`.
- `provider.remove` with two `attempt` rows lists both, in `Buffer.compare` order of attempt `id`.
- A `project_binding` row of `kind = 'git'` naming the same `target_id` blocks nothing, because the git binding of a project is a repository and not a credential.
- `provider.remove` on an unblocked registration deletes exactly one row, appends `provider.removed`, and both happen in one transaction: a forced event failure leaves the `provider` row present.
- `provider.rename`, `provider.setDefault` and `provider.remove` answer through the real koa app and never `501`, and `unimplementedFor` of the composed handler map returns `[]`.
- Every success body of the four provider write routes parses against its own strict contract schema, and `Object.keys(body).sort()` is deep-equal to `["id", "kind", "name", "projection", "setDefaultAt", "updatedAt"]` for register, rename and `setDefault`, and to `["id"]` for remove. A strict schema rejects any added key, so no credential field can travel.
- The error construction path cannot receive a payload or a ciphertext, asserted by construction: `toHttpError` of `src/http/server/credential/refusals.ts` takes the thrown error only, and `Object.keys(error).sort()` of every refusal this epic throws is deep-equal to `["name", "refusal"]`, to `["ids", "name", "refusal"]` for `default-already-set`, or to `["blockers", "name", "refusal"]` for `binding-in-use`. None of the three sets holds a payload field or a ciphertext field.
- `ConvictConfig().load` with no `masterKey` and no `masterKeyFile` throws `ConfigError` with code `config-refused`.
- The real startup path refuses before it listens, in `src/services/config/startup.test.ts`: `launchDaemon` of `test/helpers/daemon.ts` on a config with no `masterKey` and no `masterKeyFile`, in its own `mktemp` home, exits non-zero, writes `config-refused` to stderr, leaves no `daemon.lock.identity` file in that home, and leaves its reserved port unbound.
- `ConvictConfig().load` with a real key file written mode `0644` in its own `mktemp` directory throws `config-refused`, and the same file at mode `0600` loads a 32-byte key.
- `ConvictConfig().load` with `masterKeyFile` naming a directory at mode `0600` throws `ConfigError` with code `config-refused` naming that path and the OS code `EISDIR`, and not a raw system error. A directory at any other mode is refused by the mode check first, so `0600` is the only case that reaches the read.
- `ConvictConfig().load` with `masterKeyFile` naming a symbolic link that points at itself throws `ConfigError` with code `config-refused` naming that path and the OS code `ELOOP`, which proves the non-`ENOENT` stat failure no longer escapes raw. An unreadable regular file at mode `0600` is not asserted, because the owner of a `0600` file can always read it, and this suite never runs as another user.
