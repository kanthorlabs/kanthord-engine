# EPIC 054.4 — The run lifecycle pays its attempt

Status: **draft**. It follows EPIC 054.3 by sequence order, and it runs before EPIC 055. It consumes EPIC 054.1's `endAttempt`, EPIC 050.1's expiry pass, EPIC 051.6's release and EPIC 050.5's startup recovery.

It carries a decimal number because EPIC 055, EPIC 056 and EPIC 057 are already numbered, and renumbering them would move every cross-reference.

**Dispatch prerequisite.** EPIC 054.3 ships before this one. Story 1 inserts `"054.4"` into `scripts/epic-sequence-range.ts:1` — `authoredEpics` after `"054.3"`, and Story 5 appends it to `shippedEpics`, which `test/sequence/conformance.test.ts:254` — `shippedEpics` requires to stay a prefix of `authoredEpics`. Story 5 is therefore last in dispatch order.

**It is the last epic of the family, and it is where the closure is provable.** Four drawn paths change, two undrawn arms change with them, and one story asserts that `execution.closeAttempt` has exactly one caller left.

## Goal

Every remaining way an attempt ends charges the class the daemon observed:

- a run expiry charges `run-expired`, which is ambiguous, and converts on an exhausted budget;
- the external sweep of the claim charges `run-expired` on the run it recovers;
- a release charges `worker-released`, which is infrastructure and advances no limit;
- a cascade close of a descendant run charges `ancestor-ended`, which is infrastructure;
- the startup recovery of an expired run charges `run-expired`, in the pass that ends the run;
- `execution.closeAttempt` has exactly one production caller left, `end-attempt`, asserted by iteration.

## Non-goals

- **No candidate discard on the expiry path.** `expireRuns` has no point after its own commit, and EPIC 051.5 carries the ended run ids out of the claim and discards there. This epic adds no git call to `expire-runs` and no `Git` to `ExpireRunsDependencies`.
- **No discard on the release, on the external sweep, on a cascade close or on the startup recovery.** `.agents/plan/epics/051.6-the-post-expiry-reap-on-the-run-operations.md:22` — `candidate.sweep` states that a run an operation itself ends is in no expiry list, is reaped by no operation, and leaves its candidate ref until startup. This epic does not widen that set, because the reap's eligibility proof is written for the expiry list alone.
- **No human cancellation.** `src/http/contract/execution.ts:222` — `run.cancel` is `stubbed`, and `.agents/plan/epics/111-inspection-and-manual-controls.md:11` — `run.cancel` gives it to EPIC 110. No production path cancels a run in this range, so no such caller exists to count and the amendment below carries the ask. The evidence kind `human-cancellation` stays in the union, because the classifier is total over it and EPIC 110 is its producer.
- **No worker switch.** `.agents/plan/epics/056-the-worker-switch.md:45` — `end-attempt` calls the command from the switch, and that epic owns the call, the arm distinction and the counter clear. That call reaches `end-attempt` rather than the seam, so it changes this epic's count of one, and the amendment below states it.
- **No accounting change.** EPIC 054 changed `accountAttempts` and the release projection. This epic writes the row that makes the projection true of the stored data.

## Decisions

- **The expiry path ends the attempt inside the caller's transaction, and this is why it discards nothing.** `src/commands/run/expire-runs.ts:25` — `expireRuns` takes the caller's transaction and is synchronous, and its only production caller runs it inside `claimNode`'s transaction — `src/commands/node/claim-node.ts:147` — `expireRuns`. It therefore has no "after the transaction commits" of its own: the transaction belongs to a command that has not finished. `endAttempt` is a database write and joins that transaction legally. **Do not make `expireRuns` asynchronous and do not give it a `Git`**; either would put git I/O inside a storage transaction.

- **An unexplained expiry is `ambiguous`, and the conversion happens inside `endAttempt`.** The budget bounds a crash loop, and the counter is node-scoped for the reason EPIC 054 states: an expiry ends the run, so a per-run counter would reset on the very event it must count. This epic passes the evidence and asserts the stored value; it re-implements no rule.

- **A release is `worker-released`, and the `attempt-limit` branch stays reachable through an earlier semantic attempt.** `src/commands/node/release-node.ts:113` — `accountAttempts` already projects `termination: "infrastructure"` from EPIC 054, and this epic writes the class on the row. The `blocked` write at `src/commands/node/release-node.ts:134` — `attempt-limit` is reached only when an earlier attempt of the same run carried a semantic termination, and the story asserts both directions.

- **The exhausted release branch is not a second diagram.** `.agents/plan/stories/050.2-the-run-renew-release-and-report/05-the-release.md:16` — `projected.exhausted` already ruled it: after the release story its token set equals the drawn one and only its outcome value differs, and a branch that changes a value and not the call set is not a diagram. `endAttempt` enters both branches as one token, so the ruling still holds.

- **The objective release arm is undrawable, and its cascade close is stated in prose with citations.** `.agents/plan/stories/050.4-the-node-lease-removal/05-the-release-drops-the-lease.md:11` — `lease.read` states why: the arm's per-child calls repeat with no projection to separate them. The cascade close at `src/commands/node/release-node.ts:262` — `closeAttempt` therefore belongs to no `Seams:` line, and Story 2's `## Change` names it with its line, exactly as that story named its own three `lease.release` sites.

- **A cascade close charges `ancestor-ended` and never the ancestor's own kind.** An ancestor expiry is `run-expired`, which is ambiguous, so propagation would charge a descendant's crash-loop budget for an event the descendant never caused. The descendant worker produced no failure and made no claim, so it pays neither an attempt nor an ambiguous budget.

- **Two of the six shipped close sites are in the external sweep, not in the startup recovery, and the closure table of the earlier draft mislabelled both.** `src/commands/startup/recover-expired-leases.ts:80` — `sweepExpiredExternalLeases` is the sweep the claim runs, `:113` — `closeAttempt` is its close of the expired run's attempt, and `:163` — `endActiveTaskRunsUnderObjective`, its only caller at `:98`, holds the cascade close at `:196` — `closeAttempt`. `recoverExpiredLeases` at `:214` — `recoverExpiredLeases` closes no attempt today; EPIC 050.5 Story 2 (`02-startup-recovery-scans-runs`) adds that close to `recovery-verdict-run`. Both paths therefore need a story, and this epic has one each.

- **The sweep's cascade close is off the drawn fixture, and it is stated in prose.** `.agents/plan/stories/050.5-the-lease-table-removal/01-the-external-sweep-scans-runs.md:21` — `Fixture` states one task, one run and one open attempt, so the descendant close at `:196` never runs on it. A second `execution.closeAttempt` on one live diagram would repeat a token the parser refuses, so the cascade stays undrawn and Story 3 names it with its line.

- **The startup recovery draws the nested per-run verdict, and the outer pass stays undrawable.** `.agents/plan/stories/050.5-the-lease-table-removal/02-startup-recovery-scans-runs.md:15` — `storage.transact` states the outer pass opens three transactions and needs a discriminator the parser refuses outside a baseline. The drawn unit is `recovery-verdict-run`. `src/commands/startup/recover-expired-leases.ts` becomes `recover-expired-runs.ts` in EPIC 050.5 Story 2 (`02-startup-recovery-scans-runs`), and every call site moves with the file.

- **The closure is a count of one, not a list in prose.** `src/services/execution/sqlite.ts:294` — `UPDATE attempt SET outcome` is the one writer of `attempt.outcome`, so the set is every caller of `execution.closeAttempt`. After this epic that set holds exactly one production file, `src/commands/attempt/end-attempt.ts`, because EPIC 054.2 and EPIC 054.3 routed the accepted arms there too. **Every close of every attempt therefore appends exactly one `attempt.ended`**, and the assertion is that iteration, so a caller a later epic adds fails the test rather than shipping with no class or no event. A prose list misses a call site, and the epic that preceded this ruling missed five and mislabelled two.

- **A future caller calls the command, not the seam.** EPIC 056's switch and EPIC 110's cancellation each end an attempt through `end-attempt`, so neither changes this count, and the amendment below states it. A literal list of callers would have failed on the commit that landed either.

- **The stored outcome names the site and never the class.** `cancelled` carries three different kinds across this epic — `worker-released`, `ancestor-ended` and `run-expired` — and each row of the closure table states which.

## Stories

Each entry is a name and the output it contributes. The story file holds the change, the tasks and the diagrams, and it declares its kind. `.agents/plan/authoring.md` is the standard.

1. **The expiry pass ends the attempt.** Call `endAttempt` with `run-expired` evidence inside the caller's transaction, and draw `expiry-pass-one-due-paid`. Add no `Git` to `ExpireRunsDependencies`. Insert `"054.4"` into `authoredEpics`. `story-implement`.

2. **The release pays no attempt.** Call `endAttempt` with `worker-released` evidence on both task branches, draw `release-reap-paid`, and change the objective arm's cascade close to `ancestor-ended` in prose with its line. `story-implement`.

3. **The external sweep pays its attempt.** Call `endAttempt` with `run-expired` evidence in `sweepExpiredExternalLeases`, draw `sweep-external-runs-paid`, and change the sweep's cascade close at `src/commands/startup/recover-expired-leases.ts:196` — `closeAttempt` to `ancestor-ended` in prose with its line. `story-implement`.

4. **The startup recovery pays its attempt.** Call `endAttempt` with `run-expired` evidence in the per-run verdict, and draw `recovery-verdict-run-paid`. `story-implement`.

5. **The closure is asserted.** Add the case that iterates every production caller of `execution.closeAttempt` and asserts the set is exactly `src/commands/attempt/end-attempt.ts`, and the case that asserts every close appends exactly one `attempt.ended`. `story-foundation`.

6. **The proposal records the lifecycle.** Amend `docs/proposal/phase-2/attempts-and-classification.md` with the closure table, the class per site, the discard ownership per path and the two future callers. Append `"054.4"` to `shippedEpics`. It is last in dispatch order. `story-foundation`.

None is applied here, and a human applies each before dispatch.

- **EPIC 110, its cancellation story** — that epic is not authored, so it carries no story stem yet, and its entry is `.agents/plan/epics/110-scheduler-leases-and-the-general-worker.md:75` — `run.cancel`.
