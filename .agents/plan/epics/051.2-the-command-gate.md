# EPIC 051.2 — The command gate

Status: **draft**. It follows EPIC 051.1 by sequence order, and it runs before EPIC 051.3. It consumes EPIC 051.1's `git.checkout`, EPIC 050.6's process capability and the re-authored EPIC 107's `Verify`.

It carries a decimal number for the reason EPIC 051 states.

**This is the one epic of the family that needs a working `Verify`, and that is why it is its own epic.** `src/services/verify/not-implemented.ts:8-13` throws today. Isolating the command gate keeps EPIC 051, EPIC 051.1 and every story of them off the EPIC 107 critical path.

## Goal

A declared command runs against an immutable checkout of the pinned commit:

- the daemon checks the pinned commit out to a fresh directory for **each** command, runs it there, and removes the directory. `git.checkout` allocates that directory and returns it, and `git.removeWorktree` disposes of it, both from EPIC 051.1;
- a command is one string, run through `["/bin/sh", "-c", <the declared string>]`, and the daemon parses nothing and asserts a zero exit;
- an empty command list reaches no seam at all;
- every outcome that is not `passed` refuses `command-failed`, naming the command index and the command string.

## Non-goals

- **No acceptance gate.** `commands.run` has no caller here. EPIC 051.4 composes it into `acceptExecution`.
- **No checkpoint, no land, no schema.** EPIC 051.3 owns migration `14`, the `checkpoint` table and the land.
- **No rule about the command text.** The daemon never inspects it, and a `!` prefix is the plan author's shell.
- **No crash sweeper for a per-command worktree.** A crash between the checkout and the removal leaks one directory, `git worktree prune --expire=now` cannot reclaim it, and `.agents/plan/epics/051.1-the-candidate-and-the-git-primitives.md` states the measurement and names EPIC 051.4 as the owner. No story here adds a sweep.

- **No refusal code for a daemon fault.** Every non-`passed` outcome refuses `command-failed`, per `## Decisions`. A seventh code separating "your command failed" from "the daemon could not run it" is a real product question, and it belongs to EPIC 051.4, which owns `src/http/contract/errors.ts`, `src/cli/exit-code.ts`, the operation's `errors` record and the regenerated field-decisions fixture, together with EPIC 054's attempt classification.

- **No `Verify` implementation.** EPIC 050.6's process capability and EPIC 107's verify service ship before this epic and are consumed unchanged.

## Decisions

- **A declared command is one string, and the daemon runs it through a shell it does not parse.** `src/domain/verify-block.ts:29` declares `commands: z.array(z.string())`, and each item is one complete command. `Verify.run` takes argv at `src/services/verify/index.ts`, so the gate builds exactly `["/bin/sh", "-c", <the declared string>]` and parses nothing. `&&` chains inside one item, and the commands of the list run in declared order, one at a time. `.agents/plan/epics/107-verify-service.md:28` already names that argv form as legal and uses it at `:64`, and `src/services/git/launcher.ts:47` already builds one.

- **Every outcome that is not `passed` refuses `command-failed`, and the mapping is total over the check contract.** `CheckOutcome` at `.agents/plan/epics/107-verify-service.md:28` is `"passed" | "failed" | "error" | "timed-out" | "cancelled"`, and the gate reads `output.result !== "passed"`. That covers all four non-passing members and every `errorReason` the same document declares — including the `error` with `errorReason` **null** that `.agents/plan/epics/107-verify-service.md:31` produces for exit `126` and `127`, which a reason-based split would leave undefined. The gate asserts passage; the mapping says only that no other outcome is passage, and it destroys no distinction, because `CheckOutput` keeps them all for whatever records the check.

  **The predicate reads `result`, never `exitCode`.** `.agents/plan/epics/107-verify-service.md:31` states that `result` is explicit and never inferred from `exit_code`, and maps an `exited` outcome with code `0` to `passed` and every other code to `failed`, so `passed` holds for exactly a zero exit — which is what the decision below names — while `exitCode` is null for every non-exit outcome.

  **A daemon fault is not translated into a throw.** EPIC 107 returns every attempted check as a `CheckOutput` and reserves its one throw for a request it refused before starting, so converting a returned `error` into an exception would be a new command-level policy — and whether such a fault is retried, and whether it consumes the worker's attempt, belongs to EPIC 051.4 and to EPIC 054. `## Non-goals` names the owner of the alternative.

- **A failure of the removal never masks the command's verdict, and the precedence is declared.** A `finally` propagates its own exception, discards the one it wrapped, and skips every statement after the block, so a refusal placed either inside or after a `finally` is masked by a `git.removeWorktree` that throws. The gate therefore gives each call its own `try` and orders three checks: a `verify.run` throw wins, because the check produced no verdict; then `command-failed`, because the command's verdict is the fact the worker asked for; then a removal failure, which surfaces only when the check passed. A cleanup fault reported as a command failure is a false statement about the worker's work, and the reverse is a lost verdict.

- **A command carries its own expectation, and the daemon asserts a zero exit.** `worker.md` section 2 states it. The daemon applies one rule to every node, and it never inspects the command text. A harness that needs an inverted expectation writes the inversion into the command it declares, and the shell of the argv form above carries it. This epic states no rule about a `!` prefix, because a rule about the command text is the rule this decision refuses.

- **Immutable means one fresh checkout per command, and the git service is what makes it fresh.** A single checkout is writable, so command one can change what command two reads. The daemon calls `git.checkout` once per declared command, runs the command in the directory that call **returns**, and calls `git.removeWorktree` on it. `worker.md` section 8 step 5 says the commands run against an immutable checkout, and a shared writable tree is not one.

  **The gate names no path.** `commands.run` is a command under `src/commands/`, and `eslint.config.js:342` bans `node:fs` there, so it can neither allocate a directory atomically nor remove one. An earlier draft of this epic said "a new `mktemp` directory" while EPIC 051.1 gave `git.checkout` a caller-supplied `targetDir`, which no legal caller could mint. Both are amended: `git.checkout` allocates with `mkdtempSync` under `GitPaths.worktreeDirectory` and returns the path, and the gate carries neither a home root nor a naming rule. A derived name such as `<runId>-<attemptNo>-<index>` was considered and refused — it is not atomically fresh, so a crash leaves the derived path occupied and `git worktree add` then refuses it, and its freshness would rest on replay and attempt-numbering invariants this epic does not own.

- **The empty list is a different path, not a shorter one.** A node with no declared command reaches no seam at all, so its diagram holds no step. `.agents/plan/authoring.md` states that a diagram with no step is legal and is the strongest statement available: any call the implementation makes fails the comparison.

- **A list of two or more commands produces identical tokens, so the fixture states a length of one.** Ordering and per-command isolation are asserted by this epic's own tests, not drawn. `.agents/plan/authoring.md` refuses a diagram that admits two traces and forbids `loop`, so unrolling a variable-length list is not available.

- **The refusal names the index and the command string.** A worker that sees only `command-failed` cannot tell which of its declared commands failed, and the daemon holds both values at the refusal point.

- **The timeout is `DEFAULT_TIMEOUT_MS`, and this epic adds no budget.** `verify.run` receives `cwd` of the per-command directory and that timeout. A per-node budget is not decided here and no story invents one.

## Sequence

This epic draws no diagram. A path is drawn by the story that changes it, under `.agents/plan/authoring.md`. `commands.run` is written from nothing, so each of its **two** diagrams stands alone with an empty prior set and no `baseline-` diagram. No path an earlier epic drew changes, so this epic supersedes nothing.

**The refusal is not drawn, and an earlier draft of this epic was wrong to name a third diagram.** `run-commands-refusal-command-failed` would have held the token set of `run-commands-success-one` in the same order, differing only in its terminal. `.agents/plan/authoring.md` refuses that four ways: draw a path only when its seam set or its seam order differs from a path already drawn; a branch that changes a value and not the call set is not a diagram; a story that inserts a refusal draws the path that still succeeds, because that is the path whose order changed; and a diagram does not prove a refusal code. Story 3 therefore draws nothing, and the refusal, its two named values, its short-circuit and the removal on the failing path are proven by that story's own cases.

### Seam keys this epic introduces

- `commands.run` — nested unit injected into `AcceptExecutionDependencies`; encapsulates the per-command checkout-and-verify loop. Its drawn paths are `run-commands-success-one` and `run-commands-success-none`.
- `git.checkout` — introduced by EPIC 051.1; this epic is its first caller, and the reason that method allocates its own directory and returns the path.
- `git.removeWorktree` — introduced by EPIC 051.1 at this epic's request; this epic is its only caller.
- `verify.run` — present in `Verify`; unlabeled. Whether the harness projects the command string as a label is Story 3's decision, and it is stated in that story rather than left open.

## Stories

Each entry is a name and the output it contributes. The story file holds the change, the tasks and the diagrams, and it declares its kind.

1. **One declared command runs.** Write the loop of `src/commands/checkpoint/run-declared-commands.ts` and draw `run-commands-success-one`. It calls `git.checkout` per declared command, calls `verify.run` with `command: ["/bin/sh", "-c", declared]`, `cwd` of the directory that checkout returned and `timeoutMs` of `DEFAULT_TIMEOUT_MS`, and calls `git.removeWorktree` on it. The fixture states a length of one. `story-implement`.

2. **No declared command runs.** Add `src/commands/checkpoint/run-declared-commands.ts` as the `commands.run` nested unit, with its full signature and a body that does nothing, and draw `run-commands-success-none`, a diagram with no step. An empty command list returns immediately, reaching no seam. **It is first in dispatch order**: it owns the module every later story edits and the epic's first scenario file, and `authoredEpics` must name this epic before a scenario file of it exists. `story-implement`.

3. **A declared command fails.** Every outcome that is not `passed` refuses `command-failed`, naming the index and the command string verbatim, and the declared precedence keeps a failing removal from masking it. **It draws nothing**, per `## Sequence`: the refusal reaches the same seams in the same order as Story 1's path, so it changes no drawn path's trace and its proofs are its cases. It also decides that `verify.run` carries no command-string projection, and states the answer rather than leaving it to build time. `story-foundation`.
