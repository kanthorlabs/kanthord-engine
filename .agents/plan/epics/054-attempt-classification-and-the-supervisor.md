## Goal

The vocabulary of a failed attempt, and every statement that stores it, are written and proven:

- `termination` is `semantic`, `infrastructure` or `ambiguous`, and only a non-accepted attempt carries one;
- the evidence of a termination is a closed discriminated union, and two total functions classify it;
- an exhausted ambiguous budget converts the class at classification time, and the stored value is what was charged;
- `accountAttempts` counts semantic terminations, so an infrastructure failure no longer advances the attempt limit;
- `caller` and `subject` are derived from authenticated state and from the run row, never from a request body;
- one statement closes an attempt and writes its termination, one event records every close, and the supervisor is a declared interface.

## Decisions

- **Version `15` is retired, and no epic claims it.** Version `13` is EPIC 051 Story 1 (`01-migration-13`), version `14` is EPIC 051.3 Story 1 (`01-migration-14`), version `17` is EPIC 055 and version `18` is `.agents/plan/epics/057-non-null-enforcement-and-legacy-removal.md:63` — `migration-0018-enforce.ts`. Nothing in the plan tree declares `15`. `src/services/storage/sqlite.ts:181` — `validateMigrations` admits the gap, so this epic keeps `16` rather than renumbering — a renumber would only move the gap to `16` and would move four citations. **An epic that later claims `15` is a defect**, because it would apply after `16` on an upgraded database and before `16` on a fresh one, which is the reorder this epic's own next Decision refuses.

- **Migration `16` is additive, it backfills nothing, and it holds four columns.** `attempt.termination`, `attempt.caller`, `attempt.subject` and `node.ambiguous_used` are added nullable, by one migration at version `16`, registered at `src/services/storage/migrations.ts:15` — `migrations`. A historical row keeps a null caller and a null subject, because inventing one would manufacture audit evidence for an attempt nobody observed. EPIC 057 enforces them.

- **The migration and every statement that writes its columns are one epic, and that is why this epic is ten stories.** `.agents/plan/authoring.md:49` — `writes its changed columns` is unconditional. The writers are three: the close statement at `src/services/execution/sqlite.ts:294` — `UPDATE attempt SET outcome`, the counter update this epic adds to `src/services/plan/sqlite.ts`, and the open insert at `src/services/execution/sqlite.ts:252` — `openAttempt`. All three are service statements, and a service implementation draws nothing, so they fit beside the migration without a diagram. Splitting them out would take a migration version out of ship order: `src/services/storage/sqlite.ts:181` — `validateMigrations` admits any unique positive version, so a lower version added after a higher one applies in a different order on an upgraded database than on a fresh one.

- **Only a non-accepted attempt carries a termination, and the CHECK states it in one direction.** "Failed" is loose: a release ends the attempt `cancelled` and this epic calls it no failure, so the predicate is `outcome <> 'accepted'` and the prose says so. Migration `16` adds `CHECK (termination IS NULL OR termination IN ('semantic', 'infrastructure', 'ambiguous'))` and `CHECK (termination IS NULL OR (outcome IS NOT NULL AND outcome <> 'accepted'))`. **The second is not `outcome <> 'accepted' OR termination IS NULL`**: with `outcome` null that expression evaluates to SQL `NULL`, and SQLite admits a row whose CHECK is not false, so an **open** attempt could carry a termination. The stated form refuses that row and refuses an `accepted` attempt with a termination, and it admits a `cancelled` attempt with none.

- **The converse CHECK is a conditional non-null, and EPIC 057 owns it.** `CHECK (outcome IS NULL OR outcome = 'accepted' OR termination IS NOT NULL)` invalidates five shipped call sites on the commit that lands it: `src/commands/node/release-node.ts:124` — `closeAttempt`, `src/commands/node/release-node.ts:166` — `closeAttempt`, `src/commands/node/release-node.ts:262` — `closeAttempt`, `src/commands/startup/recover-expired-leases.ts:113` — `closeAttempt` and `src/commands/startup/recover-expired-leases.ts:196` — `closeAttempt`, all five of which write `outcome: "cancelled"`. The wiring of those five is EPIC 054.4, so the CHECK cannot land here, and the amendment below carries the ask.

- **The close writes the outcome and the termination in one statement, and no second writer exists.** `src/services/execution/index.ts:75` — `CloseAttemptInput` gains `termination`, and the conditional statement at `src/services/execution/sqlite.ts:294` — `UPDATE attempt SET outcome` writes both. **A separate `setAttemptTermination` was rejected**: it would make one logical close two writes, it would make the converse CHECK momentarily relevant inside the transaction, and it would break the closure this family depends on — `src/services/execution/sqlite.ts:294` — `UPDATE attempt SET outcome` is the one writer of `attempt.outcome`, and the closure of EPIC 054.4 is measured over its callers.

- **The close already wins the first-writer race, and the conditional settlement needs no new mechanism.** The statement carries `WHERE id = ? AND outcome IS NULL` and `RETURNING`, so a close over an attempt another operation already closed returns zero rows. That zero-row result is the signal EPIC 054.1 turns into a no-op settlement.

- **Termination evidence is a closed discriminated union, not a bag of booleans.** `src/domain/termination.ts` defines `TerminationEvidence` as a union with one `kind` per case, so two conflicting facts cannot be supplied at once and no precedence rule has to be invented:

  | `kind`                    | driver   | class            |
  | ------------------------- | -------- | ---------------- |
  | `daemon-rejected`         | both     | `semantic`       |
  | `worker-reported-failure` | both     | `semantic`       |
  | `operator-handoff`        | both     | `infrastructure` |
  | `provider-quota`          | internal | `infrastructure` |
  | `contended`               | both     | `infrastructure` |
  | `human-cancellation`      | external | `infrastructure` |
  | `worker-released`         | both     | `infrastructure` |
  | `ancestor-ended`          | both     | `infrastructure` |
  | `run-expired`             | both     | `ambiguous`      |
  | `process-exit`            | internal | `ambiguous`      |

  `provider-quota` carries `{ providerId, responseHash }`, a value the provider transport produces from a signed response. A boolean would be a flag any caller could set. `ancestor-ended` carries `{ ancestorRunId }`, the run whose ending closed this attempt.

- **`worker-released` keeps the driver `both`, and this answers EPIC 055's ask.** `src/http/contract/capability.ts:10` — `node.release` puts the release in the worker capability set, so an external harness reaches it under actor authentication today. EPIC 055 restricts a **grant** caller and not an actor caller, so the external producer of `worker-released` is the external run's own release. The ask at `.agents/plan/epics/055-the-grant-and-the-external-client.md:105` — `worker-released` is answered by this value, and a human deletes that bullet from EPIC 055.

- **A voluntary release is `worker-released`, and it is `infrastructure`.** The human ruling of 2026-09-03 settles it. A worker that returns its claim reports no failure of the work, so it pays no attempt. `operator-handoff` was rejected as the carrier: a release is the worker's own act, and one kind for both would make an audit unable to separate them.

- **A cascade close is `ancestor-ended`, and it is `infrastructure`.** `src/commands/node/release-node.ts:262` — `closeAttempt` and `src/commands/startup/recover-expired-leases.ts:196` — `closeAttempt` close the open attempt of a **descendant** run while the command ends its ancestor. The descendant worker produced no failure and made no claim, so it pays neither an attempt nor an ambiguous budget. Propagating the ancestor's own kind was rejected: an ancestor expiry is `run-expired`, which is `ambiguous`, so propagation would charge a descendant's crash-loop budget for an event the descendant never caused.

- **`run-expired` keeps the driver `both`, because the daemon's own clock produces it for either driver.** `src/services/execution/sqlite.ts:146` — `WHERE state = 'active' AND expires_at <= ?` carries no driver predicate, so `expireRuns` ends an `internal` run and an `external` run alike, and the startup recovery of EPIC 054.4 Story 4 (`04-the-startup-recovery-pays-its-attempt`) charges it over `src/commands/startup/recover-expired-leases.ts:229` — `internalRows`, which is an internal-only set. An `external`-only value would leave both paths with no legal evidence. **`process-exit` is not the internal substitute**: it names a termination the supervisor observed, and an expiry is precisely the case where the daemon observed nothing, which is what makes it `ambiguous`. The two kinds are therefore not alternatives, and `process-exit` stays `internal`.

- **The classifier is two total functions over two evidence types.** `classifyInternal(evidence: InternalEvidence)` and `classifyExternal(evidence: ExternalEvidence)`, where the two types are overlapping subsets of the union above — seven kinds are in both. `../docs/workflow/worker.md` section 9 states the two sources, and one function with a driver parameter would let an external value reach an internal rule.

- **The trust boundary is the transport schema, not a type signature.** A TypeScript signature is erased at runtime. `node.report` is a `z.strictObject` with no `termination` key and no `caller` key, so an unknown key is refused rather than stripped. An external termination is constructed by the daemon from its own facts.

- **A worker's own claim of quota exhaustion is `worker-reported-failure`.** `../docs/workflow/worker.md` section 9 states a worker's claim is evidence, never a verdict. Only `provider-quota`, whose `responseHash` names a response the daemon's own transport received, classifies `infrastructure`.

- **Contention is `infrastructure`, and this is a decision taken here.** Section 9 lists an operator handoff and a provider-signed quota response as infrastructure sources, and section 8 states contention consumes no attempt and is not a worker failure. The source list is read as non-exhaustive, and contention takes the class whose budget effect the document already assigns it. A fourth class would carry no different behaviour.

- **The ambiguous budget belongs to the node, not to the run, because a crash loop opens a new run each time.** An unexplained expiry ends the run, so a per-run counter resets on the very event it must count. Migration `16` adds `node.ambiguous_used INTEGER`, nullable. `ambiguousBudget` is configuration, not a column.

- **The counter is a node write, so its statement lives in the plan store alone.** `eslint.config.js:9` — `nodeEdgeWritePattern` refuses an `UPDATE node` outside the files of `eslint.config.js:18` — `src/services/plan/sqlite.ts`, so the read and the increment join the plan service. The statement is `UPDATE node SET ambiguous_used = COALESCE(ambiguous_used, 0) + 1 WHERE id = ?`, with `COALESCE` because the column is nullable and a historical node holds null. The read applies the same default, so a null counter and a zero counter classify identically.

- **The increment carries no compare and set, because one transaction cannot lose the race.** The read and the update are in one write transaction and SQLite admits one writer at a time, so a zero-row result is unreachable and the restart it would guard is dead logic. Two attempts of one node cannot be open at once — `src/commands/node/release-node.ts:103` — `openAttempts` throws on more than one open attempt of a run.

- **The counter resets when the assignment changes, and at nothing else.** A worker switch of EPIC 056 clears `ambiguous_used`, because the budget bounds one worker's crash loop and a new worker starts clean. `node.unblock` does not clear it.

- **The boundary is `>=`, and the conversion is stated for three values.** With `ambiguousBudget = n`: an ambiguous termination is stored `ambiguous` while `ambiguous_used < n`, and stored `semantic` once `ambiguous_used >= n`. `ambiguousBudget = 0` therefore converts the first ambiguous termination. It defaults to 2, refuses a negative value at startup, and refuses a non-integer, beside `src/services/config/index.ts:34` — `attemptLimit`.

- **`attemptsRemaining` counts what the limit counts, so it is `attemptLimit - semanticCount`.** `src/commands/outcome/report-outcome.ts:255` — `accounting.counter` is the highest attempt **number**, and once `exhausted` reads `semanticCount` the two disagree: three infrastructure failures under a limit of three would answer `attemptsRemaining: 0` while the daemon kept granting attempts. **Two published observables move**: the `node.report` response at `src/http/contract/outcome.ts:62` — `attemptsRemaining` and the `outcome.reported` payload at `src/http/contract/event-payload.ts:168` — `attemptsRemaining`, which reuse the one value. Neither schema changes type, and `test/helpers/sequence-conformance.ts:72` — `events.append` projects `type`, `subjectId` and `payload.reason` and never this field, so no drawn token moves. Story 7 owns the change and gate row 18a owns the proof.

- **The conversion is applied at classification time, and the stored value is what was charged.** A conversion applied at read time would leave the row and the accounting disagreeing.

- **`accountAttempts` counts semantic terminations, and the limit stops reading the raw counter.** `src/domain/attempt-accounting.ts:3` — `AttemptRecord` gains `termination`, and `src/domain/attempt-accounting.ts:32` — `accountAttempts` returns `semanticCount`, `ambiguousCount` and an `exhausted` that is `semanticCount >= limit`. This is a behaviour change to shipped code, and the shipped cases are updated rather than kept.

- **A required field lands with all eight construction sites of its type.** `.agents/plan/authoring.md:49` — `every site that constructs the type` binds them. They are `src/domain/attempt-accounting.ts:3` — `AttemptRecord`, `src/services/execution/index.ts:28` — `AttemptRecord`, `src/services/execution/sqlite.ts:80` — `toAttemptRecord`, the literal returned by `src/services/execution/sqlite.ts:252` — `openAttempt`, the accounting call at `src/services/execution/sqlite.ts:266` — `accountAttempts`, the projection at `src/commands/node/release-node.ts:113` — `accountAttempts`, the accounting call at `src/commands/outcome/report-outcome.ts:241` — `accountAttempts`, and the two fakes at `test/helpers/execution.ts:191` — `toAttemptRecord` and `test/helpers/execution.ts:403` — `openAttempt`.

- **A null termination is not a semantic one, and a legacy row therefore prices at zero.** Migration `16` backfills nothing, so every attempt closed before it holds a null termination, and `semanticCount` counts none of them. **A live run's earlier failures are forgiven at the upgrade, and its attempt limit restarts.** The alternative is a backfill, and a backfill would assign a class the daemon never observed to an attempt nobody classified. The epic states the effect rather than hiding it, and one case asserts it by value.

- **A release no longer advances the attempt limit, and the `attempt-limit` branch stays reachable.** The projection at `src/commands/node/release-node.ts:113` — `accountAttempts` carries `termination: "infrastructure"`, so a run whose attempts are all releases never exhausts its limit, and the `blocked` write at `src/commands/node/release-node.ts:134` — `attempt-limit` is reached only when an earlier attempt of the same run carried a semantic termination. The projection changes no seam call, so no diagram of `release-node` moves here; EPIC 054.4 wires the row that stores the class.

- **`caller` and `subject` are derived, never received.** `src/services/execution/index.ts:73` — `OpenAttemptInput` gains both. `subject` is `run.worker`, read from the run row. `caller` is the authenticated principal the middleware resolved: today the actor id, from EPIC 055 the grant id, from EPIC 110 the supervisor id. The one shipped attempt-opening writer is `src/commands/node/claim-node.ts:403` — `openAttempt`, and it passes both. Section 10 separates authorization from attribution, and the test asserts the derivation site, not an inequality.

- **No row is backfilled, and `checkpoint.caller` and `checkpoint.subject` follow the same derivation from this epic on.** `.agents/plan/epics/051.3-the-checkpoint-and-the-land.md:29` — `caller` created both columns nullable and named this epic as their filler, and EPIC 053.1 asked which of a backfill or a null this epic rules. The ruling: **nothing is backfilled, ever.** EPIC 054.3 derives both at every checkpoint writer it touches, because those writers are on the paths it changes.

- **`attempt.ended` is the one event of an ended attempt, it covers every outcome, and EPIC 054.1 Story 1 (`01-a-semantic-ending-and-an-accepted-one`) registers it.** This epic decides the type, the subject and the payload; it adds neither the `src/domain/event-type.ts:1` — `eventTypes` entry nor the `src/http/contract/event-payload.ts` variant, because `src/http/contract/event-payload.test.ts:430` — `every declared type except the retired ones is produced` scans `src/commands` and `src/services` for the type literal and this epic ships no producer. Registering it here lands a red `pnpm run verify` between this epic and the next. **The registration therefore lands in the same story as the producer**, together with the two catalogue counts pinned at `39` — `src/http/contract/openapi-source.test.ts:363` and `scripts/publish-contract.source.test.ts:217`. Every close of every attempt appends exactly one. `subjectKind` is `"attempt"` and `subjectId` is the attempt id: `src/domain/event.ts:11` — `subjectKind` is a free string, and a run subject is provably wrong, because one cascade close ends the attempts of several runs in one transaction.

- **The payload is a two-member union keyed on the outcome, and both members carry the close-time accounting snapshot.** The common members are `{ attemptId, runId, nodeId, attemptNo, outcome, semanticCountAfter, attemptLimit, ambiguousUsedAfter, ambiguousBudget }`. The **accepted** member adds `headOid` and carries no `termination` and no `evidence`. The **non-accepted** member, over `rejected`, `failed`, `timed-out` and `cancelled`, adds `termination` and `evidence` and carries no `headOid`. One variant joins `src/http/contract/event-payload.ts`. The four counters make the payload the close-time accounting snapshot, which is the only durable record of them: `node.ambiguous_used` resets on an assignment change, a converted ambiguous termination is stored `semantic`, and `attempt.termination` is null on every row the migration left unclassified.

- **No member carries a top-level `reason`, and this is a harness constraint, not a style.** `test/helpers/sequence-conformance.ts:81` — `reason` appends `payload.reason` to the compared token of `events.append`, so a top-level reason would put a value inside the seam token and split one drawn path per reason. EPIC 110's frozen `attemptFailureReasons` — `.agents/plan/epics/110-scheduler-leases-and-the-general-worker.md:135` — `attemptFailureReasons`, eight values — therefore lands **inside** the `worker-reported-failure` member of the evidence union when that epic ships, and `invocationId` joins the payload with the invocations that produce it.

- **One type, and not one per outcome.** Two arguments, and the first is mechanical: `test/helpers/sequence-conformance.ts:72` — `events.append` projects `input.type`, so `attempt.rejected` and `attempt.cancelled` would be two tokens, two seam sets and two diagrams, and EPIC 054.1's three drawn paths would multiply by the four non-accepted outcomes. The second is that the outcome is already a payload member here, so a type per outcome would name in the type what the record states in the row. **`.agents/plan/epics/110-scheduler-leases-and-the-general-worker.md:53` — `attempt.failed` declares four close types** — `attempt.failed`, `attempt.cancelled`, `attempt.rejected` and `attempt.accepted` — and all four are one `attempt.ended`. The amendment below carries that ask, and it keeps `attempt.started`, which this family does not emit.

- **An acceptance is an ending, so it appends the event too.** A vocabulary whose `attempt.ended` excluded the commonest ending would make `type=attempt.ended` an unusable filter of `src/http/contract/event.ts:14` — `type`, and would leave two generations of accepted attempts with different event behaviour. EPIC 054.2 and EPIC 054.3 therefore route their accepted arms through `end-attempt` as well, and each supersedes the diagram of the arm it changes.

- **A supervisor is a declared interface with a `not-implemented` implementation, and `launch` spawns a process.** Section 10 states that the worker runs as a separate process, that the supervisor spawns it and owns its process tree, and that a later worker runs on another machine. `src/services/supervisor/index.ts` declares `launch`, `observe` and `classify`, where `observe` returns an `InternalEvidence`. The interface therefore admits a remote worker without a signature change. `src/services/supervisor/not-implemented.ts` throws, mirroring `src/services/agent/not-implemented.ts:8` — `NotImplementedAgent`. **EPIC 110's in-process dispatcher is the design that has to move**, and the amendment below carries that ask; without it this interface has no consumer.
