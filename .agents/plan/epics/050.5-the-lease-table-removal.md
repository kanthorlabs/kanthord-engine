# EPIC 050.5 — The lease table removal

Status: **draft**. It follows EPIC 050.4 by sequence order, and it runs before EPIC 051.

EPIC 050.4 took the node lease out of the four worker operations and off the wire. This epic deletes
what remains that is code: the two recovery readers, the revocation pass, the status projection, the
plan store's lease facts, the domain hierarchy and the service. **It drops no table.** EPIC 057's
migration `18` already owns the lease rows, and it drops the table there.

It carries a decimal number because EPIC 051 through EPIC 057 are authored and numbered, and
renumbering them to insert a whole-number epic would break every cross-reference between them.

## Goal

- `recover-expired-leases.ts` scans runs where it scanned node leases, and `revoke-actor.ts` stops fencing leases;
- `leaseHeld`, `ContainmentFacts.lease` and the `lease` member of `executionBlockers` are gone from the plan store;
- `src/domain/lease-hierarchy.ts` and `src/services/lease/**` are deleted whole;
- `system.status` stops projecting the lease table, and `readStatus` stops scanning it;
- the `lease` table survives, empty, with no writer and no reader, until EPIC 057's migration `18`;
- one response field leaves `system.status`, and nothing else on the wire moves: EPIC 050.4 took every worker field, the error code and the capability, and `blocker` is `z.string()` at `src/http/contract/error-details.ts:36`, so dropping the `lease` blocker changes no schema.

## Non-goals

- **No worker-operation change.** EPIC 050.4 owns all four, and after it none of them names the lease.
- **No checkpoint and no workspace.** EPIC 051 owns both.
- **No `git_operation.lease_fence` change.** It is the external-drive precondition mode of `src/domain/external-transition.ts`, not a `Lease` service row.
- **No worker-operation wire change.** EPIC 050.4 took all of it.
- **No migration.** EPIC 057's migration `18` already deletes the `subject_kind = 'node'` rows and narrows the CHECK; this epic asks that it drop the table instead, which is a one-line amendment to an epic that already owns them.
- **No `src/domain/lease.ts` change and no `rows.lease` change.** Both are load-bearing for schema parity while the table exists.

## Decisions

- **The table is dropped rather than narrowed, and EPIC 057 is where it happens.** `lease.acquire` has one production caller and it passes `subjectKind: "node"`; the only production `INSERT INTO lease` is inside the service; and no `src/commands/repository/**` file touches the `Lease` service. After EPIC 050.4 the table has zero writers, so narrowing it to `subject_kind = 'repository'` would keep a table for a subject nothing acquires. **EPIC 057's Story 6 already writes migration `18` to delete the `subject_kind = 'node'` rows and narrow the CHECK** — `.agents/plan/epics/057-non-null-enforcement-and-legacy-removal.md:63` — `Migration 18`; the amendment this epic asks for is that it do `DROP TABLE lease` instead, and delete `src/domain/lease.ts` and `rows.lease` in the same edit.

- **This epic adds no migration, because every version it could take is allocated or deliberately vacant.** `12` is EPIC 050.1's, `13` is EPIC 051's `workspace_branch` table, `14` is EPIC 051.3's `checkpoint` table, `16` is EPIC 054's, `17` is EPIC 055's and `18` is EPIC 057's. **`15` is vacant and stays vacant**: it held the close-provenance columns of a draft, no epic builds them, and `src/services/storage/sqlite.ts:181` — `validateMigrations` requires unique positive versions and no contiguity, so the gap is legal and no authored migration renumbers. Taking `13` here would renumber six authored epics and their tests, and it would leave EPIC 057's migration `18` invalid: that migration's preflight refuses on a live node lease, its body narrows the lease CHECK, and its gate asserts every surviving `lease` column is present afterwards — none of which a dropped table can satisfy. Deferring the drop to the epic that already owns those rows costs one amended sentence and no renumbering.

- **The table therefore survives this epic, empty and unreachable, and that interval is deliberate.** It is the same shape EPIC 050.3 used when it left `ContainmentFacts.lease` unread for one epic: the mechanism dies where its code dies, and the schema follows in the epic that owns the schema. `src/domain/lease.ts` and `src/domain/rows.ts:33` survive with it, because `src/services/storage/schema-parity.test.ts:90` asserts the migrated table set equals `Object.keys(rows)` and the two must move together.

- **`recover-expired-leases.ts` holds two exports and both change.** `sweepExpiredExternalLeases` at `:79` is injected into `node.claim` (`main.ts:553`), `node.list` (`:515`) and `project.nodes` (`:634`), so the file's blast radius is three paths. `recoverExpiredLeases` at `:213` is `async` and opens three separate transactions — `:218`, `:231` and `:328` — around git worktree reads. **The recovery is not atomic today and this epic does not make it so**: its per-node verdict is written in its own transaction at `:328`, which is what lets one unreadable workspace block one node without failing the pass.

- **The outer recovery pass cannot be drawn, and this epic says so rather than pretending.** It has three `storage.transact` call sites, and at run time it opens `1 + (externalRows ? 1 : 0) + internalRows.length` transactions. `storage.transact` has no projection in the harness of EPIC 050.1 Story 6, and a method with no projection admits one call per diagram, so any run with a candidate needs `:#2`, which the parser refuses outside a `baseline-` id. The cause cannot be removed: the git worktree reads at `:277-281` must sit outside a transaction, which `AGENTS.md` requires. Story 2 therefore draws the pair for the **per-node verdict write**, which it promotes to a nested command **injected on the outer pass's dependencies record** — injection is what collapses it to one token, because the recorder wraps the object a command receives and a directly called helper's seam calls are recorded as the caller's own. **A human rules on whether the harness gains a `storage.transact` projection**; nothing in this epic depends on the answer.

- **The recovery step vocabulary is not renamed, because renaming it is a seam change no diagram can measure.** `RECOVERY_STEP_ORDER`'s `leases` step, `LeasesStep`, `LeasesResultLike` and `RecoverHomeDependencies.leases` keep their names. `src/commands/startup/recover-home.ts:22` calls `dependencies.leases()`, a function-valued dependency whose token is `leases.call`; renaming the key makes it `runs.call`, and `recoverHome` has four such dependencies so it has no live diagram and can have none. The two event types and the two target enums **are** renamed, because they are values and not seams.

- **Neither reader takes `expireRuns`.** The draft of this epic said startup recovery would call it. It must not: recovery reads its candidate set as **active** runs past their expiry, and a pass that ended them first would leave the external sweep at `:231` nothing to find. Each reader therefore ends the run it handles through `execution.endRun`, exactly as `sweepExpiredExternalLeases` already ends one at `:118`, and the fence rises there. `expireRuns` stays what EPIC 050 made it: the pass every run operation calls first.

- **The two recovery event types are renamed with the mechanism.** `recovery.leaseRecovered` and `recovery.leaseBlocked` become `recovery.runRecovered` and `recovery.runBlocked`, and `leaseSweepTargets` and `leaseVerdictTargets` at `src/domain/recovery.ts:27-29` become `runSweepTargets` and `runVerdictTargets`. `eventView.type` is `z.string()` at `src/http/contract/event.ts:26`, so the catalogue is not wire-constrained. `RecoveryReport` reaches only `process.stderr` at `main.ts:347`, so none of it is on the wire either.

- **`actor.revoked` has a strict payload, and `leasesFenced` leaves it.** `src/http/contract/event-payload.ts:78-85` declares the field as required. The emitted response shape does not change — `eventView.payload` is `z.unknown()` — but the internal validation contract does, and a field the command stops producing would refuse every append. Story 3 removes it deterministically.

- **Both emit sites of `recovery.leaseRecovered` live in one file, so one story renames the types.** The sweep appends it at `:142` and the verdict write appends it at `:343`. `eventPayloads` is typed `Readonly<Record<EventType, ZodType>>`, so a type removed without its payload fails to compile and a payload left without its type fails too. Story 1 therefore renames both types, both payload aliases and **both** emit sites in the file it already edits; Story 2 changes the verdict's inputs and its run write, not the event name.

- **The git verdict survives the rewrite, and its base comes from `run_base`.** `recoverExpiredLeases` decides `ready` against `blocked` by `clean && head === row.base_oid` at `:301`, and writes `dirty-recovery` when it fails. Migration `12` **drops `run.base_oid`**, so the rewritten candidate query reads `run_base.oid`, the table EPIC 050 Story 2 creates. Replacing the lease scan with a run scan changes which nodes are candidates; it does not change what the daemon concludes about a workspace. A rewrite that returned every node to `ready` would requeue a task on top of an uncommitted worktree.

- **Between EPIC 050 and EPIC 051 no run has a base, and the shipped code already handles that.** EPIC 050 creates the `run_base` table and states that EPIC 051 writes the row. A candidate with no base row therefore takes the shipped branch at `:258` — `row.path === null || row.base_oid === null` — which blocks the node and records `recovery-inputs-missing`. That is the correct verdict for a run whose base is unknown, so this epic can land before EPIC 051 without weakening the recovery. After EPIC 051 the same query finds a base and the clean-worktree verdict applies.

- **`revoke-actor` loses its lease pass and gains nothing, because there is no actor-to-run relation.** `lease.expireLeasesOfOwner` at `:100` filters on `owner` alone, with no `subject_kind` clause, so after migration `18` it has no table to read. It cannot be replaced by "end every run this actor drives": EPIC 050's Decisions state that the claiming worker comes from a server-owned caller record, _"never from `actorId` and never from the request body"_, so `run.worker` is a worker id and no column relates a run to the actor that claimed it. The call is therefore deleted outright and `leasesFenced` leaves the `actor.revoked` payload — `eventView.payload` is `z.unknown()` on the wire, so the removal costs no schema.

  **What still stops a revoked actor is stated rather than assumed.** Authentication refuses its next request, so it opens no new run and renews no existing one, and the run it held expires on `runTtlMs` and is swept by the next `expireRuns` pass. The interval between revocation and expiry is bounded by `runTtlMs` and it is a **deliberate, stated regression** against the shipped lease fencing, which was immediate. An immediate equivalent needs a run-to-grant relation, and EPIC 055 is where a grant lands. This epic records the gap; it does not invent a column to close it.

- **`system.status` loses its lease projection here, and the removal is an implement story.** `src/queries/system/read-status.ts:79` reads `dependencies.clock.now()` **inside** the lease query, and it is that query's only clock read, so deleting the projection moves the query's seam trace. Its `health` dependency is function-valued, so a baseline of that path holds
  `health.call` — legal in a baseline, refused in a live diagram — and the story that draws the pair removes the cause by injecting the **computed value**: `ReadStatusDependencies.health` becomes `HealthResult`, `:50` becomes a field read, and `src/main.ts:398` becomes `health: readHealth(healthDependencies)`. **No service capability is opened and `src/domain/layout.test.ts` does not move.** An earlier draft opened `src/services/health/index.ts` as a twenty-second capability; that was wrong on its premise, because `main.ts` binds `health` to `readHealth`, a **query** at `src/queries/system/read-health.ts:28`, so a `services/` interface would declare a capability whose only producer lives in `queries/`. The value injection is legal because nothing is deferred: `main.ts` builds the dependencies inside the per-request `readStatus` closure, `readHealth` takes `reporters`, `version` and `capabilities` and no `storage` and no `clock`, and `readStatus` reads `health` unconditionally at `:50` before `storage.transact` at `:54`. The ship diagram therefore loses the step rather than renaming it, and the `Health` participant leaves with it. The `clock` dependency leaves with the query it served.

  **The removal has no covering capability, and Story 8 closes it.** `system.status` belongs to no entry of
  `capabilityOperations` (`src/http/contract/capability.ts:5-15`), so there is no name to retire as the
  announcement the amendment requires — and a capability would not repair this direction in any case:
  it lets a newer client detect an older daemon, while this removal breaks an older client against a
  newer daemon. **A human ruled the removal**, on the standing constraint that the product carries no
  backward-compatible obligation and has no deployment. Story 8 therefore **amends**
  `docs/proposal/api/README.md` with one clause admitting an operation that no capability covers,
  moves `KANTHORD_VERSION` to `30.0.0`, and writes the compatibility row with both capability cells
  reading the literal `none`. A deprecated `leases: []` left on the wire is refused: it is a
  compatibility shim, and the constraint exists to avoid one.

- **`Lease.expired()` has no production caller** — `grep -rn '\.expired(' src/` returns test files only — so it is deleted with the interface and no command loses a call.

- **`recovery.leaseRecovered` and `recovery.leaseBlocked` are replaced, not retired quietly.** `eventView.type` is `z.string()` at `src/http/contract/event.ts:26`, so the catalogue is not wire-constrained and the swap costs no capability. `retiredEventTypes` stays empty: there are no deployments and no stored event to keep readable.

## Stories

Each entry is a name and the output it contributes. The story file holds the change, the tasks and
the diagrams, and it declares its kind. A `story-foundation` draws nothing; a `story-implement` draws
one pair. `.agents/plan/authoring.md` is the standard.

0. **groundwork.** `eslint.config.js`'s node-and-edge write exemption gains the renamed recovery test, and `package.json`'s `version` moves to `30.0.0`. The two paths this epic edits that `scripts/lane-check.sh` denies to both engineers. `story-foundation`, `Executor: groundwork-engineer`, `Paths: eslint.config.js package.json`, and it runs before the loop.

1. **The external sweep scans runs.** `sweepExpiredExternalLeases` becomes `sweepExpiredExternalRuns`, its candidate query reads `run` instead of `lease`, its unused `lease` dependency key goes, and the two recovery event types are renamed at both emit sites. One pair, and three call sites to re-verify.

2. **Startup recovery scans runs.** `recover-expired-leases.ts` becomes `recover-expired-runs.ts`; the per-node verdict write becomes an injected nested command that ends the run and closes its open attempt. One pair, on the verdict write.

3. **`revoke-actor` drops its lease pass.** `lease.expireLeasesOfOwner` deleted with no replacement, and `leasesFenced` deleted from the `actor.revoked` payload schema. One pair.

4. **`system.status` drops the lease projection.** `leases[]` leaves the response, `readStatus` loses its lease scan and its `clock` dependency, and `health` becomes the `HealthResult` value so the ship diagram holds no `.call` token and no `Health` participant. One pair.

5. **The plan store stops computing the lease facts.** `leaseHeld`, `ContainmentFacts.lease` and the `lease` member of `executionBlockers`, which keeps its other six. `story-foundation`.

6. **The lease service is deleted.** `src/services/lease/**`, its construction in `main.ts`, `LeaseError` with it, `test/helpers/lease.ts` and the five importers no earlier story repairs, and the two `src/domain/layout.test.ts` inventories. `story-foundation`.

7. **The lease hierarchy is deleted.** `src/domain/lease-hierarchy.ts` whole, orphaned by Story 6 and by EPIC 050.4 Story 8. `src/domain/lease.ts` survives. `story-foundation`.

8. **The proposal records the removal.** Seven documents amended, `KANTHORD_VERSION` to `30.0.0`, one compatibility-record row, and the tree assertion. `story-foundation`.
