# EPIC 050.4 — The node lease removal

Status: **draft**. It follows EPIC 050.3 by sequence order, and it runs before EPIC 050.5 and EPIC 051. It consumes EPIC 050's run and fence, EPIC 050.2's authority check and EPIC 050.3's plan-write guard.

It carries a decimal number because EPIC 051 through EPIC 057 are authored and numbered, and renumbering them to insert a whole-number epic would break every cross-reference between them.

The node lease leaves the four worker operations and the worker wire. EPIC 050.5 then deletes the table, the service and the two recovery readers.

## Goal

The four worker operations hold one exclusion mechanism, and it is the run:

- `node.claim`, `node.renew`, `node.release` and `node.report` acquire, renew, release and assert no node lease;
- the node-lease fields leave the worker wire — the two `claimedLease` response objects, `objectiveRunId`, the node-lease `fence` on three requests, and the `lease-held` error code with its details schema;
- `worker-model` is retired and `worker-run` is declared, which is how a client learns the shape moved.

After this epic the only production callers of the `Lease` service are `revoke-actor.ts` and `recover-expired-leases.ts`. EPIC 050.5 deletes those, the table and the service.

## Non-goals

- **No table removal and no migration.** The `lease` table, `src/services/lease/**` and `src/domain/lease-hierarchy.ts` survive this epic with their node rows in place. EPIC 050.5 owns the migration and the deletion, and it lands only after every writer is gone.
- **No startup-recovery change and no revocation change.** `recover-expired-leases.ts`, `sweepExpiredExternalLeases` and `revoke-actor.ts` keep reading node leases here. EPIC 050.5 owns all three.
- **No `system.status` change.** The table still exists after this epic and still holds rows, so the `leases[]` projection is truthful. Removing it also moves that query's seam trace — `read-status.ts:79` reads `clock.now` **inside** the lease query, and it is that query's only clock read — which makes it an implement story whose ship diagram would need `health.call`, a token a live diagram may not hold. EPIC 050.5 owns the projection with the table and the `health.call` cause with it.
- **No plan-store change.** `leaseHeld`, `ContainmentFacts.lease` and the `lease` member of `executionBlockers` survive unread. EPIC 050.3 already gave the plan write its run guard, so no plan command is in scope, and EPIC 050.5 deletes the producer.
- **No checkpoint, no workspace, no grant.** EPIC 051 and EPIC 055 own those.
- **No `git_operation.lease_fence` change.** The column is the external-drive precondition mode of `src/domain/external-transition.ts`, not a `Lease` service row. EPIC 050 already dropped `run.lease_fence`.

## Decisions

- **The node lease has no repository half to preserve, so the removal is total where it reaches.** `grep -rn 'lease\.\(acquire\|renew\|release\|read\|assertHeld\)' src/` returns call sites in `claim-node.ts`, `heartbeat-node.ts`, `release-node.ts`, `report-outcome.ts` and `report-objective.ts`, and every one passes `subjectKind: "node"`. One further call is outside that pattern: `lease.expireLeasesOfOwner` at `revoke-actor.ts:100`, which passes **no** `subjectKind` — its SQL filters on `owner` alone — so it is node-scoped only by what the table happens to hold, and EPIC 050.5 owns it. `lease.acquire` is called from exactly one place, `src/commands/node/claim-node.ts:426`, and the only `INSERT INTO lease` in production is inside that service. `src/commands/repository/**` never touches the `Lease` service: the five files under `src/commands/` that hold `subjectKind: "repository"` — `assert-no-outside-writer.ts`, `register-repository.ts`, `reap-orphans.ts`, `sweep-remnants.ts` and `reconcile-journal.ts`, two of them more than once — carry it **only** as an `events.append` subject kind. The draft that preceded this epic reserved a repository half; the source holds none.

- **`lease-held` is retired outright, not scoped.** `grep -rn '"lease-held"' src/http/contract/` binds it to `node.claim`, `node.heartbeat`, `node.release` and `node.report` alone. No repository operation declares it. When the four commands stop raising it, its last producer is gone, so the code leaves `src/http/contract/errors.ts:16`, `src/cli/exit-code.ts:25` and every operation's `errors` record, and `leaseHeldDetails` at `src/http/contract/error-details.ts:120-135` is deleted rather than orphaned. Deleting it takes the `leaseRelations` import at `:6` with it, which is what lets EPIC 050.5 delete `src/domain/lease-hierarchy.ts` whole.

- **This epic is not wire-invisible, and it takes a major version.** EPIC 050.2 Story 3 states it: _"The shipped `fence` field is the node lease fence and it stays … The two mechanisms run side by side inside one transaction until EPIC 050.4."_ The deferred removal is a **response field removal** on `node.claim` and `node.renew` and a **required request field removal** on `node.renew`, `node.release` and `node.report`. Both are outside the closed list of `docs/proposal/api/README.md:100-106`. The amendment EPIC 050.2 Story 8 landed makes that legal only when a human records the ruling and the covering capability is retired and replaced. The ruling is recorded here, `worker-model` is retired, `worker-run` is declared over the same four operations, `KANTHORD_VERSION` moves to `29.0.0` and the compatibility record gains one row. A client reading `system.health.capabilities` sees `worker-model` gone and cannot call the old shape unknowingly.

- **`nodeClaimResponse.objectiveRunId` goes with them, and this epic takes it.** The field at `src/http/contract/execution.ts:45` is required, and EPIC 050.1's `claim-success-task` opens one run where the baseline opened two, so the claim can no longer populate it. EPIC 050.1 Story 1 lists what the response keeps, gains and loses without naming it. Leaving a required field with no producer for a later epic to discover is not a plan, so Story 1 removes it and the compatibility row names it. If EPIC 050.1 is amended to remove it first, Story 1's item is a no-op.

- **The repairs the wire change forces land in the story that forces them.** `src/http/server/` and
  `src/cli/` are typed against `http/contract/`, so removing a request or response field breaks a
  handler and a commander program in the same commit. `.agents/plan/authoring.md` states the rule — _"a
  required field and every site that constructs the type are one epic"_ — and it outranks the story
  count. Those repairs add no story: each belongs inside the story that already owns its schema edit.
  `field-decisions.fixture.ts` is derived from the registry and pinned by `coverage.test.ts`, so it is
  regenerated in each of those stories too, never once at the end.

- **The contract splits per operation, and the residue lands last.** Each operation's request fields, response fields and `errors` entry die in the story that changes that operation's command; Story 8 holds only `errorStatuses`, `exitCodes`, `leaseHeldDetails`, the capability swap, the version and the compatibility record. A single contract story landing first would remove a required request field before its handler stopped reading it, leaving `pnpm run verify` red for the length of the epic. Every story in this tree that touches a schema promises `pnpm run verify` exits 0, and that promise is only keepable if a schema and its reader move together. The one interval this epic admits is the version pair below, which touches no schema.

- **`package.json` is the one locked path, and Story 0 holds it.** `scripts/lane-check.sh` denies `package.json` to both TDD engineers and allows it to `groundwork-engineer`, and it is the only path this epic edits that does. `.agents/plan/authoring.md` collects every such path into one `story-foundation`, so `00-groundwork.md` is first in dispatch order and declares `Executor: groundwork-engineer` and `Paths: package.json`. It counts against the ten-story cap, and this epic is at ten.

- **The version pair is not atomic, and the interval it opens is accepted.** `src/domain/version.test.ts:13` — `assert.equal` asserts `KANTHORD_VERSION` equals the `version` field of `package.json`. `src/domain/version.ts` is the software-engineer lane and `package.json` is the groundwork lane, so no turn writes both: Story 0 moves the field before the loop opens and Story 8 moves the constant. Between them that one assertion is red, and it is red for no case that runs in the interval — `src/domain/version.test.ts` appears in Story 8's `node --test` list alone, and `/work` runs the `Gates:` command once, as a precondition of `IMPLEMENTATION_READY_FOR_REVIEW`. Assertion 8 of the gate stays with Story 8, which lands the half that closes it.

- **The report collapses its two attempt reads, because the grammar forces it.** `report-outcome.ts` calls `execution.attemptsOfRun` twice, at `:213` and `:240`. No two steps of one live diagram may carry one token, and the seam call this epic deletes — `lease.release` at `:282` — sits after both. A diagram whose prefix reaches `:282` therefore cannot be drawn until the two reads collapse into one. EPIC 050.2 Story 5 made the identical collapse in `release-node.ts` for the identical reason, and `release-node.ts:113-122` is the shipped pattern: read once, and project the closing outcome onto the open attempt for the accounting.

- **The objective attestation loses its lease guard and gains no replacement.** `report-objective.ts:80-111` proves the caller by the node lease. It is reached only from `report-outcome.ts:125`, inside that command's transaction, and EPIC 050.2 Story 6 asserts the authority prelude runs for **all six** members of the report union including the objective ones. A second coverage check there would refuse the run that is reporting. `aggregate-initiative.ts` and `close-objective.ts` import no lease and read none, so neither is in scope; the draft that preceded this epic named all three.

- **The objective lease renewal dies with the hazard that justified it.** EPIC 050.2 Story 3 kept `lease.read:O` and `lease.renew:O` in the renew, reasoning that _"a run on `runTtlMs` that outlived an objective lease on `leaseTtlMs` would free a node that another claim then takes."_ With no lease of any subject, nothing frees a node on `leaseTtlMs`, and `subtreeExclusion` of EPIC 050 is what keeps a second claim off the objective. The three calls go, and `leaseTtlMs` loses its last reader in a run command.

- **A claim of a task stops touching the objective row.** EPIC 050.1 already replaced the objective run with the subtree rule: `claim-success-task` opens one run, not two. `lease.acquire:O` at `src/commands/node/claim-node.ts:218` is the last write a task claim makes to its objective, and the subtree exclusion is what refuses a competing claim on `O`. The cascade state writes on `O` and `I` are unchanged.

## Sequence

This epic draws no diagram. A path is drawn by the story that changes it, under
`.agents/plan/authoring.md`. Six of the seven paths were drawn by EPIC 050.1 or EPIC 050.2, so those
six carry no `baseline-` diagram: their prior set is the live diagram this epic supersedes. One path
— the objective attestation — nobody drew, and it carries a baseline with a citation per step.

## Stories

Each entry is a name and the output it contributes. The story file holds the change, the tasks and
the diagrams, and it declares its kind. A `story-foundation` draws nothing; a `story-implement` draws
one pair. `.agents/plan/authoring.md` is the standard.

0. **groundwork.** `package.json`'s `version` moves to `29.0.0`. The one path this epic edits that `scripts/lane-check.sh` denies to both engineers. `story-foundation`, `Executor: groundwork-engineer`, `Paths: package.json`, and it runs before the loop.

1. **The claim of a task drops the lease.** Supersedes `claim-success-task`. Carries `node.claim`'s response fields, including `objectiveRunId`, and its `errors` entry. One pair.

2. **The claim of an initiative drops the lease.** Supersedes `claim-success-initiative`. One pair.

3. **The objective-busy refusal drops the lease.** Supersedes `claim-refusal-objective-busy`. One pair.

4. **The renew drops the lease.** Supersedes `renew-success`, and with it the objective lease renewal EPIC 050.2 kept. Carries `nodeRenewRequest.fence`, `nodeRenewResponse`'s two fields and the `claimedLease` schema. One pair.

5. **The release drops the lease.** Supersedes `release-success`, and deletes the descendant lease loop of `releaseObjective`. Carries `nodeReleaseRequest.fence`. One pair.

6. **The report drops the lease.** Supersedes `report-authority-prelude`, collapses the two attempt reads and draws the whole task path. Carries `fence` on five members of `nodeReportRequest`. One pair.

7. **The objective attestation drops the lease.** `report-objective.ts` loses its lease proof and its release. One pair, with a baseline.

8. **`lease-held` is retired and the capability is swapped.** `errorStatuses`, `exitCodes`, `leaseHeldDetails`; `worker-model` retired and `worker-run` declared; `KANTHORD_VERSION` to `29.0.0`; one compatibility-record row. `story-foundation`, and it lands last of the contract work.

9. **The proposal records one authority.** Four documents, plus the two tree assertions. `story-foundation`.
