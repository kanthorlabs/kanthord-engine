# Plan 00: Index

## Scope

ERD 2 ("Execution") covers the `worker_instance`, `scheduler_execution`, `mission_attempt`,
`mission_evidence`, `mission_evidence_asset`, `mission_assessment` and `mission_outcome`
tables (`docs/reference/erd/02-execution.md`), together with the operations, collaborations,
CLI commands, configuration fields and the two applications that make them usable end-to-end:
the work pull and the claim; the release with the release admission; the loss settlement; the
human controls; the evidence, assessment and request operations, including `mission.node.check`;
the credential handover and the execution credential store; the action performer; the native
agent runtime on pi-coding-agent 0.86.0 with the prompt composer, the tool table, the
verification runner, the workspace and the budget; the `worker` application lifecycle; the CLI
groups and the OpenAPI of all of these.

Consumed seams of a later ERD, declared inline as dependency types and injected by the
composition root under decision D6:

- ERD 3: `intake.storage.put`, `intake.storage.get`, `intake.storage.check`,
  `intake.storage.delete`, `intake.execution.storage.get`, `intake.action.perform`,
  `intake.action.read`, and the Intake check of a request (`intake.action.check`). Production throws internal `system.composition.unwired` before work; the Gateway answers HTTP 500 `gateway.invocation.unknown` under `architecture.impl.md` "Unwired collaborations";
  `gatewayFixture` injects a fake.

- The MCP server: `worker.mcp.message`, `worker.mcp.listen`, `worker.mcp.close`,
  `mcp_session_<ulid>` and the MCP tool source of the tool table (ruling R1, decision D5).
- The external harness extension of Claude Code and opencode and its `/work` skill
  (`worker-service.impl.md:146–149`). The external-harness E2E journey uses a scripted CLI client.

  the page as written and states the gap in one line (decision D1).

- The stored telemetry of ERD 4 and the working tracer (`tracking-service.impl.md:18–19`).
- The `server` placement pool and the in-process execution view of custody (decision D8).
- The workers `claude@1` and `opencode@1` beyond their catalog declaration
  (`worker-service.impl.md:14`); the multi-agent worker `tdd@1` (`worker-service.impl.md:16`).

**Rationale for order.**
Mission attempts and controls (01) create the five Mission tables and the `MissionTransitions`
seam before the claim of plan 03 opens an attempt, and they need only the ERD 1 tables plus a
stand-in of the Scheduler revocation.
Worker registration (02) creates `worker_instance` and the `workerBindingOf` Project seam before
the claim reads a live registration and the instance count.
Scheduler execution (03) creates `scheduler_execution`, the claim, the release, the loss sweep
and the execution proof before any execution operation exists.
Mission execution operations (04) need the proof of plan 03 for every `client` write.
Custody handover (05) needs the pin seams of plan 03 and the proof of plan 03.
The action performer (06) needs the evidence request of plan 04 and the live-claim reads of 03.
The native runtime (07) needs the credential store builder of 05; the methods (08) need 04, 06
and 07; the `worker` application (09) hosts 08; plan 10 assembles what crosses services.

**Collaboration-type contract rule.**
A service declares the types its collaborations need inline in its own `contract.ts`; it does
not import types from a peer's `contract.ts` for its `Dependencies` interface. The composition
root (`src/apps/server/index.ts:62–191`) is the only file that imports and wires cross-service
types. Source: `engine/src/project/service.ts:16`; `architecture.impl.md:587–604`.
