# Plan 00: Index

## Scope

ERD 1 ("Environment and planning") covers the `credential`, `project_project`,
`project_binding`, `agent_enablement`, `mission_mission`, `mission_node`,
`mission_node_revision`, `mission_dependency` and `scheduler_job` tables, together with
the operations, collaborations, CLI commands and configuration fields that make them
usable end-to-end in the running server.

ERD 2 and later are out of scope. The out-of-scope boundary is:

- Execution, claims, leases, renewals and releases (`scheduler_execution`,
  `scheduler_request`, `scheduler_renewal`).
- Mission attempts, outcomes, evidence, assessments, observations, unblocks and
  external objects.
- Worker registrations (`worker_registration` table, `worker.register` beyond the
  existing in-memory stub). Heartbeat and work pull are registration lifecycle (ERD 2).
- Intake subscriptions, deliveries and admission obligations.
- Stored Tracking telemetry (`tracking.db`); the no-op Tracking interface is in scope
  (Plan 07 wires it).
- Human controls (pause, resume, block, unblock, ready, override, discard): they
  write attempt or outcome rows (ERD 2).
- The acquisition grant and the verification secret (Intake redesign is open in
  HANDOFF).
- The `scheduler_request` durable-request table (ERD 2, used by `work.pull`).
- `pinCredential` and `liveExecutionsPinning` Scheduler collaborations (ERD 2:
  `scheduler_execution.credentials`).

The decisions D1 to D16 that the plans cite are in [decisions.md](decisions.md).

**Rationale for order.**
Custody (01) is the foundation: the `credential` table has no ERD 1 peer dependency.
Scheduler job (02) exposes the `WorkQueue` seam before Mission can insert jobs.
Worker (03) declares `validateEntry` and `agentProvidersDependentOn` before Project and
Custody consume them.
Repository (04) declares the `git ls-remote` connector before Project's binding write
calls it.
Project (05) declares `entriesOfAgent`, `bindingsNaming` and `resolveBinding` before
Worker, Custody and Mission consume them (wired in Plan 07).
Mission (06) declares `createMission` and `liveNodesPinning` before Plan 07 wires them
into Project.
Plans 07–09 assemble the application layers in dependency order.

**Collaboration-type contract rule.**
A service declares the types its collaborations need inline in its own `contract.ts`; it
does not import types from a peer's `contract.ts` for its `Dependencies` interface.
The composition root (Plan 07) is the only file that imports and wires cross-service
types.
Source: `engine/src/project/service.ts:16` (`ProjectBindings` declared in own
`contract.ts`); `engine/src/apps/server/index.ts:43–82`.
