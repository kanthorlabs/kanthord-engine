## 2026-08-07 — Story 8 (010.6): env-integer parsing without a convict `coerce` hook

- Convict's per-format `coerce(k, v, ...)` fires on any string value regardless of source (file or
  env) — it cannot be used to accept an env-sourced numeric string while still refusing the same
  string when it comes from the JSON file. Registering `coerce` on `positiveInteger`/
  `nonNegativeInteger` (previous attempt) violated Story 8's `## Constraints` line and broke the
  `ttl: "300"` file-string refusal.
- Fix: revert `convict.d.ts`'s `addFormats` type back to `{ validate }` only; parse the four
  `KANTHORD_HTTP_IDEMPOTENCY_*` env vars manually with a strict integer regex, then `config.set(...)`
  the parsed number after `config.load(parsed)` and before `config.validate()`. File-sourced strings
  never pass through this path, so the refusal and the env-override behavior both hold.
- General lesson: when a vendor coercion hook can't distinguish two input sources the spec wants
  treated differently, do the source-specific parsing in the calling code, not inside the vendor
  hook.
