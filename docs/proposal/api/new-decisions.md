# New decisions

Reviewer: everyone. Read this before the domain files.

The proposal decided the transport policy and it named most public operations. It did not decide a method, a path, a status code, a version prefix or a paging rule. Everything in this list is therefore new. It is separated from the domain files so that a reviewer argues with the decision rather than discovers it inside a route table.

## Decided here

- **A `/v1` prefix.** The CLI runs on a second machine and can be older than the daemon. The daemon serves one version at a time.
- **Every resource segment is singular, and a path is a typed segment tuple rather than a string.** `GET /v1/repository` lists repositories. A path noun is public contract language and is tied to neither a table name nor an id prefix — `repo_01J…` at `/v1/repository/:id` in table `repository` already disproves that identity. The registry declares resource, subresource, action, system and parameter segments from closed sets, and one renderer builds the path, so a plural cannot enter through a route edit. A flat spelling vocabulary was rejected: it would accept `/v1/project/:id/project`. See [README.md](README.md).
- **`openapi.yaml` is generated, self-contained and not committed.** External `$ref` files are refused for generator, viewer and publish portability. The document is not committed because the zod module and the table in this directory are the reviewable change, and a generated schema diff hides it. `npm run verify` generates it into a temporary directory, validates it, asserts parity, and deletes it. A release publishes it as an artifact, and `npm run contract:publish` refuses a dirty tree and an untagged commit; `manifest.json` names the tag, and `--unreleased` writes `tag: null` for an artifact a client must not pin. See [README.md](README.md).
- **Resource plus explicit action.** A command that acts on a resource is `POST /<collection>/:id/<action>`. `unblock`, `waive`, `abandon`, `discard`, `approve`, `publish`, `reconcile` and `rename` are actions. None is a field a client writes.
- **`409` for a precondition.** A stale revision, an illegal transition, a binding in use, a live lease, a divergence and a missing acknowledgement are all `409`, each with its own code, and each returns the current value.
- **`501` for a later phase, `404` for post-MVP.** A route the daemon will implement answers `501 not-implemented` and writes no state. A path that is post-MVP does not exist and answers `404`.
- **One error shape, and the CLI routes on the code.** Block reasons and publish rejection classes are codes.
- **Cursor paging on events.** An offset cannot page an append-only log.
- **`repository.inspect` is a separate route.** Default branch detection writes nothing, and the human confirms in the client. The daemon holds no partial registration.
- **`node.abandon` is one route for a task and an objective.** The node kind decides the behaviour.
- **`plan.validate` exists, and it is also the suggestion route.** It runs the import validation, computes the per-node choice suggestions of `../phase-1/plan-format.md`, and writes nothing. A human edits a plan by hand and wants the finding list and the conflict set before a revision moves.
- **The plan document shape in the import body is a path-and-content pair per file.** An archive is worse to read in a review and worse to diff. A submitted path is a relative POSIX path under `plan/`, ending in `.md`, with no empty, `.` or `..` segment. Array order carries no meaning, and a duplicate path is `422 plan-invalid`.
- **A re-import carries a choice per node, and the choice is binary.** `submitted` or `database`, over the whole node. A field-level three-way merge is not built. Today a single illegal edit rejects a whole document, and a human who edited twenty nodes loses all twenty; the per-node choice is what removes that. Every node of the union carries a choice, with no implicit default. See `../phase-1/plan-format.md`.
- **A choice set is validated as a whole graph.** Two individually legal choices can build a cycle that neither side authored. The daemon builds the candidate graph, re-runs the full validation, and applies nothing unless the whole candidate is valid. `422 choices-invalid`. It never repairs a choice by itself, and a suggestion set is held to the same standard.
- **`plan.export` writes no status.** State moves without a new revision, so a status field would change the bytes of a revision that did not move. One plan revision has one byte representation. A human reads state through `system.status`, `node.list` and `node.show`. This reverses `../phase-1/plan-format.md`, and that file now carries the reversal.
- **`project.nodes` and `project.graph` are two reads of one project.** `project.nodes` at `GET /v1/project/:id/node` returns the node list of one project in the `node.list` body shape, and `project.graph` at `GET /v1/project/:id/graph` returns one atomic snapshot of that topology — every node, every edge, and the topology revision — read in one transaction. The two node routes serve two different reads: `node.list` is the cross-project overview and filters an unindexed full read, while `project.nodes` is the per-project read that filters an indexed project range. The atomicity of `project.graph` is the capability a client cannot rebuild: `project.nodes` followed by `edge.list` is two transactions, and a node write between them returns a node set and an edge set that describe two different topologies. `project.graph` reads the nodes, the edges, and the revision in one read transaction.
- **The wire shape `{ attributes, options, nodes, edges }` is kanthord's, and it coincides with the graphology serialized format.** The contract owns this shape by declaring it in zod and in `graph.md`. The daemon builds the value through `graphology` because that validates the document by construction — a document graphology built is a document `graphology.import` accepts — and then rebuilds it in an order and a key set the contract fixes. A graphology major version that changed its export shape would be a build failure in one file, never a silent `/v1` change.
- **The byte-identity baseline is the accepted document, not the authored one.** An authored document may lack identities, reference by path, and use noncanonical YAML, so no renderer can reproduce it. `plan.export` at a revision equals the accepted documents of that revision.
- **`provider.register`, `provider.list` and `provider.show` ship in phase 1.** `repository.register` carries a mandatory `credentialId`, and the phase-1 exit criterion registers a real remote, so a phase in which every provider route answers `501` cannot complete its own journey. See [credential.md](credential.md).
- **`repository.register` takes `--upstream <branch>` in the CLI.** The human confirmation of the detected default branch is a product rule, and an automated run needs a non-interactive way to give it. The CLI refuses to register when neither a prompt nor the flag answered.
- **`worker.list` and `agent.list` are queries.** A client tells a valid `worker` frontmatter value from a rejected one before it imports a plan.
- **`db migrate` does not call HTTP.** It is the one exception to the parity rule of `../phase-1/transport.md`. The daemon applies every pending migration at startup, so the route would serve only a home whose daemon does not run, where it is unreachable. See [system.md](system.md).
- **A blob hash carries its algorithm prefix.** `sha256:<lowercase hex>`, in the column, in every `_blob` field of a response, and in the `blob.show` path. Seven characters buy the visibility the id prefixes buy elsewhere, and a second algorithm becomes a new value rather than a migration of every citing row. See `../database/blob.md`.
- **`blob.show` exists, and large payloads travel as hashes.** Every route returns its small fields inline and a content hash for a prompt, a trace, a diff, a check log, an evidence document or a plan document. One attempt record would otherwise run to megabytes, and a client that wants a verdict would pay for all of it. The route declares its content type, its caching, its `Range` behaviour and its authentication in [system.md](system.md), because a bare "serve the bytes" contract leaves all four undefined.
- **The actor comes from configuration.** `event.actor_id` and `candidate.approved_actor` are stamped from a configured name. No request carries an actor. One token serves one human, so a request-supplied name would be a claim rather than a fact.
- **`node.attempts` scopes to the active run.** `?run=` selects an earlier one. A node holds several task runs after an abandon, and an unscoped route would make P2-E2's "exactly three attempts" untrue the first time a human reran a task.
- **`plan.import` is idempotent by `importId`, and a reuse with a different document is an error.** `409 idempotency-mismatch`. Returning the first result silently would hide a client defect.
- **`system.health` reports dependency status, and it carries the token.** It asks each dependency to report `ok`, `failed` or `not-implemented`, rolls the answers up to `ok` or `degraded`, and answers `200` either way. `not-implemented` never degrades the daemon. The bearer scheme has **no exception**, so the daemon keeps no anonymous surface: an unauthenticated request answers `401` whatever it asks for, and cannot tell a registered path from an unregistered one. The earlier decision — a public constant `{ "status": "ok" }` — was reversed because a route that reads state cannot be anonymous, and a probe that names the broken subsystem is worth more than one that only proves a process answers. The `Origin` rejection and the `Host` allow list are a separate control and apply everywhere. The daemon version and the bind address are on `system.status`.
- **The integration journal is readable.** P3-E1 asserts no incomplete row survives a restart, and the client host cannot open SQLite. The route is read-only.

## Rejected here

- **A precondition token on every mutating route.** A registration has no prior revision. Preconditions are per operation, and the three that carry one are listed in [README.md](README.md).
- **`ETag` and `If-Match` instead of body fields.** The proposal already spells preconditions as body fields, `landingOid` and `expectedRemoteOid`. A CLI reads a body field more easily than a header, and one mechanism beats two.
- **A route for the merge compare-and-swap.** Approval triggers integration. An internal step that uses a compare-and-swap is not a public operation, and a client that could drive it could land a tree no check covered.
- **A lease collection.** A lease is a field of a node and a run. Nothing asks a human to read one directly.
- **A credential route.** The secret is a write-only field of a provider registration. A route that returns it exists only to leak it.
- **A scheduler administration surface.** `run.start` and `run.cancel` are the whole control surface. The daemon runs one worker loop.
- **An invocations subresource.** `agent_invocation` is a table, and invocations nest inside the attempt representation. A normalized schema does not require a normalized route, and a subresource would be a round trip for two rows of hashes.
- **A generic project update, and a generic `bindings/:kind` route.** `project.worker` is a column, and a binding operation may persist to one. One `PATCH /v1/project/:id` would mix a phase-1 field, a phase-2 field and a post-MVP field under one lifecycle tag, and `bindings/:kind` would leak the storage dispatch key while hiding that a repository set is replaceable and a provider chain is ordered.
- **A `parentRevision` rename.** `plan_revision.parent_id` is a column name. The request field stays `fromRevision`, and only its value type changed.
- **A `candidate-invalidated` code.** It collapses into `stale-revision` with `candidateState` and `invalidatedReason` in `details`. A revision mismatch and an invalidated freeze mean one thing to the human, and two codes would force a client to handle them identically.
- **`auth-failed`, `unsupported-transport` and `insecure-transport` as API codes.** A bad url is `400 invalid-request` with the reason in `details`, because it fails validation before any network call. A forge refusing a token is `422 credential-rejected`, not `401`, because `401` on this API means the caller's own bearer token failed. `auth-failed` stays what `../database/git_operation.md` makes it: a journal outcome.

- **A merge-base `fromRevision`.** A stale `fromRevision` stays a hard `409 stale-revision`. With the revision compared for equality, the stored plan data equals the base by construction, so classifying each node across base, submission and database would degenerate to a two-way comparison and buy nothing. Topology drift and state drift stay separate concerns. The merge-base model is in `../after-the-mvp.md`.
- **A field-level choice.** A node that carries a legal prose edit and an illegal structural edit falls to `database` as one node, and the prose edit is lost. `plan.validate` reports the differing field names so the human sees the cost. Splitting the choice per field multiplies the decisions a human makes and the combinations the daemon must validate, for an edit pattern that a re-export repairs.
